# 웹 입력 설계 — 키보드·게임패드·터치·마우스, 게스트 등록(키 입력 등록)

2026-10-08. 상태: **설계 문서(구현 전)**. 원본 입력 판독은 [05_ui_input.md](05_ui_input.md) §6, 인원·컨트롤러 단계는 [../shell/setplayer.md](../shell/setplayer.md) §6.2·§9.4. 여기서는 그 위에 얹을 **웹 쪽 입력원**을 정한다. 표기: [판독] 원본 근거, [설계] 웹 결정, **사용자 확인 필요** = 기본값을 정해 두고 진행할 곳.

## 1. 결론 요약

| 항목 | 정한 것 |
|---|---|
| 원칙 | 모든 입력원은 **원본 패드 값(PadInput: Npad 버튼 비트·스틱·가속도)** 하나로 바꿔 넣는다. 화면·게임 로직은 지금처럼 원본 비트만 읽고, 입력원이 늘어도 로직은 그대로다 |
| PC 키보드 | 글자 키(J·K 등) 대신 **Space·Enter·Esc·Shift·Ctrl·방향키** 중심 기본 배치(§3). 키 배치는 코드가 아니라 **표(프로필)**로 두고 바꿀 수 있게 |
| PC 마우스 | **메뉴(2D 화면)만** 클릭 지원: 올리면 커서 이동, 누르면 A. 게임 플레이는 키보드·패드(§6) |
| 게임패드 | Gamepad API 표준 배치를 자동으로 읽고, 아무 버튼이나 누르면 빈 자리에 참가(§4). Switch 배치(위치 기준) 유지 |
| 모바일 | 화면 **가상 스틱 + A/B/X/Y 마름모 버튼**, 장면이 쓰는 버튼만 표시. 메뉴는 직접 터치(§5). 리듬 게임은 휴대폰 기울이기/흔들기(DeviceMotion) |
| 게스트 추가 | 키보드 게스트는 **"위 키를 누르세요 → 아래 → … → 결정 → 취소" 순서로 키를 눌러 등록**, 빠른 선택용 프리셋도(§7). 게임패드 게스트는 아무 버튼으로 바로 참가 |
| 위치 | 입력 계층은 `script/view/input*.ts`(페이지 쪽). 셸·게임 코드는 수정 없이 `PadSource` 만 받는다(mgm_common.md §9.1 경계 유지) |

| 위치 | 내용 |

| `script/view/input.ts` | `KeyboardPad`(J=A, K=B, U=X, I=Y, Q=L, E=R, Enter=+, Backspace=−, WASD/방향키=왼쪽 스틱), `GamepadPad`(표준 배치, 아래 0=B·오른쪽 1=A — 닌텐도 위치), `MergedPad`(1P = 키보드 + 패드0), `padSourcesFor(isCom, keyboard)` = 사람 순서대로 패드 0,1,… |

| `shell/mgmcommon/input.ts` | 셸 화면이 쓰는 bex 비트 `PAD`(A 0x1, B 0x2, X 0x4, Y 0x8, 십자 0x100~, 스틱 방향 0x10000~) — 페이지가 Npad → bex 로 바꿔 넘김 |
| `setplayer_page.ts` | 시스템 컨트롤러 애플릿 대체 DOM: 컨트롤러 = 키보드 `kb` 1개 + `gpN`. 할당 안 된 컨트롤러가 A → 다음 빈 칸 |
| 터치·마우스 | **없음**. 키 배치 바꾸기 **없음**. 한 키보드를 두 사람이 나눠 쓰기 **없음** |

원본(05 §6.3) 디버그 키보드 배치는 A=J, B=K… 로 지금 웹 배치의 출처지만, **비활성 디버그 기능**이라 지킬 이유가 없다 [판독]. 원본 화면의 버튼 안내 글리프 E000~E003 은 버튼 이름이 아니라 **마름모 안의 위치**를 칠한 그림이다(online.md 4.9) — 이 점이 §4·§5 결정의 근거.

## 3. 키보드 기본 배치 [설계] — 사용자 확인 필요

### 3.1 1인(키보드 혼자)

| 원본 버튼 | 기본 키 | 보조 키 | 이유 |
|---|---|---|---|
| 왼쪽 스틱 | 방향키 | (WASD) | 기본은 방향키만. WASD 를 함께 열면 Ctrl(X)과 겹쳐 Ctrl+W(탭 닫기)가 나므로, WASD 를 쓰는 프로필은 X 를 Ctrl 대신 다른 키로 둔다 → §3.3 |
| A (결정·주 행동) | **Space** | **Enter** | PC 관례: 결정 = Enter, 게임 행동 = Space |
| B (취소·보조 행동) | **Shift** | Backspace | 게임 중 손이 방향키에 있을 때 왼손 Shift 가 편함 |
| X | **Ctrl** | — | (방향키 배치일 때만, §3.3) |
| Y | **Alt** 대신 **Z** 를 권장 | — | Alt 단독은 창 메뉴로 포커스를 뺏긴다(keydown preventDefault 로 대부분 막히나 브라우저마다 다름) |
| L / R | Q / E (또는 PageUp / PageDown) | — | 쓰는 미니게임이 적다(mgInst 조작 표로 장면별 확인) |
| ZL / ZR | 1 / 3 또는 Shift·Ctrl 오른쪽 | — | 거의 안 씀 |
| + (일시정지·메뉴) | **Esc** (게임 플레이 중) | P | §3.2 |
| − (카드 보기·건너뛰기) | **Tab** | — | 광장 −/+ 카드, 기구 건너뛰기 |
| 오른쪽 스틱 | I J K L (또는 숫자패드) | — | 거의 안 씀 |

### 3.2 Esc 의 뜻은 장면에 따라 [설계]

PC 사용자는 Esc 를 "뒤로/일시정지"로 기대한다. 원본은 메뉴의 뒤로 = **B**, 미니게임 중 일시정지 = **+** 이다. 그래서:
- **셸 화면(메뉴·광장)**: Esc = B.
- **미니게임 플레이 중**: Esc = + (일시정지). 이때 B 는 게임 행동이라 Shift 로만.
- 장면이 `escAs: 'B' | 'PLUS'` 하나를 알려 주고 입력 계층이 그에 따라 비트를 넣는다(로직 수정 없음).

### 3.3 브라우저·OS 함정 (막을 수 없는 키) — 배치에 반영

| 함정 | 결과 | 대응 |
|---|---|---|
| Ctrl+W / Ctrl+T / Ctrl+N / Ctrl+Tab | 탭 닫기 등. **preventDefault 로 못 막는다**(전체화면 + Chromium Keyboard Lock API 일 때만 가능) | Ctrl 을 버튼으로 쓰면 이동은 **방향키만**. WASD 프로필에서는 Ctrl 을 쓰지 않는다 |
| Ctrl+S / Ctrl+D / Ctrl+F | 저장·북마크·찾기 창 | 게임 중 keydown 에서 preventDefault(이건 막힘) |
| Esc (전체화면 중) | 첫 Esc 는 브라우저가 전체화면 해제에 쓰고 페이지에 안 올 수 있다 | Esc 를 게임 행동 키로 쓰지 않는다(일시정지·뒤로만). 전체화면이면 Keyboard Lock 시도 |
| Space / 방향키 | 페이지 스크롤 | 이미 preventDefault(현 `KeyboardPad`) |
| Shift 5번 | Windows 고정 키 창 | Shift 를 연타 행동에 배정하지 않는다(리듬 게임 휘두름은 Space) |
| Shift + 방향키(숫자패드 확장키) | Windows 가 가짜 Shift 떼기/누르기를 끼워 넣는다 | ddalkkakrider `createFakeShiftFilter`(4 ms 짝 제거)를 그대로 옮긴다 |
| 한국어 배열에서 오른쪽 Shift·Ctrl·Alt | Chromium 이 `KeyboardEvent.code` 를 빈 문자열로 준다 | ddalkkakrider `normalizeCode`(key + location 으로 복원) 이식 |
| 키보드 고스팅 | 한 키보드에서 3~4키 동시 입력이 일부 조합에서 안 들어감(저가 키보드 2키 롤오버) | 한 키보드 두 사람은 **서로 먼 영역**(방향키+오른쪽 Ctrl/Shift ↔ WASD+Space 계열 금지 조합 피함)을 프리셋으로, 마법사에서 등록 때 "동시 입력 시험" 한 번(§7.3) |
| 창 포커스 잃음 | 눌린 키가 안 떼짐 | 이미 `blur` 에 비움 |
| 키 반복(keydown repeat) | 자동 반복 | `e.repeat` 무시(반복은 원본 RepeatGen 이 만든다) |

### 3.4 화면 안내 글리프 — 사용자 확인 필요

원본 안내는 E000~E003(마름모 위치) 그림이다. 키보드 사용자는 "오른쪽 칸 = A = Space" 를 알 수 없다.
- 안 1 [권장]: 원본 글리프는 **그대로** 두고(원본 에셋 그대로 규칙), 화면 구석에 작은 키 범례(현재 장면이 쓰는 버튼만: "◇오른쪽 Space · ◇아래 Shift")를 DOM 으로 띄운다. 마지막 입력이 키보드일 때만.
- 안 2: 글리프 그리기 훅에서 키캡 그림으로 바꿔치기. 원본과 화면이 달라져 기본값으로 하지 않는다.

## 4. 게임패드 [설계]

| 항목 | 정한 것 |
|---|---|
| 배치 | 표준 배치(`mapping === 'standard'`)는 **위치 기준**(아래=B, 오른쪽=A, 왼쪽=Y, 위=X) — 지금 코드 그대로. 원본 안내 글리프가 위치 그림이라 어떤 패드든 화면 안내와 손가락 위치가 맞는다 |
| Xbox 패드 | 위치 기준이면 Xbox 의 "A"(아래)가 취소가 된다. **사용자 확인 필요**: 기본 = 위치 기준(원본 화면과 일치). 설정에서 "라벨 기준(아래=결정)" 전환 1개 제공 |
| 비표준 배치 | `mapping !== 'standard'`(Firefox 의 Switch Pro, Joy-Con 한 짝, 일부 안드로이드 패드)는 `id` 문자열 표로 버튼 번호 보정. 모르면 "버튼을 눌러 주세요" 등록(§7 마법사 그대로 재사용) |
| Joy-Con 한 짝 가로 | 스틱 축 90° 회전(05 §6.2 축 변환과 같은 방향) |
| 데드존 | 원형 0.2(스틱 반경 기준), 원본 스틱 단위 `STICK_MAX` 로 다시 늘림 |
| 연결 | Gamepad API 는 **버튼을 한 번 눌러야** 페이지에 보인다 → "아무 버튼이나 눌러 참가" 흐름과 그대로 맞물린다(§7.1) |
| 진동 | 지금 `vibrate()`(dual-rumble) 유지 |
| 모션(자이로) | Gamepad API 에는 없다. WebHID Joy-Con 은 05 §6.5 대로 선택 기능(Chrome 계열) |

## 5. 모바일 터치 [설계]

### 5.1 구성

```
┌──────────────────────────────────────────────┐
│ [−]                                     [+]   │  ← 장면이 쓰면만 표시(작게)
│                                               │
│      (게임 화면)                       (X)    │
│                                    (Y)   (A)  │  ← 원본 마름모 위치 그대로
│   ( 스틱 )                             (B)    │
│  왼쪽 아래 아무 곳이나 누르면 그 자리에 생김   │
└──────────────────────────────────────────────┘
```

| 요소 | 동작 |
|---|---|
| 가상 스틱 | 화면 왼쪽 절반 아무 곳이나 누른 자리가 중심(떠 있는 스틱). 반경 = 짧은 변의 12%, 반경 밖은 최대값, 데드존 0.15. 결과 = `lx/ly`(원본 스틱 단위). 메뉴 화면에서는 스틱 대신 직접 터치(§6) |
| A/B/X/Y | 오른쪽 아래 **마름모 위치 그대로**(원본 글리프 위치와 일치 — 글리프를 보면 어느 버튼인지 바로 앎). 버튼 위 표시는 원본 글리프 모양(마름모 한 칸 칠함)으로 그려 원본 화면과 통일 [설계] |
| 장면별 버튼 | 장면이 `uses: ['A','B','L','ZR', ...]` 를 알려 주면 그 버튼만 보인다. 미니게임은 원본 `mgInst.json` 조작 데이터(05 §6.4)로 자동 결정 |
| 멀티터치 | 스틱과 버튼 동시(포인터 id 별 추적). 버튼 위에서 미끄러져 옆 버튼으로 가면 옮겨 누름(격투 게임 패드 방식) |
| 진동 | `navigator.vibrate`(안드로이드만, iOS 없음) |
| 표시 조건 | 마지막 입력이 터치일 때만(`pointerType === 'touch'`), 키보드·패드 입력이 오면 숨김. 처음 값은 `matchMedia('(pointer: coarse)')` |
| 화면 | 가로 강제 안내(세로면 "가로로 돌려 주세요"), 전체화면 버튼, `touch-action: none` 로 확대·스크롤 막음 |

### 5.2 기울이기·흔들기(리듬 쿠킹 10종 등 `Gyro` ≠ −1)

- 05 §6.5 그대로: `DeviceMotion.accelerationIncludingGravity ÷ 9.80665` → `accX/Y/Z`(G). iOS 는 **사용자 터치 안에서** `DeviceMotionEvent.requestPermission()` 필요 → 미니게임 설명 화면의 "시작" 터치에 붙인다.
- 모션을 못 쓰는 기기·거절하면 화면 A 버튼 = 3.0 G 1프레임 주입(이미 설계된 대체).

### 5.3 한 기기 여러 명

- 휴대폰 한 대는 **1인 기본**. 블루투스 게임패드는 모바일 브라우저 Gamepad API 로 그대로 붙으니 로컬 2~4인은 패드로.
- 태블릿 화면 반씩 나눠 두 명 [보류]: 원본에 없는 형태라 기본값으로 하지 않음.

## 6. 마우스·터치로 메뉴 누르기 (PC·모바일 공통) [설계]

### 6.1 방식 — "누름을 원본 입력으로 번역"

메뉴 상태기계(MenuGrid·각 화면 state)는 원본 입력만 받으므로 그대로 둔다. 포인터는 **커서 이동 + A** 로 번역한다:

1. 화면이 "누를 수 있는 칸" 목록을 내놓는다: `{ pane 경로, row, col }` — MenuGrid 의 `MenuItem` 이 이미 칸마다 페인을 안다.
2. 칸의 화면 사각형 = `render2d.nodeMatrix(root, path)` + `rectOf(...)`(이미 있는 함수) → 캔버스 → CSS 좌표.
3. 포인터가 칸 위로 오면(마우스 hover / 터치 down) **그 칸으로 커서를 옮기는 입력**을 넣는다. 그 칸이 현재 커서면 클릭(up) = **A 1프레임**.
4. 빈 곳 오른쪽 클릭 / 화면 구석 "뒤로" 버튼 = **B 1프레임**.
5. 가로 스크롤 목록(mgm01 목록·승패 표)은 휠·스와이프 = 좌우 방향 반복 입력.

커서 이동을 직접 상태에 쓰지 않고 "그 칸까지 방향 입력 n번"으로 보내면 원본 소리·애니(커서 SE·cursor 애니)가 그대로 나온다. 이동 경로가 막힌 칸(disable·잠금)은 원본 규칙대로 건너뛴다. 한 프레임에 한 칸씩이라 먼 칸은 몇 프레임 걸린다 — **사용자 확인 필요**: 즉시 점프(`grid.setCursor`)가 낫다면 MenuGrid 에 공용 함수 하나 추가(소리는 커서 SE 1번).

### 6.2 화면별 대상

| 화면 | 누를 칸 |
|---|---|
| 모드 선택·mgm01 목록·설정·필터 | MenuGrid 칸 |
| 캐릭터 선택 | 얼굴 칸(랜덤·잠금 포함 — 원본 규칙대로) |
| 인원 설정(setplayer) | 인원 버튼·유저 칸 |
| 메시지 창 | 아무 곳 = A(다음), 선택지 = 칸 |
| 대화 상자(예/아니요) | 버튼 칸 |
| 광장 3D | **클릭 이동은 하지 않음**(원본에 없는 조작, 충돌·따라가기와 맞물려 원본 동작과 달라짐). 하단 파티 줄·카드는 2D 칸으로 누름. 모바일은 가상 스틱 |
| 미니게임 플레이 | 포인터 없음(키보드·패드·터치 버튼). 설명·결과 화면은 메뉴와 같게 |

## 7. 게스트 추가 = 조작 키를 눌러 등록 [설계]

### 7.1 흐름 (setplayer 컨트롤러 단계 = 시스템 애플릿 대체 DOM 확장, setplayer.md §9.4)

```
인원 2~4 결정 → 컨트롤러 단계
  칸: [1P 키보드(기본)] [2P 비어 있음] [3P 비어 있음] ...
  ├ 게임패드: 아무 버튼 → 다음 빈 칸에 즉시 참가(표준 배치 자동). 비표준이면 아래 마법사
  ├ 키보드 게스트: 빈 칸에서 "키보드로 참가" 선택 → ① 프리셋 고르기 또는 ② 직접 등록(마법사)
  ├ 터치 기기: 터치 = 1P 만(§5.3)
  └ 모두 차면 1P 가 A → 닫힘. 1P 가 B(빈 칸 있음) → 취소 → 인원 단계로(원본 6.2 결과와 같음)
```

### 7.2 직접 등록(마법사)

| 순서 | 안내 | 필수 |
|---|---|---|
| 1~4 | "**위** 키를 누르세요" → 아래 → 왼쪽 → 오른쪽 | 필수 |
| 5 | "**결정(A)** 키를 누르세요" | 필수 |
| 6 | "**취소(B)** 키를 누르세요" | 필수 |
| 7~ | X·Y·L·R·+·− | 선택(Esc = 건너뛰기, 이번 모드에서 쓰는 버튼만 묻는다) |

규칙:
- 이미 **다른 플레이어가 쓰는 키**면 거절 + 그 플레이어 이름 표시. 같은 사람 안에서 겹쳐도 거절.
- 막을 수 없는 키(§3.3: Ctrl+W 계열 조합, F5·F11·F12, Meta/Windows 키, Tab 은 포커스 이동)는 거절.
- 마지막에 **동시 입력 시험**: "위+오른쪽+결정을 함께 누르세요" — 고스팅이면 다른 키를 권함.
- 각 단계 원본 커서 SE·결정 SE, 화면 안내 문구는 원본 설정 화면 글꼴·창(MgmWindow·MessageWindow)으로 [설계].
- 결과 = 프로필 `{ name, binds: { code → 버튼비트 | 스틱방향 } }`. `localStorage` 에 기기별로 저장(다음에 "지난번 설정으로 참가" 한 번에), 지워지거나 못 읽어도 기본 프리셋으로 동작.

### 7.3 프리셋(빠른 참가)

| 프리셋 | 이동 | A | B | X | Y | + | − |
|---|---|---|---|---|---|---|---|
| P-화살표(1P 기본) | 방향키 | Space/Enter | Shift | Ctrl | Z | Esc | Tab |
| P-WASD (키보드 2인 중 왼쪽) | WASD | **F** | **G** | R | T | 1 | 2 |
| P-방향키 오른쪽 손 (2인 중 오른쪽) | 방향키 | **/** | **.** | **;** | **'** | Enter | Backspace |
| P-숫자패드 | 숫자패드 8456 | 숫자패드 0 | 숫자패드 . | 숫자패드 + | 숫자패드 Enter | 숫자패드 * | 숫자패드 − |

- 2인 프리셋에는 **Ctrl·Alt 를 넣지 않는다**: 한 사람이 Ctrl 을 누른 채 다른 사람이 W 를 누르면 Ctrl+W(탭 닫기)가 되고 막을 수 없다(§3.3).
- 한 키보드 2인일 때는 1P 가 자동으로 **WASD 프리셋으로 옮겨 가고** 2P 가 방향키 오른손 쪽을 받는다(두 사람 손 간섭 최소). Space·Shift 처럼 가운데 키는 2인에서 쓰지 않는다. **사용자 확인 필요**: 1P 를 자동으로 옮기는 것 vs 1P 유지·2P 가 WASD.
- 3·4인 한 키보드는 고스팅 때문에 권하지 않음(숫자패드 프리셋 있으면 3인까지).

### 7.4 원본과의 관계

원본은 컨트롤러 등록이 **시스템 애플릿**(nn::hid::ShowControllerSupport)이라 화면·규칙을 재현할 근거가 없다 [판독: setplayer.md §6.2]. 등록 뒤 게임에 넘어가는 결과(칸별 할당 완료 = `IsMinimalGameControllerAssigned` 참)만 원본과 같으면 되고, 그 뒤 유저 단계·캐릭터 선택은 원본 흐름 그대로다.

## 8. 구조 [설계]

```
입력원(페이지 쪽 script/view/)
  KeyboardSource(프로필 표)  GamepadSource(자동 배치)  TouchSource(가상 스틱·버튼)  MotionSource(DeviceMotion)
        │                          │                           │                          │
        └──────── 플레이어 칸별 묶음(PadSource = MergedPad) ────┴──────────────────────────┘
                                   │  PadInput(Npad 비트·스틱·가속도)   ← 지금과 같은 계약
                       ┌───────────┴────────────┐
             셸 화면(Npad→bex PAD)        미니게임 로직(원본 그대로)
  PointerUi(메뉴 칸 누르기) ──→ 화면이 내놓은 칸 목록 → "커서 이동 + A" 입력 주입(같은 PadSource 에 1프레임 비트)
  SceneInputInfo{ uses[], escAs, pointerItems() } ← 장면이 알려 줌(로직 수정 없이 페이지/뷰에서)
```

| 파일(예정) | 내용 |
|---|---|
| `script/view/input.ts` | 지금 파일 유지 + `KeyboardPad` 가 프로필 표를 받게(기본 = P-화살표) |
| `script/view/inputProfiles.ts` | 프리셋·저장·충돌 검사·막힌 키 목록·`normalizeCode`·가짜 Shift 거르기(ddalkkakrider 이식) |
| `script/view/touchPad.ts` | 가상 스틱·버튼 DOM(오버레이 캔버스 하나), `uses` 반영 |
| `script/view/pointerUi.ts` | 칸 사각형 계산(render2d `nodeMatrix`·`rectOf`) → 커서 이동·A 주입 |
| `script/view/motion.ts` | DeviceMotion → accX/Y/Z, iOS 권한 |
| `setplayer_page.ts` | 애플릿 대체 DOM 에 "키보드로 참가"·마법사·프리셋 |
| 셸 모듈 | **수정 없음**이 목표. 포인터용 칸 목록만 각 화면 debug/뷰에서 꺼내는 작은 공용 함수(MenuGrid 에 `items()` 노출 정도) |

경계: 셸(`script/shell/*`)은 지금처럼 `PadSource` 만 받는다(mgm_common.md §9.1). 입력원은 엔진 독립 페이지 쪽이라 다른 플랫폼 포팅 때 입력원만 바꾸면 된다.

## 9. 구현 순서와 규모 (실측 속도 기준: 화면 하나 30~60분)

| 단계 | 내용 | 예상 |
|---|---|---|

| 4 | 모바일 터치 오버레이(스틱·마름모 버튼·장면별 버튼·멀티터치·가로 안내) | 1~1.5 h |
| 5 | 메뉴 포인터(칸 목록·hover/클릭 번역) — 화면 7~8개에 칸 목록 연결 | 1.5~2 h |

| 검증 | 상태 시험(프로필 충돌·번역 결과 비트·마법사 흐름) + 마지막 헤드리스 1회(터치 에뮬레이션 `hasTouch`) | 0.5 h |

## 10. 사용자 확인 필요 (기본값은 이미 정함)

1. 키보드 기본 배치 §3.1(A=Space/Enter, B=Shift, X=Ctrl, Y=Z, +=Esc(게임 중), −=Tab). 특히 **Y 를 Alt 대신 Z** 로 한 것.
2. Esc 장면별 뜻(메뉴 = B, 미니게임 = +) §3.2.
3. 키보드 사용자 안내: 원본 글리프 유지 + 구석 키 범례(안 1) §3.4.
4. 게임패드 기본 = 위치 기준(원본 화면 일치), Xbox 라벨 기준은 설정 전환 §4.
5. 메뉴 클릭 = 한 칸씩 이동 입력(원본 소리 그대로) vs 즉시 점프 §6.1.
6. 광장 클릭 이동 안 함 §6.2.
7. 키보드 2인 때 1P 를 WASD 로 자동 이동 §7.3.
8. 휴대폰 한 대 = 1인, 화면 나누기 보류 §5.3.
