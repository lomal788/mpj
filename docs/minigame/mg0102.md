## 1. 기능 개요와 사용자에게 보이는 동작

4인 개인전(VS4). 구체 표면을 달려 깃발을 터치하면 1점을 얻고, **60개가 모두 획득되면 종료**한다. 가장 많이 얻은 사람이 승리하며 같은 최고점이면 공동 승리한다. 이동만 조작하고 점프·공격·탈락 규칙은 없다 [판독·데이터].

- 화면은 2×2 분할, 각 플레이어의 구면 좌표계에 붙은 카메라를 쓴다. 45초부터 남은 깃발 방향 화살표가 나타난다 [판독].

## 3. 진입점과 전체 호출 흐름

### 3.1 구성·준비 [판독]

`Scene : bq::MinigameScene`(`Scene::Scene @0x710003cb18`)이 `GameMgr`를 소유(`Scene+0x358`), 훅을 `_Mgr` 함수로 전달한다. `GameMgr`는 우선순위 0인 `bex::Fiber`이며 `CameraMgr(+0x60)`·`Players(+0x68)`·깃발/받침 엔티티 배열·UI·결과 정보를 보관한다.

- `SetupGame_Mgr @0x7100014d9c`에서 준비, `SyncedSetupGame_Mgr @0x7100014dd0`에서 CSV 값을 double로 읽어 f32에 저장하고 플레이어·깃발·카메라를 초기화한다. 점수 0, 순위 3, 깃발 소유자 −1, 남은 개수 60, 본편 시간 0이다.
- `Players::InitSub @0x7100033c30`는 `PlayerWork`/`ComMatter`와 표시 모션·Heading을 만들고 CPU 레벨별 값을 읽는다. `InitParam @0x7100035390`에서 구면 행렬과 초기 배치를 정한다.
- `GameMgr::Update @0x7100014650`는 `UpdateHorogramRotate`·준비 모션 완료 검사를 하고 `Fiber::Wait()`한다. `GameMgr::TickUpdate_Mgr @0x7100014644`, `Scene::TickUpdate @0x710003cc3c`는 빈 함수다. 고유 이동·득점은 본편 훅에서 갱신한다.

### 3.2 본편 한 프레임 [판독 `OnGameMain_Mgr @0x71000244f8`]

1. `GameMgr+0x610 += GetDeltaTime()`.
2. **p=0,1,2,3 순서**로 `UpdatePlayer(p,false)` → `UpdatePlayerHitCheckHologram(p)` → 행렬 취득·카메라 갱신 → `UpdatePlayerArrow(p)`.
3. 한 번이라도 획득했으면 4명의 순위를 재계산하고 상태 UI 갱신. `UpdateArrowDisp()`에서 화살표 표시·CPU 탐색 범위 전환.
4. 설명 화면이면 남은 개수 <1을 반환. 일반 플레이도 기본은 같은 조건이며, 별도의 디버그 `finishType` 분기는 5절.

CPU가 읽는 가까운 깃발·방향 캐시는 자기 `UpdatePlayerArrow`보다 먼저 소비된다. 모든 플레이어를 먼저 이동한 뒤 일괄 판정하는 구조가 아니므로, 순서·지난 캐시를 바꾸면 같은 프레임 경쟁과 CPU 경로가 달라진다.

**순위·승패** [판독 `CalcPlayerRank @0x71000255a0`, `OnGameEnd_Mgr`, `OnEndingInit_Mgr`]:

- 각 `rank[p] = count(score[q] > score[p])`(0 시작, 최대3). 동점에 슬롯 번호나 획득 시각을 보조 기준으로 넣지 않는다.
- **전원 점수 <1이면 모두 rank3, WinLose2(draw)**. 그렇지 않으면 rank0은 WinLose1(win), 나머지는 WinLose0(lose).
- 양의 점수로 4명 동점이면 4명 공동 승리이며 draw가 아니다. 정상 60개 전부 획득 시에는 점수 합이60이라 전원 0점 경로는 발생하지 않는다.
- `SetResultTelop @0x710002c970`: 승자0명→종류8, 1명→7, 2~4명→5. `mg0102_Result_GetTelopType @0x710002d08c`도 같은 구분(표 `0x7100068694`의 7,5,5). 공동 승자를 한 명으로 축약하지 않는다.

**모드 차이** [판독·데이터]: `flag::Check(0)`은 [공통 장면 §5.3](../shell/minigame_scene.md)의 **설명 화면 안 실행**이다. 같은 이동·깃발 규칙을 쓰지만 오프닝을 스킵하고 `InstLoopTiming:Finish`에 따라 결과 없이 초기화·반복한다. 일반 VS4 외 팀전·엔들리스 고유 분기는 없다. `finishType>0`은 일반 플레이에서 지정 승자 조합으로 점수를 덮어쓰고 즉시 종료하는 개발용 경로이며 설명 화면은 이를 우회한다. 코인 지급·자유 플레이 재시도·보드 보상은 호출한 공통 흐름의 책임이다. 고유 판독 범위에 `MGRecorder` 호출은 없다.

## 6. 핵심 알고리즘·물리·충돌·CPU

### 6.1 입력·구면 이동 [판독]

근거: `UpdatePlayerPad @0x7100036ec0`, `UpdatePlayerMove @0x7100037c50`, `UpdatePlayerTurn @0x71000385f0`, `UpdatePlayerRoll @0x7100035924`.

초기 행렬은 단위 기저와 `p=(0,15,0)`이다. 월드 Z축을 중심으로 4절의 슬롯별 초기 거리만큼 `UpdatePlayerRoll`한다. 매 프레임 스틱을 정규화 범위 `(sx,sy)`로 받아 `m²=sx²+sy²`, 입력 yaw=`atan2(sx,−sy)`, **로컬 회전축 `a=(-sy,0,-sx)`**를 만든다. 회전축과 접선 이동 방향은 서로 다르다.

| 조건 | 이동·표시 |
|---|---|
| `m² ≤ 0.1` | 정지·idle |
| `0.1 < m² < 0.8` | 걷기, 이동 거리 `2dt`, yaw 상한 `6.2831852dt` |
| `m² ≥ 0.8` | 달리기, 이동 거리 `6dt`, yaw 상한 `19.198621dt` |

스틱 길이에 연속 비례하는 속도가 아니다. 월드축 `normalize(B0·ax+B1·ay+B2·az)`와 거리 `s`로 회전각을 `((s·180)/47.12389)·0.017453292`로 만들고, **세 기저와 위치를 모두 같은 axis-angle quaternion으로 회전**한다(수학적 동치 `θ=s/15`).표시 yaw는 차이를 [−π,π)로 감싸 상한만큼 접근하며 이동 방향을 제한하지 않는다. 모델의 회전은 구면 기저에 로컬 yaw를 합성하고 위치는 구면 행렬에서 쓴다. 중력 적분·일반 지상 이동·낙하 판정은 이 고유 이동 경로에 없다.

원본 `GetHold` 방향 비트가 스틱을 덮어쓴다: 우선순위 **bit11(위)→bit8(왼쪽)→bit9(오른쪽)→bit10(아래)**, 기본 축 ±1·대각 축 ±0.7, 이동 강도는1. 이 비트는 **bex 엔진 비트**이고 현행 [core/pad.ts](../../script/core/pad.ts)의 Npad 원시 LEFT/UP/RIGHT/DOWN(12~15)과 다르므로 변환한다. A/B·자이로는 고유 이동에서 읽지 않는다. 단일 Joy-Con 축 회전은 [05_ui_input.md](../engine/05_ui_input.md)의 입력 전처리를 따른다.

### 6.2 플레이어끼리 밀어냄 [판독]

`UpdatePlayer @0x710003683c`의 이동 직후 인라인 판정(`UpdatePlayerHit @0x71000370c0`에도 동일 형태), `UpdatePlayerHitReplace @0x7100037228`, `UpdatePlayerMove2 @0x71000376c0`.

자신의 이동 직후 위치를 한 번 저장하고 다른 슬롯을 번호순으로 검사한다. 유클리드 거리(구면의 **현 길이**) `d < 2·0.5=1`인 **첫 상대만** 처리한다. 보정 거리 `h=(1-d)/2`로 자신을 상대에게서 밀고, 상대도 저장한 자기 위치에서 반대 방향으로 민 뒤 루프를 끝낸다. 상대가 나중에 자기 차례를 처리하면서 같은 쌍을 다시 검사할 수 있다.

`HitReplace`는 상대 위치를 자기 행렬의 로컬 좌표로 변환하고 XZ 접선 성분의 `φ=atan2(localX,localZ)`로 **회전축 `(−cosφ,0,sinφ)`**, 보정 거리h를 `Move2`에 전달한다. 현 길이의 침투량을 곧바로 표면 회전 거리로 사용한다. PhysX 캡슐 반발·속도 충격으로 대체하면 동등하지 않다. 동시에 겹친 모든 쌍을 대칭적으로 푸는 규칙도 아니다. d=1은 보정하지 않으며, 완전 동위치의 접선각은 수학 라이브러리의 atan2(0,0) 경로에 의존한다.

### 6.3 깃발 배치·난수 [판독]

`InitHologramTransform @0x710001c7f0`, `InitHologramTransformSub @0x710002b2f0`.각 후보에는 기본 행렬0과 근접 대체 행렬1~3, 대응 표시 행렬이 있다. 기본 판정 구면은 반지름15, 대응 표시 위치 계산에는15.3도 사용한다.

- 띠 번호i=0..7(설정9−2), 띠별 후보 수는 **F(i+2)**, F(0)=0,F(1)=1: 1,2,3,5,8,13,21,34. 방위각은 띠마다 π/2씩 진행하며 띠 안에서 `2πj/F(i+2)`를 더한다. 극각 생성식은 `β=(i/7+0.1sinφ)·π/2`이다. 남쪽 계열은 β+π, 북쪽 계열은β를 쓴다.
- 기본 `randInitType=1`: 먼저 **남쪽 i<7** 후보를 순서대로 만들고, 이어 **북쪽 i≥3** 후보를 만든다. 다른 값이면 북쪽·남쪽 생성 순서가 섞인 분기로 가고 후보 ID를 섞는다. 섞기는 각 슬롯마다 `j=SyncRandMod(전체 후보 수)`를 뽑아 교환하며, 범위가 줄어드는 Fisher–Yates가 아니다(`w1` 인자 @0x7100020a28).
- 후보를 순서대로 선택한다. 3개 묶음 사용 수<3, 출력 수<60−3, 기본 후보 y<5이면 대체1·2·3을 출력한다. 그 외는 기본0을 출력하고, 60개가 되면 멈춘다.
- **선택 후보마다 `SyncRandMod(36)·10`을 한 번** 뽑는다(@0x7100020a94~0x7100020aac). 이는 0~350도의 **깃발 로컬 회전각**이며 애니메이션 시작 프레임이 아니다. 같은 3개 묶음은 같은 각을 쓴다. 기본 설정도 이 난수 소비는 생략하지 않는다.
- `InitHologramTransformSub`는 판정 행렬을 `+0x508`에 저장한 뒤 표시 모델을 설정한다. 설명 화면 외에서 판정 y<−12.5면 대응 표시 행렬로 모델을 바꾸는 경로가 있으나 판정 행렬은 바꾸지 않는다. 대체 후보 생성에는 0.017453292·0.030229991 rad 상수가 있다. 대체 행렬의 정확한 축 합성은11절의 잔여 범위다.

### 6.4 획득·힌트 [판독]

`UpdatePlayerHitCheckHologram @0x7100024b90`은 깃발 ID 오름차순으로 `owner<0`만 검사한다. `distance(playerPos,flagMatrix.translation) < 0.5+0.5`이면 첫 깃발의 owner=p, score[p]++, remain-- 후 즉시 반환한다. 따라서 **한 플레이어·한 프레임 최대1개**, 같은 깃발을 동시에 터치하면 본편의 낮은 슬롯이 먼저 얻는다. 거리 동점 공동 획득·깃발 탈취·획득 점수 손실은 없다.

획득 시 상태11→표시 갱신에서14→get 모션 완료 후99(`UpdateHorogramRotate @0x71000146b0`).캐릭터 ID별 `mg0102_hologram_pcNN`, `mg0102_hologram_base_pcNN_emi`, `mg0102_hologram_ray_pcNN`, `mg0102_holo_ray_under_pcNN` 텍스처를 선택하고 보이스·FX_GET·상태 점수·남은 개수 텍스트를 갱신한다. 카메라 가시성 최적화는 모델 visible 또는 Entity Activate/Deactivate를 제어하며 **소유권·거리 판정을 제외하는 조건이 아니다**. `DrawLayoutNum @0x710002c720`은 남은 개수를 1~3자리 문자열로 만든다.

`UpdatePlayerArrow @0x710003b150`는 가장 가까운 다른 플레이어와 **미획득 깃발**을 현 길이로 검색한다. 거리 비교는 `<`여서 같은 거리면 먼저 읽은 ID가 남는다. 목표를 자기 접선 좌표로 투영해 CPU 입력각·화살표각을 구하고 표시각은 호출당10도 이내로 접근한다. 위치는 로컬(0,2.4,0)을 구면 기저에 적용한다. `UpdateArrowDisp @0x710003bbb0`는 본편 경과≥45초이고 종료 전일 때 네 화살표를 표시·모션 재생한다. 가려진 깃발도 검색 대상이며 지형 경로 탐색은 없다. 머리 시선은 이전 캐시의 깃발 거리≤6이면 깃발, 아니면 다른 플레이어 거리≤6이면 상대를 본다.

### 6.5 CPU [판독·데이터]

근거: `InitSub`, `UpdatePlayerCom @0x7100036c20`, `SetPointPos @0x710003c208`, `PlayerComThinkReset @0x71000366a4`, `UpdateArrowDisp`.

| GetComLevel | 0 | 1 | 2 | 3 |
|---|---:|---:|---:|---:|
| 가까운 깃발 탐색 거리 `range` | 2.5 | 4 | 6 | 8.5 |
| 목표 없을 때 방향 변경까지 `turn_sec` | 11 | 10 | 9 | 8 |
| 힌트 이후 추가 대기 `arrow_sec` | 45 | 30 | 15 | 0 |
| 전체 탐색으로 전환되는 본편 초 | **90** | **75** | **60** | **45** |

CPU는 입력 강도1, 로컬 회전축 `(cosα,0,−sinα)`로 항상 달린다. α와 캐릭터 표시 yaw는 별도 값이다.

- 상태0: 캐시된 가까운 깃발 거리≤range이면 입력각을 목표각 쪽으로 호출당10도 돌리고 초 타이머0. 아니면 dt를 누적하여 turn_sec 이상 때 `turnTarget=wrap(α+π/2)`로 정하고 상태10으로 전환한다.
- 상태10: 깃발이 range 안이면 목표각을 따라가고 타이머0·상태0. 아니면 turnTarget에 호출당10도로 접근하고 도달하면 상태0.
- 획득 `SetPointPos`: 획득 깃발 위치·획득 시 접촉 거리를 저장하고 상태1·타이머0. `PlayerComThinkReset`은 **상태가 아니라 타이머만0**으로 한다.
- 상태1: 방향을 유지한다. 최대5초, 또는 획득 위치까지 거리가 저장 기준보다 증가하면 상태0. 감소/동일이면 기준을 새 거리로 갱신한다. "5초 동안 무조건 직진"으로 고정하지 않는다.
- `playTime ≥ 45+arrow_sec[level]`이면 range를9999로 바꾼다. **현재 프레임의 CPU 처리 뒤** 전환되므로 그 효과는 다음 자기 이동에서 소비한다.

CPU/화살표 각 접근은 dt를 곱하지 않는 호출 단위이고 걷기/달리기·캐릭터 yaw·초 타이머는 dt를 쓴다. 난이도 레벨 이름은 데이터에 없으므로0~3으로 표기했다.

## 8. 다른 기능과의 상호작용

## 9. 웹 포팅 구조와 구현 순서

### 9.1 현재 구현 차이

2026-10-08 정적 확인: [games/index.ts](../../script/games/index.ts)의 GAMES는 **mg1801만 등록**.`script/games/mg0102/`, `assets/mg0102/`가 없고 script 내 mg0102 참조도 없다. 따라서 구면 이동·수동 충돌·깃발60개·순위·CPU·4분할 카메라·전용 에셋 연결은 현재 구현되지 않았다. 본 요청에서는 구현/등록/에셋 변환을 하지 않았다.

향후 `GameDef`·`GameLogic`·`GameView` 연결은 [game.ts](../../script/game.ts) 계약에 맞춘다. 로직 state에는 구면 행렬4개, 표시 yaw, 소유자60개·행렬, score/rank, 순차 판정용 캐시, CPU 상태·각·시간, 본편 경과·종료 원인을 둔다. view에는 캐릭터·깃발·화살표 인스턴스, 카메라4개, 남은 수/점수 HUD와 일회성 획득/힌트 이벤트를 둔다. `GameResult.ranks`는 원본의0기준 공동 순위를 그대로 받는다. 자료에 없는 점프·엔들리스·난이도 외 규칙 옵션을 추가하지 않는다.

### 9.2 lib·공유 렌더러 연결의 게임 고유 조건

일반 API·소유권은 [mg0106 §9.2](mg0106.md)·[loader_manager §11](../engine/loader_manager.md) 참조.[Stage3D](../../script/shell/stage3d/stage.ts)는 `scene`·단일 `camera`와 `render()`를 제공하고 [Renderer](../../script/view/renderer.ts)는 `render(scene,camera)`·`setPost()`를 제공한다 [현행 코드 판독].

- GPU는 페이지의 `ctx.renderer.gl`을 주입하고, loader의 owner는 `mg0102`로 둔다. **구면 scene 하나를 네 카메라로** viewport/scissor에 그리는 게임 어댑터가 필요하다. 현행 래퍼에4분할 호출·각 영역 post 합성 기능은 없다. Stage3D 네 벌을 각자 갱신하면 모션·이펙트가 네 번 진행될 수 있으므로 공유 scene의 `update(dt)`는 스텝당 한 번이다.
- 화면 크기를 네 사분면으로 나누고 각 카메라 aspect를 영역에 맞춘다. viewport/scissor·clear와 post 렌더 타깃을4분할에 맞춰 관리한다. 원본의 radial up·플레이어 기저를 사용하는 추적 카메라를 global up=(0,1,0) 자유 카메라로 대신하지 않는다.
- 캐릭터 transform을 로직 행렬＋yaw에서 직접 적용한다. Stage3D의 평면 mesh 이동/접지 처리를 여기에 더하지 않는다. 깃발 표시 위치와 판정 행렬은6.3처럼 별도로 보관한다.
- 깃발60개·받침·4화살표 인스턴스는 모델·텍스처 템플릿을 공유할 수 있지만, 획득 플레이어별 재질 교체·표시 상태는 인스턴스별로 둔다. 공유 원본 재질을 수정하면 모든 깃발 색이 바뀐다. 하나의 카메라에서 가려졌다고 전체 모델을 숨기지 않고 네 영역의 가시성을 고려한다.
- `onStep`에서 획득/힌트 사운드·FX를 한 번 발생시키고, 모션·fmab/fvbb 표시만 view에서 진행한다. 60Hz 고정 로직의 CPU10도/호출과 rAF 표시를 분리한다.
- 종료 시 Stage3D.dispose 및 `manager.release('mg0102')`, 게임 post 제거·viewport/scissor 복구가 필요하다. 페이지 소유 WebGLRenderer를 dispose하지 않는다. 애니 메모리·공유 템플릿 캐시 구분은 기존 lib 분석을 따른다.

### 9.3 구현 우선순위

1. 배치 대체 행렬의 잔여 축 합성을 해결하고 판정/표시 행렬·난수 소비 자료를 만든다.
2. 입력 문턱·구면 회전·순차 밀어냄→깃발 획득→공동 순위·종료를 연결한다.
3. 이전 캐시를 읽는 CPU·45초 힌트·난이도별 전체 탐색 시각을 연결한다.
4. 네 카메라·공유 lib 로더·UI·모션/FX/SE·설명 화면 반복·공통 종료 타이머·결과 무대를 연결한다.
