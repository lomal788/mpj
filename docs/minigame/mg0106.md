## 5. 상태별 입력·종료·결과

`ComPlayer::GameStart @0x710001a270`은 입력을 켜고 위치·방향을 초기화하며 탈락 플래그를 0으로 둔다. 사람은 카메라 기준 스틱, CPU는 overlay 입력을 사용한다. NRO 고유 자이로 처리는 없다 [판독]. 현재 웹 입력은 `script/view/input.ts`의 WASD/방향키·J(A), 게임패드다. [input_web.md](../engine/input_web.md)의 새 키 배치는 **설계**이므로 현재 코드와 구분한다.

### 결과 [판독 `PlayerManager::Update @0x7100018a30`, `GameFinish @0x710001aa40`]

1. Update 시작에서 탈락자 총수 D를 먼저 센다. 새 탈락자 모두에게 **rank = 4−D**를 준다(0이 1위). 같은 갱신에서 탈락한 사람은 공동 순위이며 무작위 섞기를 하지 않는다.
2. 일반 대전 D=3이면 마지막 생존자 rank=0, winLose=1. 전원 새로 탈락한 경우에는 전원 rank=3, winLose=2로 바꾼다. 그 외 탈락자는 winLose=0(단, D=4이면 1을 쓰는 중간 분기가 있으므로 전원 동시 분기와 함께 옮긴다).
3. GameFinish에서 아직 결과가 없는 생존자는 **rank=0, winLose=1**. 시간 종료에 여러 명 살아 있으면 모두 승리한다. 공용 상태 UI/MGMgr로 각 결과를 반영한다.
4. 일반 대전에는 득점 누적이 없다. 엔들리스 `TimeRecord @0x7100019128`은 탈락 순간 또는 생존 종료 시 카운트업 현재값을 `ComUiStatus::SetTime`·`MGRecorder::SetPlayerRecord`로 기록한다. 엔들리스 최종 기록 순위의 공용 정렬은 이 고유 분기와 별개다.

**재구현 계산**(위 rank 식): 첫 1명 탈락 D=1 → rank3(4위), 첫 2명 동시 D=2 → 둘 rank2(3위), 첫 3명 동시 D=3 → 셋 rank1(2위), 생존자 rank0. 이는 실행 결과가 아니라 식의 예시다.

## 6. 핵심 알고리즘·물리·충돌·CPU

### 6.1 회전판 [판독 `UpdateRotate @0x710000f230`, `UpdatePlayer @0x710001c8c0`]

`ω = clamp(ω + dt·accel[phase]·π/180, 0, maxSpeed[phase]·π/180)`, `angle += dt·ω`. angle≥2π이면 **초과분을 버리고 0**, phase는 0→1→2→2다. 속도는 phase 전환 때 리셋하지 않는다.

플레이어 **y≤0**일 때 δ=−ω·dt로 좌표를 `(x cosδ−z sinδ, 0, z cosδ+x sinδ)`에 보정하고 방향도 Y 회전한다. **y>0**이면 이 판 이동을 적용하지 않는다. 점프가 판에 실려가는 시간을 줄이는 이유다. 캐릭터 자체 걷기·가속·A 홀드 점프는 공용 ComActor 책임이며 고유 NRO에 완결된 적분식이 없다.

### 6.3 감전·탈락 [판독 `UpdateAction @0x710001d940`]

입력 활성·생존자에 대해 θ=atan2(player.x, player.z), α=atan2(Bilikyu[0].x,z), β=atan2(Bilikyu[2].x,z)를 읽는다. 안전 조건은 **β < θ < α**다. 경계와 같은 각도도 탈락이며, 점프 높이·NPC와의 구 거리는 이 조건에 없다.

탈락하면 +0xAE=1, 액터 충돌 플래그(+0x28) 해제, `Electric` 액션 호출·입력 끄기·`VB_MG0106_ELEC_WAVE` 중지. `ActionElectric @0x710001c2dc`는 `co_electric00`를 재생한다. 퇴장 기준 벡터는 시작 위치에서 **(약 0,20,0)** 방향이다. 그 벡터 전체를 정규화한 x/z 성분에 **dt·20**을 곱해 수평 변위를 누적하고, **45°**와 기준 벡터 길이·높이로 포물선 y를 보정한다. 따라서 20을 고정 수평 속도로 바꾸지 않는다. 현재 y<0이면 보정을 끝낸다. 감전은 탈락 flag를 세운 시점에 확정되며 애니메이션 완료를 기다리지 않는다.

### 6.4 장애물 애니메이션 [판독 `UpdateAnim @0x710000f4e0`]

- Boo: `pos_objA_teresa00` 소켓의 위치를 갱신하고 `ω+2π/period[phase]`에 dt를 곱해 자체 회전한다. 슬롯0/1 속도는 phase별 1.9/2.2/2.5. 모션 **0~60, 150~210** 구간에 대기 분기가 있으며 **20·150·170·300** 프레임 경계에서 상승/하강 루프 SE를 시작·정지한다. 대기 변수의 정확한 갱신형과 모션 길이는 11절 대상이다.
- 멍멍 상태: **0 초기 ObjEInit→1 각도>−60°에서 대기→2 ObjWanwanStart 완료 대기→3 ObjEIn·ObjWanwanIn 시작 및 Mouth 예약→4 충돌 유효 구간→5 마지막 10프레임부터 루프 SE 정지→6 ObjWanwanEnd 후 −90°<각도<−60°에서 0**. 종료를 임의 시간으로 대신하지 않고 클립 프레임/완료를 사용한다.
- 배치 선택은 난수가 아니라 `GameWork::GetGameStage`: 0→grp05, 1→grp06, 2→grp07, 그 밖→grp05다(`ComMap` 생성자 @0x7100008784, CreateObj @0x7100009020).

### 6.5 CPU [판독·데이터]

| ComLevel 인덱스 | 0 | 1 | 2 | 3 |
|---|---:|---:|---:|---:|
| JumpInterval | 2.0 | 1.4 | 0.8 | 0.2 |
| JumpThreshold | 0.7 | 0.75 | 0.8 | 1.0 |
| JumpLength | 0.1 | 0.2 | 0.4 | 0.5 |
| MoveInterval | 2.0 | 1.4 | 0.6 | 0.2 |
| MoveArea(°) | 30 | 25 | 15 | 10 |

`UpdateParam @0x710001c5a0`은 CPU 최초 한 번만 초기화한다. 난수 호출 순서는 **JumpInterval+U(0,.2), JumpThreshold+U(0,.2), MoveInterval+U(0,.2), 첫 대기 U(0,1), MoveArea+U(0,10)**이고 JumpLength는 그대로다. 모두 SyncRandRangeF. 이름상 JumpThreshold를 성공 확률로 오해하지 않는다. 실제로는 낮은 Boo 접촉 요청의 **높이 비교**에 쓴다.

`UpdateCom @0x710001d100`은 생존·활성 CPU만 처리한다. 매번 Route.GetTargetRouteData로 목표를 얻는다. θ는 플레이어 각도, β는 Bilikyu[2] 각도, area는 보정 MoveArea다.

| CPU 상태 | 동작·전환 |
|---|---|
| 0 대기 | 스틱 0, 대기시간 +=dt. `(첫 이동 전 && time>첫대기) || time>MoveInterval`이며 **θ>β+(area+10)°**일 때 1로 전환 |
| 1 이동 | 목표−현재를 정규화하여 스틱 **(−dir.z, dir.x)**. θ<β+area°이면 0. 그 밖에서 y≤0이고 +0xD8이면 **A trigger=1, hold=0**, 점프 시간=0, 상태2 |
| 2 점프 유지 | θ>β+10°일 때만 목표 방향, 그 밖은 스틱0. 방향 크기는 **JumpLength**로 줄인다. trigger=0, time<JumpInterval이면 **A hold=1**, 만료하면 hold=0·대기시간0·상태0 |

버튼 1·스틱 축 변환·JumpLength 곱은 AArch64 `@0x710001d480~0x710001d5c4`로 확인했다. CPU가 “잘 뛰는 확률” 하나로 움직이는 방식이 아니다.

Route는 미리 만든 **100×5** 표를 사용한다. Setup @0x7100011360은 각 샘플에서 Physics.CastShape로 **ObjA/ObjE/기타**를 구분한다. Update @0x71000115ec은 회전에 따라 좌표를 이동하고 Boo y의 증감을 기록한다. GetTargetRouteData @0x71000118d0은 현재보다 각도가 작은 가장 가까운 줄을 고르고, 1° 미만이면 앞줄로 이동한다. GetTargetRouteNodeID @0x7100011b60은 인접 줄·후보의 충돌/레이 검사로 목표를 고른다. 후보를 못 찾으면 SyncRandMod 대체 분기가 있다. **선택 우선순위 전체와 대체 난수 인자는 미확정**이며 임의 최단거리 AI로 교체하면 다른 동작이 된다.

## 8. 다른 기능과의 상호작용

- 사람 이동·A 점프·착지·벽 접촉은 **main 공용 ComActor**. 고유 생성자는 GroundedTest를 켜고 MapCollisionLayerBit 인자 **6**을 지정한다(AArch64 @0x710001bcd0/0x710001bd68). 6을 `1<<6`으로 바꾸는 의미는 공용 API 확인 후 연결한다.
- 고유 플래그·rank·record는 `MGMgr`, `MGRecorder`, 공용 UI로 넘긴다. 일반 승패와 엔들리스 기록의 화면 연결은 공용 미니게임 흐름 참조다.
- 난수 알고리즘·f32 규칙은 01_core·`script/core/rng.ts` 참조. 고유 소비는 CPU 초기 5회와 Route 대체 분기다. 난수 호출을 rAF/렌더러에서 추가하지 않는다.
- 원본 PhysX를 웹의 단순 원·상자로 대체할 때는 고유 수동 밀어냄을 중복 적용하지 않도록 구분한다. 접촉 근사는 명시하고 감전 각도 판정은 그대로 유지한다.

### 9.2 현재 렌더러·lib API와 수명주기

공통 설계·API 설명은 [loader_manager](../engine/loader_manager.md) 11절, `script/lib/assetcore/index.ts`, `assetcore-three/index.ts`, `shell/stage3d/index.ts`를 참조한다. **현재 lib에는 mg0106용 게임 렌더러가 없다.** 아래는 고유 게임을 연결할 때 필요한 접점이다(웹 소스 확인; 구현 제안).

| 접점 | 연결 방법 |
|---|---|

| 무대 갱신 | `loadModel(name,{visible,instance,pri})`, `model(name).play(clip,{loop,startFrame,speed})`, `playFmab(root,file,opts)`, `getSocket(name)`, `setCameraDriver(driver,'anim')`, `update(dt)`(초→60프레임), `render()`, `dispose()` |
| 로딩·준비 | lib **get(key,kind,pri,owner)**·want·묶음 API 및 `ScenePreparer.prepare(root,pri)`의 PrepJob.promise. 키는 `mg0106/...` 소스 논리 경로, 우선순위 P0~P3. 로딩 완료와 GPU 준비 완료를 구분 |

### 9.3 구현 우선순위

1. 배치 3종 소켓·충돌·카메라·클립 길이를 먼저 추출하고 data/manifest를 만든다.
