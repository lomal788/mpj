### 2.1 기존 판독·미확정 일괄 목록

### 2.2 최신 C·INDEX·필요 함수 일괄 대조

[데이터] 최신 [decomp 폴더](../../../analysis/decomp/) C479개와 [Ghidra out 폴더](../../../ghidra_work/) C7개를 파일명·수정 시각·모듈 헤더로 다시 대조했다. `docs_gap*` 이름에 한정하지 않았다. 담당 mg0108.nro의 실제 C와 INDEX 대응480행을 확인했다. 다른 모듈의 같은 숫자 주소를 쓰지 않았다. [C][gamec]·[INDEX][index]·[TSV][func].

## 5. 상태·수명

[판독] 공용 main @0x71002e0500/@0x71002e0844의 준비→오프닝/스킵→시작→본편→종료→결과→퇴장 흐름은 [틀 §5·12.12][frame] 재사용이다.
[설계] mg0108는 MgGame 훅을 구현하고 게임 상태를 소유한다. 생성/정리·오프닝·본편·결과를 틀 단계에 연결한다. Work·저장·복귀는 app/minigame/frame 책임이다. [DESIGN §10.5][design], [틀 §12.12.1·12.12.4][frame].

[판독] life는 `max(0,life-damage)`이고 CheckHit 소비 damage는1이다. life>0이면 Damage 연출,0이면 DropOut·입력 차단·state3이다. mg0108.nro @0x7100007fa8/@0x71000103d0 [C][gamec].
[판독] Timer.Update는 paused/end가 모두 false일 때 elapsed를 limit까지 clamp하고 >=limit이면 end=true다. Wave.BeginMove는 speed<=0이면 반환하며, 활성 시 flag+0x78=1·+0x70=speed/Params+0x10·Timer999.0·모션 `wave_ma`를 설정한다. 파동 실제 반지름 갱신/풀 종료 조건은 별도 미판독이다. mg0108.nro @0x7100014540/@0x71000070c0 [C][gamec].

## 6. 계산식·의사코드

[판독] 착지 callback은 jumpStatus=3 상태에서 이전Y>0·현재Y<=0인 경계다. 생성 파동 speed는 `min+(startY/2.6)*(max-min)`이며 ProcessHipDrop 자체에는 clamp가 없다. mg0108.nro @0x7100008148/@0x7100010614 [C][gamec].
[판독] WithinLightWave는 `D=(wave.x-player.x)^2+wave.y^2+(wave.z-player.z)^2+wave.w^2`를 `(2*radius−0.25)^2<D<(2*radius+0.25)^2`와 비교한다. 두 비교 모두 엄격하다. player.y는 이 식의 피연산자가 아니며 Wave 벡터의 y/w를 근거 없이0으로 지우지 않는다. mg0108.nro @0x710000735c [C][gamec].
[판독] CheckHit는 player0→3 중 생존·Y<=Params+0x18(기본0.03)만 검사한다. owner0→3 중 자기 owner를 제외하고 slot0→7을 순회한다. 처음 발견한 이동 중 hit가 ProcessHit를 호출하고 해당 플레이어 검사를 끝낸다. 따라서 한 호출에 플레이어당 최대 한 hit 후보다. invincible이면 damage는 없지만 hit 탐색은 끝난다. mg0108.nro @0x710000f130/@0x71000103d0 [C][gamec].
[판독] 탈락은 Rank.SetRank가 같은 Main의 배치에 모은다. batchCount=n일 때 n==4이고 flag=false이면 rank0, 그 외 rank=remainingRank−n+1; 배치 모두 같은 rank, 다음 remainingRank=max(rank,1)−1이다. 초기 remainingRank 값은 Setup 판독 대기라 임의로3을 대입하지 않는다. mg0108.nro @0x710000c890/@0x710000c9c0 [C][gamec].
[판독] 종료 훅은 생존자를 life1..10의 bucket에 담고 낮은 life부터 같은 bucket을 한 배치로 처리한다(flag=true). GetWinLose는 rank==0이다. 따라서 시간 종료에서는 생존자의 life 차이가 순위 계산 입력이며 같은 life를 PlayerID로 갈라놓지 않는다. mg0108.nro @0x710000f5b0/@0x710000ca98/@0x710000ffd8 [C][gamec].
[판독] CPU state1은 wait 끝에 trigger/hold→state2,2는 hipDrop 대기 끝에 trigger→3,3은 jumpStatus3을 벗어나면 새 wait→1이다. 회피 state4는 avoid 대기 뒤 trigger와 SyncRandRangeF(0,100) 비교로2 또는5,5는 jumpStatus0이면 새 wait→1이다. wait/hip/avoid draw는 상태 진입 조건에 따라 소비하며 호출을 매 프레임으로 옮기지 않는다. overlay의 정확한 bit 인자는 C prototype 손실이 남아 있다. mg0108.nro @0x71000086c8/@0x7100007490/@0x710000752c/@0x71000075c8/@0x7100007664 [C][gamec].

[설계] 아래는 핵심 순서만 옮긴다. 파동 표시 메시 교차가 점수 판정의 근거가 되지 않게 코어 상태를 소비한다. mg0108.nro @0x710000eec0/@0x710000f130 [C][gamec], [DESIGN §10][design].

```text
Button.Update(); WaveMgr.Update(); PlayerMgr.Update(); TimerMgr.Update()
for p in [0,1,2,3]:
    if alive(p) && y[p] <= threshold:
        find first moving wave in owner/slot order, owner != p
        if ringHit: ProcessHit(p); break search for p
Rank.UpdateRank(false); publish rank UI
finish = aliveCount < 2 || UI.Timer.IsEndTimer()
```

## 12. 사용자 확인

[설계] 원본 규칙을 기본으로 유지한다. 함수 수800~1,300 기준은 충족하지만 특수 셰이더가 적다는 조건은 미입증이다. 다섯 게임이 모든 선정 조건을 충족했다고 선언하지 않는다. [후보 표](mg0203.md#부록-d-다섯-게임-후보선정-근거), [DESIGN §1·10][design].
[설계] §7.1의 그래프/반사/굴절 표현을 근사하려면 사용자 선택이 필요하다. 미승인 상태에서는 원본 그래프 판독 필요로 남긴다. [원본 폴더][archive]의 `Materials[].ShaderAssign.ShaderOptions`, [DESIGN §7][design].
[설계] 판독 후 화면 근사·kit 추출·착수 우선순위·아래 인일 수를 선택할 경우 미승인 추천으로 남긴다. 이번 범위에서 원본 실행·C 추출을 수행하지 않는다. [DESIGN §7·10][design], 부록 C.
