### 6.2 후속 규칙·CPU·난수 계약

[판독] GetUnusedKeys는 key vector 순서를 보존하며 Key+0x118!=0을 제외한다. GetUncorrectKeys는 그 목록에서 어느 Door+0x118 정답 ID와도 같지 않은 키를 고른다. 정상 판정은 선택 문 Door+0x118==선택 key index다. 모델 수를 판정 대신 쓰지 않는다. mg0110.nro @0x710000af50/@0x710000b0d0/@0x71000248b0 [C][gamec].

[판독] SelectKey/SelectDoor는 후보가 하나면 즉시 반환하며 Timer 만료 검사도 생략한다. 후보가 여럿이면 진입 시 만료를 먼저 보고−1을 반환한다. 입력 루프는 좌우 trigger→확정 bit1→Timer 만료 순서다. 방향 bits0x10100은−1,0x40200은+1이며 둘 다 있으면+1이 우선한다. 선택 위치는 `(current+count+direction)%count`이고 확정과 timeout이 같은 반복에서 겹치면 확정을 먼저 수락한다. mg0110.nro @0x710001dce0/@0x710001e820 [C][gamec].

[판독] 후보가 여럿인 경로는 사람도 ThinkTargetKey/ThinkTargetDoor→ResetOverlayInput을 호출한다. PlayerType1만 반복마다 SetOverlayInput을 쓰므로 인간 조작에서 전략용 Sync 소비가 없다고 바꾸지 않는다. ThinkTargetKey는3문×5키 확률, ThinkTargetDoor는 선택 키의3문 확률을 사용하고 비음수 중 낮은 값을 우선하며 후보 목록에서 SyncRandMod 한 회로 고른다. 기억 확률 생성은 종전 부분 판독 @0x7100017350을 재사용한다. mg0110.nro @0x710001dce0/@0x710001e820/@0x7100016ba0/@0x7100018ad0 [C][gamec].

[판독] IsEasySelect와 IsDistractSelect는 각각 SyncRandModF(1) 한 회 후 표의 확률과 `<` 비교한다. special은 easy 확률0,distract .9지만 draw는 유지한다. CheckPlayOnlyCPU는 남은 플레이어가 모두 Type1이면 모든 control의 special+0x18을true로 쓴다. AddPatternMemory는12byte 시도 기록을 append하며 자체 truncation은 없다. 보존 길이 적용은 부분 판독 확률 생성에 남는다. mg0110.nro @0x7100018868/@0x710001729c/@0x71000265a0/@0x71000272f0 [C][gamec].

[판독] overlay state0은 elapsed>brainTime→1, state1은 현재<target에서requested0x40200/>target에서0x10100·state3, 같으면requested1·state2다. state2는 elapsed>decideWait→3, state3은 requested 출력 후 elapsed>controlTime*.25→4, state4는 출력0 후 elapsed>controlTime*.75→1이다. bit값과 actor setter prototype 소실을 구분한다. mg0110.nro @0x710001992c [C][gamec].

[판독] RoulettePlayerTurn은 SyncRandMod 한 회로 vector index를 고르고 current/first PlayerID에 저장한다. PhaseRoulette는 이어 `[0,1,2,3]`에 네 SyncRandMod 교환을 적용하고 선택자 외 이동마다 SyncRandModF(.2) 한 회를 소비한다. 4인이 유효한 초기 경로는1+4+3=8회이며 마지막3회는 연출 대기용이다. modulus 소실 때문에 교환 균등성을 주장하지 않는다. mg0110.nro @0x710001be90/@0x7100024200 [C][gamec].

## 12. 사용자 확인

[설계] 원본 규칙을 기본으로 유지한다. mg0110의 함수 수는 원래800~1,300 기준을 벗어난다. 상한1,646 완화 및 선정 유지/교체는 사용자 확인이 필요한 미승인 추천이다. 다섯 게임이 모든 선정 조건을 충족했다고 선언하지 않는다. [후보 표](mg0203.md#부록-d-다섯-게임-후보선정-근거), [DESIGN §1·10][design].

[설계] 판독 후 화면 근사·kit 추출·착수 우선순위·아래 인일 수를 선택할 경우 미승인 추천으로 남긴다. 이번 범위에서 원본 실행·C 추출을 수행하지 않는다. [DESIGN §7·10][design], 부록 C.
