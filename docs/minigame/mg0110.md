# mg0110 이 열쇠가 네 열쇠냐 (Gate Key-pers)

[데이터] 작성일2026-10-10. 함수 목록·catalog·원본 설정·기존 공용 판독을 조사했다. [catalog][catalog], [TSV][func].
[미확정] **분석 진행: 게임 고유 C 없음. 게임 로직 판독 완료·웹 구현 완료가 아니다.** 원본 실행 확인은 없다. [INDEX][index].
[설계] [판독]은 기존 C 판독 재사용, [판독: 어셈블리]는 기존 명령 판독 재사용, [데이터]는 파일 값, [추정]은 원본 해석, [설계]는 웹 판단, [미확정]은 공백이다. 원본 주소는 모듈과 함께 쓴다. [DESIGN §2·10][design].

## 1. 기능 개요

[데이터] 4인 개인전이다. 문과 게임 열쇠의 올바른 조합을 찾으며, 모두가 시험한 조합을 기억하고 추리하는 것이 핵심이다. [규칙][ruledata] `im_inst_mg0110_rule`, [mgListND][list] `mgList[Name=mg0110].GameRule=VS4`.
[데이터] `inst_mg0110_ctrl00` = 스틱 선택, `inst_mg0110_ctrl01` = A 결정. [조작][controldata].
[데이터] `mgList[Name=mg0110]`는 `Available=1`, `Coin=0`, `Gyro=-1`, `Endless=0`이다. `mgInst[Name=mg0110].ControllerID_0/1/2=0`, `Gyro0_A/1_A/2_A=0`. [목록][list], [설명 설정][instdata].
[설계] 선정 이유와 완화 기준은 [mg0203 부록 D](mg0203.md#부록-d-다섯-게임-후보선정-근거)를 따른다. Gyro=-1·강체 심볼 부재는 모든 숨은 의존이 없다는 증명이 아니다.

## 5. 상태·수명

[판독] 공용 main @0x71002e0500/@0x71002e0844의 준비→오프닝/스킵→시작→본편→종료→결과→퇴장 흐름은 [틀 §5·12.12][frame] 재사용이다.
[설계] mg0110는 MgGame 훅을 구현하고 게임 상태를 소유한다. 생성/정리·오프닝·본편·결과를 틀 단계에 연결한다. Work·저장·복귀는 app/minigame/frame 책임이다. [DESIGN §10.5][design], [틀 §12.12.1·12.12.4][frame].

## 6. 계산식·의사코드

[미확정] 문/게임 열쇠 조합 추첨이 순열인지 복원 추출인지, CPU의 기억이 전원 공개 기록인지 자기 시도만인지는 C 없이 판독할 수 없다. `LotteryDoorKeyIndex @0x7100007f9c`, `PlayerControl::AddPatternMemory @0x71000272f0`, `GetRemenberCount @0x710001926c`와 `GetProbabilityAgoTable @0x7100017350`를 요청한다. [TSV][func].

[설계] 웹 후보 상태는 `doorKeyMatch`, `usedKeys`, `publicAttempts`, `activePlayer`, `turn`, `escapeOrder`, `cpuMemory`다. 원본 대응이 판독되기 전에는 서로 다른 기록을 합치지 않는다. 원본 필드 오프셋은 부여하지 않는다. [DESIGN §4·10][design], [TSV][func].

[데이터] NRO 함수 목록의 난수 import thunk: `SyncRandMod @0x7100030160`, `SyncRandModF @0x7100030ef0`. 이것은 main 함수 주소가 아니며 호출 횟수도 아니다. [TSV][func].
[미확정] 준비·본편·CPU·연출별 sync/async 호출자·조건·소비 순서는 C 없이 확정할 수 없다. 난수를0회로 처리하거나 seed당 결과를 만들지 않았다. [TSV][func], [INDEX][index].
