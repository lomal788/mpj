## 1. 기능 개요와 사용자에게 보이는 동작

4인 자유 대전(VS4) 레이스. 한 레인에서 세 종목을 이어서 한다.

| 구간 | 종목 | 조작(조작 설명 문구) | 진행 방식 |
|---|---|---|---|
| 1 | 수영(킥보드) | Joy-Con R 가로 쥐기로 **물장구치듯 흔들기** (`inst_mg0118_ctrl00` "헤엄치기") | 한 번 칠 때마다 속도 +1.6(최대 4.0) m/s, 프레임마다 0.92배 감쇠 |
| 2 | 세발자전거 | Joy-Con을 **페달처럼 원을 그리며 돌리기** (`ctrl01` "세발자전거 밟기") | 회전 방향 4분면 변화가 4번 연속 같은 방향이면 한 번 밟기(+0.17, 최대 2.0 m/s), 프레임마다 0.972배 |
| 3 | 허들 | Joy-Con을 **위로 들어 올리기** (`ctrl02` "점프") | 일정 속도 6 m/s로 달린다. 들어 올리면 점프. 허들에 걸리면 넘어진다(1초 경직, 앞 0.6초는 1.5 m/s) |

- 먼저 골인한 순서로 순위가 정해진다. 같은 프레임에 들어온 플레이어는 **같은 순위**를 받는다(6.9).
- 3명이 골인하거나 경과 시간이 180초가 되면 끝난다. 이때 출발 신호용 피스톨 소리(`SQ_SE_MG0118_FINISH_PISTOL`)가 난다.
- 화면 위쪽에 경과 시간(카운트업 타이머)이 보인다. 골인한 플레이어는 그때의 시간이 표시된다. 무대의 전광판(`mg0118_timer00`)은 첫 골인 전까지 같은 시간을 보여 준다.

### 3.4 본편 한 프레임 `Scene::GameMainProc @0x7100020ec0` [판독]

`OnGameStartAfter`는 장면 흐름 파이버 안에서 불리므로 본편 파이버는 **다음 프레임부터** 돈다(01_core.md 5.4). 본체 첫 줄이 `Fiber::Wait()`라서 실제 첫 반복은 그다음 프레임이다.

```
Wait()
UiManager::LocateOffScreenOperationGuideUiSet(플레이어0 위치, 플레이어3 위치)
loop:
  goalBefore = PlayerManager.GetGoalPlayerCount()
  PlayerManager.OnGameMainProc(ui)          // ① Player[0..3].Update ② 순위·기록 ③ 3명 골이면 타이머 정지
  target = GetFirstPlayerIsNotGoal()의 위치 → Scene+0x370
  CameraManager.UpdateForGameMain(Scene+0x370); SetZoomOutLength(PlayerManager.CalcZoomOutValue())
  UiManager.UpdateMapOperationGuide(); 플레이어 0..3: UpdateOffScreenOperationGuide(i, state, pos)
  UiManager.UpdateCountUpTimer()            // 180초에서 멈춤
  if (goalBefore == 0) MapManager.SetTimerBoard(UiManager.GetCurrentTime())
  NpcManager.UpdateForGameMain(goalCount, Scene+0x370, 마지막 플레이어 위치)
  if (UiManager.IsTimerFinished() || IsGoalPlayerCountReachedEndGame()) {
     Play("SQ_SE_MG0118_FINISH_PISTOL"); PlayerManager.OnGameMainWhenFinished();  // 4명 Player::OnGameEnd
     Scene+0x381 = 1; return                 // 파이버 끝
  }
  Wait()
```

- 플레이어 순서는 `GetMGEntryPlayerList` 순서다. 그 순서가 곧 레인 번호(0~3)다(`GetPositionsForPlayer(i)`) [판독].
- 같은 프레임 안에서 **플레이어 0이 먼저 움직이고 3이 마지막**이다. 순위는 4명이 다 움직인 뒤 매긴다.

`Timer`(0xC B) = `{u8 active, f32 elapsed, f32 duration}`, 모든 Player 타이머는 Update 첫머리에 `+0x30C, 0x334, 0x31C, 0x370, 0x328, 0x41C, 0x428, 0x3E4, 0x438, 0x444, 0x450` 순서로 갱신된다 [판독].

```
Timer::Start(d)  : elapsed = 0; duration = d; active = 1                       @0x710002346c
Timer::Update()  : if active { e = f32(elapsed + dt); elapsed = (e <= duration) ? e : duration;
                               if (duration <= elapsed) active = 0 }             @0x7100023480
Timer::IsEnd()   : 0 < duration && duration <= elapsed && 0 < elapsed             @0x71000234e0
```

## 6. 계산식·조건·상세 의사코드

모든 시간은 f32 초다. `dt = GetDeltaTime()`이다. **이 게임은 리듬 장면이 아니므로 오프라인에서 dt는 실측 프레임 시간(최대 0.05 s)이다**(01_core.md 4.4). 위치 갱신은 `fmadd(속도, dt, x)` 단일 반올림이다 [판독: 디스어셈블 `fmadd s0, s8, s0, s9`]. 속도 감쇠는 **dt와 무관한 프레임당 곱**이다(`speed *= 0.92`, `*= 0.972`) [판독]. 그래서 프레임 시간이 길어지면 원본 자체가 덜 감쇠한다. 웹이 고정 1/60으로 돌리면 60fps 원본과 같고, 원본의 처리 지연 상황은 재현하지 않는다.

`SixAxisSensorWaveDetector`(샘플마다):

```
v   = 종류(+0x40: 0 가속도, 1 각속도)의 벡터에 축 마스크(+0x44 비트 x=1,y=2,z=4)를 씌운 것

state 2(진행 중):
   mag < thr                → value = mag, state = 3, 이미터 호출, 초기화(state 0)
   dot(v, peak) >= 0         → if |peak| < mag: peak = v;  value = mag; 이미터 호출(state 2)
   dot(v, peak) < 0 (반전)   → value = 0, state = 3, 이미터 호출, 초기화 → 같은 샘플에서 아래 시작 검사
state 0 이고 mag >= thr     → count++, peak = v, value = mag, state = 1, 이미터 호출(state 1), state = 2
```

이미터 공용(`FUN_71000413d0`):
- state 1이면 '발사됨' 표시를 지운다.
- 이미 발사됐으면 건너뛴다.
- 판정(vt+0x38)이 2를 돌려주면 함수를 부르고 발사됨으로 표시한다.

| 이미터 | 판정 |
|---|---|
| Value(`SetTestValue`) | `test <= value` → 2 [판독 `FUN_71000415ac`] |
| Sum(`SetTestSum`) | state 1이면 합 = 0. state 1·2에서 합 += value. `test <= 합` → 2 [판독 `FUN_71000415e4`] |

즉 **한 파형(같은 부호로 임계 이상인 구간)에 최대 한 번** 발사한다. 부호가 바뀌면 새 파형이다.

## 8. 다른 기능과의 상호작용

- **입력 차단**: `SetInputControlEnabled(false)`는 다음 시점에 걸린다.
  - Setup
  - 골 도달(state 6 → 7)
  - OnGameEnd
- 입력이 꺼지면 파형 람다와 수영 정지·세발 판정이 모두 건너뛴다. CPU 경로는 입력 플래그를 보지 않는다.
- **같은 프레임 순서**: Player 0~3 Update → 순위 → 카메라 → UI → 전광판 → NPC → 종료 판정. 종료 판정은 같은 프레임의 골인을 본다.
- **센서 컴포넌트 교체**: 종목 전환마다 `_internalRemoveComponentByTypeDesc` 후 다시 붙인다. 변환기 링·파형 상태가 새로 시작한다.
- **타이머 정지**: 3명 골인 프레임에 UI 카운트업이 멈춘다. 180초 상한도 UpdateCountUpTimer가 직접 잘라 멈춘다.
- **일시정지**: 본편은 FiberLite라 기본 일시정지 단계를 따른다(01_core.md 5.5).

### 10.2 CPU 완주 시간 (재구현 계산, 레벨마다 시드 1~20)

가정:
- dt = f32(1/60)
- CPU 하나만 따로 난수열을 쓴다(원본은 4명이 같은 동기 난수를 나눠 쓴다).
- 점프 "성공" = 허들 통과, "실패" = 그 허들에 1회 충돌(물리 미확정이라 가정)
- 착지는 다음 허들 전에 끝난다

| 레벨 | 골 시간(s) 최소~최대 / 평균 | 수영 끝(s, 시드 1~3) | 세발 끝(s) | 허들 충돌 수 |
|---|---|---|---|---|
| Easy | 38.40~40.98 / 39.73 | 11.42, 11.37, 11.35 | 29.83, 29.95, 29.75 | 2~5 |
| Normal | 33.02~35.68 / 34.53 | 10.30, 10.23, 10.23 | 25.38, 25.32, 25.32 | 1~4 |
| Hard | 22.30~24.22 / 23.08 | 5.85, 5.72, 5.72 | 15.60, 15.45, 15.43 | 0~2 |
| Master | 19.87~22.30 / 20.27 | 4.80, 4.77, 4.77 | 13.10, 13.13, 13.00 | 0~3 |

- 시간은 상태 2 시작부터 잰다.
- gamerecord의 달성 기준(2499 → 24.99초 [추정 단위])은 Hard~Master CPU 수준이다. 단위 추정과 어긋나지 않는다.
- 이것은 식의 일관성 확인일 뿐 원본 시간이 아니다.

### 10.4 스텁과 검증하지 않은 범위

- 스텁으로 둔 것
  - 액터 물리(점프·착지·충돌)
  - 센서 틱 순서
  - UI 타이머 진행 방식. mgC 판독(SHARED)에 따르면 `bq::ComUiCountUpTimer`는 TickUpdate마다 `남은 −= dt`이고 `CurrentTime = 한도 − max(남은, 0)`이다. 장면 파이버와의 같은 프레임 안 순서는 미확정이라 재구현은 "골 프레임의 경과 시간 = 경과 프레임 × dt"로 둔다
  - 카메라·NPC·이펙트
- 함수 단위 재구현이 원본과 같다는 것은 확인하지 않았다(원본 골든 없음).

웹 구현 뒤 기대값(같은 가정): 레벨별 CPU 단독 완주 프레임이 `analysis/mgA_calc.json`의 `mg0118_cpu.*.goal_frames`와 같아야 한다(난수열 분리 가정 포함).
