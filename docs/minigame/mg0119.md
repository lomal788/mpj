# mg0119 기울이기 골프 (Tilt-a-Golf / コロコロゴルフ)

2026-10-02. 상태: **분석 진행(흐름·물리 경계·CPU 판독, 웹 미구현)**. 원본 실행 대조는 하지 않았다.
확정 수준 표기: **[실행]** 원본 실행 확인, **[판독]** 원본 코드 판독, **[데이터]** 데이터 확인, **[추정]**, **[미확정]**. 이 문서에 [실행]은 없다. 계산 결과는 **[재구현 계산]**으로 따로 적는다.

담당 mgD. 같은 계열인 [mg1002 아이템 구슬 굴리기](mg1002.md)와 아래 부분이 **코드 수준으로 같다**. 공통 부분은 mg1002 문서를 가리킨다.
- Joy-Con 자세 → 판 회전 변환(`SixAxisSensorInput::GetQuaternion`). 두 NRO의 디컴파일이 주소·심볼 이름을 빼고 한 줄도 다르지 않다 [판독].
- 판은 기울이지 않고 중력 방향만 돌리는 물리 처리.
- 공 강체 생성 인자. 반지름만 다르다.

## 1. 기능 개요와 사용자에게 보이는 동작

4인 동시 대전(VS4)이다. 화면이 2×2로 나뉘고, 플레이어마다 자기 골프 코스(같은 모양의 사본)를 Joy-Con으로 기울여 공을 컵에 넣는다.

- 라운드(홀) 3개, 라운드마다 제한 시간 30초.
- 라운드마다 컵에 먼저 넣은 순서로 **5, 3, 2, 1점**을 받는다. 같은 프레임에 들어가면 순서를 무작위로 정한다. 시간 안에 못 넣으면 0점이다.
- A를 누르면 그 자리 자세로 보정하고 공이 나온다.
- Joy-Con을 **흔들면** 공이 위로 튄다(점프).
- 공이 코스 밖으로 떨어지면(y < −1) 다시 A를 눌러 처음 자리에서 시작한다.
- 지형마다 굴림 저항이 다르다: 페어웨이·그린은 각감쇠 10, 벙커는 50. 나무에 맞으면 효과와 소리가 난다.
- 3라운드 합계로 순위를 정한다. 모두 0점이면 전원 무승부다.
- CPU는 코스에 미리 그린 경로(path1~3)를 따라 PID 제어로 기울인다.

## 3. 진입점과 전체 호출 흐름

### 3.1 클래스 구성 [판독]

```
mg0119::Scene : bq::MinigameScene    Params(0xF0 B), Sequencer*(+0x310), GameManager*(+0x318)
  GameManager       +0x10 ControllerManager, +0x18 MapManager, +0x20 UiManager, 파이버 "GameManager_PostUpdate"
  ControllerManager 플레이어 4명 ComController (사람: SixAxisSensorInput, CPU: AiInput)
  MapManager        +0x50 vector<Map>(0x110 B × 4, 플레이어마다 한 코스), 현재 스테이지, 코스 교체 연출
    Map             MapModel(+0x00 시각) / MapCollision(+0x90 물리) / JoyConModel(+0xC0) / 잠금(+0xF8)
  AiManager         CPU 슬롯 4개(엔티티 + ComAi), AiInput
  UiManager         타이머, 점수(ComUiStatus), 라운드 텔롭, 점수 팝업(ComUiScore), 순위
  ScreenManager     그래픽 레이어 4개, SplitScreenLayerList
```

### 3.2 준비 [판독 `GameManager::Initialize @0x710000d4e0`]

1. 참가자 4명의 PlayerWork 핸들을 GameManager+0x48 + 0x18·p에 복사한다.
2. `PhysicsModule::SetCollisionLayerBitMask(6..9, 1)`(디스어셈블: w1 = 6..9, w2 = 1). 플레이어별 코스를 레이어로 나누는 설정으로 본다 **[추정]**.
3. 라운드 스테이지 3개를 고른다(동기 난수, 인자는 디스어셈블로 확인):

| 칸 | Params | −1일 때 | 후보(Stage 번호 → 파일) |
|---|---|---|---|
| +0xA8 라운드 1 | StageRound1 | `SyncRandRange(1, 4)` | 1 r1_3, 2 r1_4, 3 r3_4 |
| +0xAC 라운드 2 | StageRound2 | `SyncRandRange(4, 7)` | 4 r3_1, 5 r1_5, 6 r1_6 |
| +0xB0 라운드 3 | StageRound3 | `SyncRandRange(7, 10)` | 7 r1_2, 8 r3_5, 9 r3_6 |

Stage 0은 `mg0119_stage_start`(오프닝 연습 코스)다. 이름 표는 `MapManager::kFilename @0x710006a550`이다 [데이터].

4. ControllerManager / MapManager / UiManager / ScreenManager 초기화.
5. 환경 엔티티를 만든다: `env_sky`(mg0119_env_sky.fmdb), `light`(dir_light), `joycon-light`(EnvFilePath 0x1a, +0x28 = 0xF0), `backgrounds`.
6. 레이어 0~3마다(엔티티 레이어 비트 1<<i) 다음을 만든다.
   - `env`(mg0119_env.fmdb)
   - `cloud`(구름 fskb + 스크롤 fmab 묶음, 슬롯 "background")
   - `sky`(모션 "sky")
   - `wind`(모션 "wind")
   - 시작 프레임 = `(int)SyncRandModF(FrameMax)` 3회 → 동기 난수 12회
7. 파이버 `"GameManager_PostUpdate"`(우선순위 1): 매 프레임 `PostCupInUpdate`(6.6).

### 3.3 장면 흐름 [판독]

Sequencer는 mg1002와 같은 틀이다([mg1002.md](mg1002.md) 3.3). 문맥 ctx는 +0xB0/+0xB4, 끝남 플래그는 +0xAC다.

| Scene 함수 | 동작 |
|---|---|
| `OnGameInit @0x71000251f4` | Initialize → `LaunchSequence(bq::flag::Check(0) ? 1 : 0)` (0 = GameOpening, 1 = GameOpeningSkip) |
| `OnGameOpening` | 끝남 플래그 |
| `OnGameOpeningSkip @0x7100025364` | Launch(1) |
| `OnGameStartBefore` | Launch(2) = GameMain |
| `OnGameStart` / `OnGameStartAfter` | ctx = (0,1) / (0,2) |
| `OnGameMain` | ctx == (1,0) |
| `OnGameFinish` / `OnGameFinishAfter` | ctx = (1,1) / (1,2) |
| `OnEndingInit @0x7100025420` | `GameManager::SetupEnding`(결과 장면 배치, 이 문서 범위 밖) |
| Ending 계열 | 1 반환(빈 함수) |

**GameOpening `@0x710000f14c`**
1. `MapManager::SetupOpening`: 시작 코스 Map 하나.
2. 0.25 s 뒤 `SpawnBallWithEffect`(공 등장 연기·SE).
3. 0.25 s 뒤 `Sleep(3.0, 데모 람다 @0x71000175c8)`.
   - 람다는 mg1002 6.5와 같은 자동 기울기다. 목표는 **컵(attach_fx01)**이다.
   - 컵 인이면 잠금 + 컵 인 이펙트·진동 후 거짓을 돌려 끝낸다.
4. 0.5 s 뒤 `ChangeMap(라운드1 스테이지, 0)` → `WaitUntil(교체 끝)`.
5. `SplitScreenLayerList::SplitTo(2, 2, 0.5)`(2×2 분할, 0.5 s) → `WaitUntil(분할 끝)` → 0.5 s.

**GameOpeningSkip `@0x710000f3d0`**:
- 모든 맵 이펙트를 멈춘다.
- `ChangeMap(라운드1, 1)`(즉시)을 부른다.
- `SplitTo(2, 2, 0.0)`을 부른다.

**GameMain `@0x710000f4a0`**
```ts
await waitUntil(() => ctx == (0,2));
for (round = 0; round < 3; round++) {        // this+0xB4 는 라운드 시작 전에 +1 (1..3)
  ui.showRoundTelop();  await waitUntil(ui.isFinishedRoundTelop);
  roundStart();
  await waitUntil(() => { roundUpdate(); return ui.isTimeUp() || allCupIn(); });   // 람다 @0x7100018648
  await wait(1);
  roundOver();
}
updateWinLose();  ctx = (1,0);
```

**RoundStart `@0x710000f798`**
- 플레이어 p마다 다음을 한다.
  - PlayerType이 1(CPU)이고 AiManager 슬롯 p가 아직 없으면 `AiManager::Register(p, ComLevel)`을 부른다.
  - 그 플레이어의 ComController를 지우고 AiInput으로 다시 만든다.
- `ControllerManager::SetInputEnabled(true)`, `UiManager::RoundStart`(남은 순위 목록 [0,1,2,3], 점수 표시 초기화, 타이머 `SetTimer(TimeLimit=30)` + Start).
- `AiManager::RoundStart`(ComAi::OnRoundStart: 상태 0, 레벨 = 기본 레벨).
- 플레이어 상태 +0xB8..+0xC4 = 0.
- 사람 플레이어만 Joy-Con 모형 FadeIn(A 안내).
- `MGSound::TryStartWhistle(1)`.

**RoundUpdate `@0x7100012150`**(매 프레임, 플레이어 p = 0..3)
```ts
// (가) 낙하·컵 인
for p: if (state[p] == 1) {
  if (ballEntity(p).translation.y < -1.0) {             // 맵 로컬
    requestRetry(p);  playVoice(p, "SAD");  ai.onBallDropped(p);
  } else if (mapCollision(p).isBallCupIn()) {           // 6.4
    controller(p).enabled(+0x50) = false;  ai.onBallCupIn(p);
    ui.addScore(p);  ui.scoreDirty[p] = 1;  playVoice(p, "JOY_HIGH");
    cupTimer[p] = 0;  mapModel(p).playCupInEffect();  if (!ball.noVib) vibrate();
    state[p] = 2;
  }
}
// (나) Joy-Con 모형 종류 갱신(PadType)
// (다) 모든 사람이 컵 인이면 AiManager::RequireAllComMaster()  → CPU 전원 Master 레벨
// (라) 조작
for p: switch (state[p]) {
  case 1: map(p).setRotation(controller(p).getQuaternion());
          if (controller.enabled && input.isTriggerShake() && mapCollision(p).applyImpulseForce())
            playVoice(p, "JUMP");
          break;
  case 0: if (controller.enabled && input.isTriggerRespawn()) {   // A (CPU: 6.8)
            controller.calibrate();  map(p).spawnBallWithEffect();  map(p).locked = 0;
            joycon(p).playDecisionSound();  joycon(p).state = 2;  playVoice(p, "READY");
            state[p] = 1;  ai.onBallSpawned(p);
          }
}
```

`RequestRetry @0x710001268c`: 잠금 = 1, 낙하 SE, 진동, (사람이면) Joy-Con 모형 FadeIn, `state = 0`.

**RoundOver `@0x710000fcd8`**
1. 입력 끔, 타이머 정지, `AiManager::RoundOver`(ComAi 상태 3).
2. 전원 컵 인이 아니면 플레이어마다 Joy-Con 모형 상태 = 2로 둔다. 상태가 1(공이 코스 위)인 플레이어는 `DeactiveBallWithExitEffect`(퇴장 이펙트) + `DeactiveBall`을 부른다 → 0.25 s.
3. 마지막 라운드(+0xB4 > 2)이면 `ShowRanks`를 부른다.
4. 0.5 s 뒤 맵 4개를 모두 잠근다(+0xF8 = 1) → 0.25 s → `HideTimer` → `WaitUntil(점수 UI 4개 끝)` → `HideAllScores`.
5. 남은 라운드가 있으면 `ChangeMap(stage[+0xB4], 0)`(코스 퇴장 `pos_course_out` / 입장 `pos_course_in` 모션)을 부른다. 그 뒤 `WaitUntil(교체 끝)`, `WaitUntil(타이머 애니 끝)`.

**UpdateWinLose `@0x71000100c0`**:
- `UiManager::GetRanks`가 4명 점수(ComUiStatus 값)를 점수 내림차순으로 정렬하고 동점은 같은 순위로 둔다.
- 그 결과로 `MGMgr::SetPlayerRank`와 `SetPlayerWinLose(rank == 0)`를 부른다.
- 전원이 1위 동점이면 GetRanks가 모두 순위 3으로 바꾼다. 그 경우 4명 모두 `SetPlayerWinLose(p, 2)`(무승부로 보임)다 **[판독, 2의 뜻은 추정]**.

### 3.4 한 프레임 순서

| 단계 | 내용 |
|---|---|
| 파이버(0x0E) | sequencer_fiber: RoundUpdate(입력 → 회전 → 중력, 점프 충격량) → GameManager_PostUpdate(우선순위 1): PostCupInUpdate |

- **공 생성**(`Map::SpawnBall @0x710001c728`): 엔티티 활성화, 시각 어태치먼트 켬, `ComBallCollision::Spawn(위치)` → `SetTranslation` + `Teleport` + 진동. 속도 0 초기화는 이 함수에 보이지 않는다(Teleport 동작 **[미확정]**).

## 6. 계산식·조건·상세 의사코드

### 6.1 입력 → 판 회전 [판독]

- 사람: `SixAxisSensorInput::GetQuaternion @0x710000b760` = mg1002와 같은 식([mg1002.md](mg1002.md) 6.1).
- `ComController::GetQuaternion @0x710000a514` = `slerp(q, target, Params.RotateCoef)`(기본 1.0 → 목표값)이다.
- CPU: `AiInput::Update @0x7100006644`가 `q = slerp(q, ComAi::GetQuaternion(), AiRotateCoef 0.5)`를 프레임마다 계산한다. `AiInput::GetQuaternion`은 그 q를 돌려준다. 그 위에 ComController의 RotateCoef 1.0 slerp가 한 번 더 걸린다.
- `Map::SetRotation @0x710001cd60`: 잠금이면 무시한다. 아니면 q를 +0x40에 저장하고 시각 루트 회전, `SetGravityDirection(q)`, Joy-Con 모형 회전을 갱신한다.

### 6.2 흔들기(점프) [판독 `SixAxisSensorInput` ctor `@0x710000b21c`]

ComActorSixAxisSensor에 변환기를 만든다. main 쪽 동작은 SHARED [mgA] 판독을 따른다.
- 변환기: 버퍼 크기 **200**, `SetRotateInPosture(1)`(가속도를 자세로 회전), `SetRemoveGravity(1)`(자세로 돌린 −UnitY를 뺌), `SetInverseAcceleration(1)`(부호 반전). 인자는 디스어셈블로 확인했다(`mov w1,#0xc8`, `mov w1,#0x1` ×3 @0x710000b2ec~0x710000b314). 변환기에는 프레임당 최신 샘플 1개만 들어간다.
- 파형 검출기: 대상 종류 0 = **가속도**, 축 마스크 2 = **y만**(x1 y2 z4), 임계 = `MoveThreshold` 0.25(0이면 −1 → 기본 0.1).
  - 상태 0에서 |v| ≥ 임계면 파형이 시작된다.
  - |v| < 임계거나 부호가 바뀌면 파형이 끝난다.
- 합 이벤트 `TestSum` 2.5: 파형 동안 값을 더하다가 합 ≥ 2.5가 되면 파형당 한 번 콜백을 부른다.
- 콜백이 `+0x2C = 1`로 둔다. `Update`가 프레임마다 0으로 지운다. `IsTriggerShake`는 +0x2C를 돌려준다.

근사: y 가속도(G, 중력 제거)가 0.25 이상인 프레임들의 값을 더해 2.5를 넘기면 한 번 점프한다. 예를 들어 0.5 G가 5프레임 이어지면 점프다. "값"이 성분값인지 절댓값인지는 **[미확정]**이다(mgA 판독 범위).

점프 `MapCollision::ApplyImpulseForce @0x710001bfe0` → `ComBallCollision::ApplyImpulseForce @0x710001c100`:
```ts
if (!physicsEnabled || airborne) return false;      // 땅에 있을 때만
airborne = true;
rigidBody.applyImpulse(UnitY * Params.ImpulseForce); // addForce(eIMPULSE): Δv = 5.0 m/s, 맵 로컬 +Y(판 법선 쪽, 월드 위가 아님)
return true;                                         // → 음성 "JUMP"
```
재구현 계산: 평평한 판에서 체공 2·5/29.4 = 0.340 s, 최고 높이 0.425 m(g' = 29.4).

### 6.3 공 힘·지형·소리 `ComBallCollision::ReceiveMessageImpl @0x7100008280` [판독]

```ts

onCollisionLeft(other) { contactKinds &= ~tagBit(other); airborne = (contactKinds === 0); }   // 0x5f503101
```

- `SetAngularDamping(kind)`의 switch에 tree(8)는 없다. kind 계산도 8을 보지 않는다. 나무나 이름 없는 `_col`(벽·틀)에만 닿아 있으면 0.05다 [판독].
- 페어웨이 비트가 있으면 다른 지형보다 먼저 고른다(페어웨이 > 벙커 > 그린 순).
- 진동(`UpdateRollingVibration @0x7100009010`):
  - 땅에 있고 속력 > 0.25(`|v|² > 0.0625`)이면 동작한다.
  - 지형이 바뀔 때(1, 2, 4)만 새로 재생한다.
  - gain = `((speed − 0.25)/1.75)·0.8 + 0.2`(위쪽 클램프 없음).
  - 그 밖에는 Stop이다.

### 6.4 컵 인·낙하·코스 밖 [판독, 재구현 계산]

### 6.7 CPU 입력 [판독 `ComAi` @0x71000036f0~]

```ts

  }
}
OnFixUpdate(dtSub) {                              // 0x5f454e06, PID 작동 중일 때
  controlState.tickFixUpdate(dtSub);               // 진행도 += dtSub / duration (≥ 0)
  e = target - ballPos (x, 0, z);   if (pidReset) { ePrev = e; pidReset = false; }
  integral += (e + ePrev) * dtSub * 0.5;  deriv = (e - ePrev) / dtSub;   ePrev = e;
}
GetQuaternion() {                                 // @0x7100004038
  const pid = AiParam[level].Pid;
  const vz = I·integral.z + P·e.z + D·deriv.z,  vx = I·integral.x + P·e.x + D·deriv.x;
  A = clamp(vz, ±MaxAngle);  B = -clamp(vx, ±MaxAngle);   // 라디안 그대로
  return qx(A) * qz(B);                           // mg1002 6.1과 같은 조립
}
```

- 출력각은 오차(미터)에 P를 곱한 **라디안**이다.
- 오차 1 m면 0.5 rad → 17°로 클램프된다. x 오차 0.3 m면 −8.59°다(`analysis/mgD_calc.json`).
- 부호: +z 오차 → X축 + 회전 → 맵 로컬 중력 +z 성분 → 공이 +z로 간다. 6.1 표와 맞는다 [재구현 계산].

### 6.8 CPU 경로 `ControlStateDefault` [판독]

`Initialize @0x7100005338`(공이 나올 때 / 상태 첫 Tick):
1. `lv = AiParam[level]`.
2. 경로 `i`: 가중치 (r0, r1, r2)에서 `u = SyncRandModF(r0 + r1 + r2)`로 고른다(u < r0 → 0, < r0+r1 → 1, < 합 → 2).
3. `SyncRandF() < MissRate`이면 실패 경로를 고른다.
   - 실패 경로(`GetMapPathMissRoute @0x710001c4f4`): 노드 수 − 2 = n. n > 0이면 `"miss" + (SyncRandMod(n) + 1)`까지의 경로, 아니면 정상 경로다.
   - 정상 경로(`GetMapPathClearRoute @0x710001c3e4`): `pathK`에서 `SearchRoute("start" → "end")`.
4. `speed = (BallSpeed − Var) + SyncRandModF(2·Var)`, `duration = 길이 / speed`, `+0x3C = 0.25 / 길이`.

`GetControlTarget @0x7100004cc8`:
- `MapPathRoute::CalcPosition(min(진행도, 0.9999))`을 맵 충돌 루트 회전의 역으로 맵 로컬로 바꾸고 y = 0으로 둔다.
- 진행도 < 0.25/길이(처음 0.25 m)이면 공 생성 위치에서 선형 보간한다.

`TickUpdateImpl @0x7100004ea4`:
- 상태 0.5 s 뒤 PID를 켠다.
- 매 프레임 공 속력·dt를 기록한다.
- 3 s가 지나면 창을 밀며 `이동거리/3 < 0.1`인지 본다. 그러면 **Trapped** 상태로 바꾼다.
- Trapped 목표(`@0x71000061c0`) = `ballPos + normalize(ballPos) × speed` **[판독: 디스어셈블, speed 값의 뜻은 추정]**.

동기 난수 소비(경로 한 번 고를 때): SyncRandModF 1 + SyncRandF 1 + (실패면 SyncRandMod 1) + SyncRandModF 1(속력). CPU 점프 타이머는 SyncRandModF 1이다.

| 대상 | PhysX | 게임 코드 |
|---|---|---|
