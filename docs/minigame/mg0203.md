[판독] Params의 CPU target 쌍은 level0: +0x1c/+0x20=`25,45`, level1: +0x24/+0x28=`35,75`, level2: +0x2c/+0x30=`60,75`, level3: +0x34/+0x38=`75,90`이다. 생성자의 packed 대입을 해당 두 int32 필드로만 해석했으며 `SyncedSetupGame`이 PlayerID별 `SetMinAndMax`에 전달한다. ### 5.1 후속 초기화·종료 수명

[판독] `CreateGame`은 68개 객체를 만들며 4인×17줄 배열의 표시 handle은 `player+4*row`, TumbleControl은 stride0x38이다. `InitGame`은 전부 초기화하고 숨긴다. `Appear`의 row>9 반환은 오프닝 표시 제한이며 점수 상한10의 증거가 아니다. mg0203.nro @0x71000050c0/@0x7100005390/@0x7100008000 [C][gamec].

## 6. 계산식·의사코드

[판독] 정상 OnGameMain 한 호출은 플레이어별 입력을 한 번 검사한다. 수락한 Swing마다 `score[p]++`이며 이 함수에 명시적 상한/hold 반복은 없다. 타이머 검사는 입력 처리 뒤에 있다. 다만 Timer.Update와 이 훅의 상대 스케줄은 남아 있어 수락 프레임 수를600으로 확정하지 않는다. mg0203.nro @0x7100010f18/@0x710000ce44 [C][gamec].
[판독] 점수 내림차순의 경쟁 순위다. 다른 점수로 바뀌면 정렬 위치를 rank에 쓰고 같은 점수면 앞 rank를 유지한다. 최고 점수가0이면 전원 rank=3·WinLose=2; 양수 최고 점수 동점은 모두 rank=0·WinLose=1, 나머지는0이다. 수치0/1/2의 전역 enum 의미는 여기서 새로 붙이지 않는다. mg0203.nro @0x7100013d58, 정렬 helper @0x7100014700/@0x7100015470 [C][gamec].
[판독] AI.Init은 플레이어0→3마다 target용 SyncRandRange 한 번, countdown용 SyncRandRangeF 한 번을 소비한다(총8회). base=600/target, 초기 countdown 범위는0.7×base..1.5×base이며 int 변환을 거친다. target의 실제 난이도 범위와 SyncRandRange 인자 일부는 아직 복구되지 않았다. mg0203.nro @0x710000a3c0 [C][gamec].
[판독] AI.OnGameMain은 프레임 카운터를 올리고 각 countdown을 줄인다. 갱신 전 값<=1이면 pulse=true와 새 SyncRandRangeF 한 회, 아니면 pulse=false다. 300프레임 전후로 잔여 `599-oldFrame`·target−현재 score를 반영해 다음 범위를 조절한다. 난수 소비는 pulse가 난 플레이어의0→3 순서이며, 인간 여부에 따라 AI 전체 갱신을 생략하지 않는다. mg0203.nro @0x710000a4f0/@0x7100010f18 [C][gamec].
[판독] Battan.UpdateCount는 카운터를 매 호출1 올리며 7호출마다 그룹을 처리한다. 표시 제어는17×4이고 그룹은17로 순환한다. 종료 반환은 `7*maxScore+18<counter`다. 재사용 idle 모션에 비동기 RandRange가 있고 정확한 호출 인자는 남는다. 점수 비교와 시각 도미노 갱신을 분리한다. mg0203.nro @0x7100006e40 [C][gamec].

[설계] 아래는 읽힌 범위를 옮긴 요약이며 미판독 스케줄을 보충하지 않는다. mg0203.nro @0x7100010f18/@0x710000ce44/@0x7100013d58 [C][gamec].

```text
AI.OnGameMain()
for p in [0,1,2,3]:
    if acceptedTrigger(p): Swing(p)  // 내부 score[p] += 1
if timerEnabled && Timer.IsFinished(): return finished
rank[p] = count(scores strictly greater than score[p])  // max>0
if max(scores)==0: rank[:] = 3; winLose[:] = 2
```

### 6.2 후속 규칙·CPU·난수 계약

[판독] `Battan::Update`는 player0..3, row0..16 순서다. idle 모션 종료 후 변형 선택은 비동기 `RandRange`이며 게임 Sync 난수와 분리한다. `OnGameEnd`는 score에 필요한 row10..16 표시를 더하므로 `Appear`의 초기10개를 최종 풀 크기로 쓰지 않는다. mg0203.nro @0x7100007d10/@0x7100006b60 [C][gamec].

## 12. 사용자 확인
