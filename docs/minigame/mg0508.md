## 1. 기능 개요와 사용자에게 보이는 동작

2대2 팀전이다. 팀마다 도마 위 큰 스테이크 하나와 큰 칼 하나가 있다. 칼은 두 팀원이 양 끝을 든다.

- 두 팀원은 각자 **좌우(x)로만** 움직인다. 칼날은 두 사람의 위치를 잇는 직선이다. 그래서 두 사람의 x가 같으면 칼이 세로(z축)로 서고, 다르면 비스듬해진다 [판독 6.2].
- 제한 시간(기본 10초)이 끝나면 칼이 내려가 스테이크를 자른다. **양쪽 조각의 "위에서 내려다본 면적" 비율**이 절반(50%)에 가까운 팀이 그 라운드를 이긴다 [판독 6.4].
- 라운드는 3번이다. 세 라운드를 모두 자른 뒤 결과 화면에서 라운드마다 비율을 공개하고 점수를 준다. 점수가 많은 팀이 이긴다 [판독 6.6].
- 화면은 팀별 분할 화면이다(두 팀의 도마는 같은 좌표에 겹쳐 있고 모델 레이어 비트로 나눠 그린다) [판독 7].

## 3. 진입점과 전체 호출 흐름

### 3.1 클래스 구성 [판독]

```
mg0508::Scene : bq::MinigameScene            장면. 상태 머신은 OnGameMain 하나(this+0x314)
  ├ CameraMgr (Scene+0x438)                  오프닝 카메라·분할 화면
  ├ Field ×2 (Scene+0x440 팀0, +0x448 팀1)   팀 하나 = 도마·칼·접시·스테이크 3장·플레이어 2명
  │   ├ Player ×2 (Field+0x108 칸0, +0x110 칸1)  칼 한쪽 끝을 드는 사람. COM 이면 updateCom
  │   └ Steak ×3 (Field+0x118, +0x120, +0x128)   라운드 0·1·2 스테이크
  │        └ Runtime ×4 (Steak+0xB0, +0x180, +0x250, +0x320)  잘린 조각 메시(양쪽 조각·양쪽 단면)
  └ Cutting:: (자유 함수)                   MeshDivide / Process / calcArea / SetWeight
```

- `Scene::Scene @0x710000f3c8`: `MinigameScene` 생성, 필드 0 초기화, 정적 `Scene::s_instance = this`.
- 제품·파이버 구조가 없다. 매 프레임 일은 모두 `Scene::OnGameMain`이 부르는 함수 안에서 끝난다 [판독].

### 3.2 준비 `Scene::SyncedSetupGame @0x710000f570` [판독]

1. 장면 엔티티: `mg0508_cutsurf.fmdb`(Scene+0x420), `env/mg0508_env.fmdb`(+0x330), `model/mg0508_bg00.fmdb`+`bg00.fmab` 애니(+0x360), `mg0508_tablecloth.fmdb`(+0x378).
2. `CameraMgr` 생성·`Initialize @0x71000035b0`.
3. 플레이어 4명을 `PlayerWork::GetTeamID()`로 팀 0/1에 나눈다. **두 팀이 정확히 2명씩이 아니면 Abort**한다.
4. 스테이크 순서 3개를 정한다(6.1). **동기 난수 `SyncRandMod(6)`을 SteakOrder 값과 무관하게 먼저 1회** 부른다.
5. `Field(0, 팀0 첫째, 팀0 둘째, order)`, `Field(1, …)`. 두 팀은 **같은 스테이크 순서**를 쓴다.
6. UI: 텔롭(`ComUiMGTelop` 타입 4, `SetRoundMax`), 타이머(`ComUiTimer` 타입 0), 상태(`ComUiStatus` 0x10/1/0xD), 점수판 `layout.lyt`의 `mg0508_point_pos.flyt`(`L_circle_1P/2P`, `L_point_1P/2P`, 텍스트 `mg0508_tlp_timer` 4개와 문자 `:`(0x3A)).
7. `Scene+0x320`(팀0 점수)·`+0x324`(팀1 점수) = 0, 상태 `+0x314` = 0.
8. 철판(griddle) `ComMatter` + 모션 `mg0508_griddle`(fskb) 재생, 오프닝용 스테이크(`steak00`)·조명·포스트 엔티티.

`Field::Field @0x7100007640`(팀 t):
- 도마 `mg0508_cuttingboard0t.fmdb`를 `bg00` 뼈 `pos_cuttingboard0t`에 붙인다(`Scene::hook`). 연기 이펙트 `mg0508_ef_steak_smoke00.eset`.
- `Steak` 3개 = `mg0508_steak%02d.fmdb`(번호 = order[i]).
- 칼 위치 엔티티 `knifeXZ`(Field+0x78), 칼 모델 `mg0508_knife0t.fmdb`(+0x90, `ComAnimator` 슬롯 `myslot`, 애니 `cut` = `mg0508_knife0t.fskb`), `ComAttachment`로 knifeXZ 에 붙임.
- 접시 `mg0508_plate0t.fmdb`(+0xA8, 같은 `pos_cuttingboard0t`).
- `Player(PlayerID, team, slot 0/1, &knife)` 두 명.

### 3.3 미니게임 흐름 훅 [판독]

`bq::MinigameScene::MinigameFlow`(main @0x71002e0500)는 한 프레임에 한 단계 처리기를 부른다. 처리기 표 main `0x71019e3250`(멤버 함수 포인터 19개)을 이번에 판독했다 [판독 `analysis/decomp/mgC_main_mgflow.c`]. 시작 부분만 적는다(장면 vtable 오프셋은 mg0508·mg0107 vtable 덤프로 이름 확인).

|---|---|---|---|
| 5 | `FUN_71002e14c0` | vt+0x210 `OnGameOpeningSkip`(또는 오프닝 계열) | 참이면 6 |
| 6 | `FUN_71002e14e8` | vt+0x218 `OnGameStartBefore`, 참이면 페이드인 | 7 |
| 7 | `FUN_71002e16c0` | **매 프레임 vt+0x228 `OnGameStart`**, 하위 0: vt+0x220 `OnGameStartTelopBefore` 참 → 시작 텔롭("Start"/"321Go"), 하위 1: 텔롭 끝 → 호루라기 | 텔롭 끝 + OnGameStart 참 → 8 |
| 8 | `FUN_71002e17f0` | vt+0x230 `OnGameStartAfter` | 참이면 9 |
| 9 | `FUN_71002e1818` | **vt+0x238 `OnGameMain`** | 참이면 10 |

### 6.1 스테이크 고르기와 배치 [판독 `SyncedSetupGame`, `Steak::Steak`]

```ts
const r0 = syncRandMod(6);                    // 항상 소비

  case 0: order = [r0 % 6, (r0 + 1) % 6, (r0 + 2) % 6]; break;

```

Steak 생성(팀0의 0,1,2 → 팀1의 0,1,2 순):
- `createBaseMesh`: 모델 첫 셰이프의 `_p0`(f32×3)·`_n0`·`_u0`·`_t0`와 **u32 인덱스**를 읽어 인덱스 순서대로 펼친 삼각형 수프를 만든다. 스테이크 6종 모두 이 형식이다 [데이터 dump: `Format_32_32_32_Single`, `UInt32LittleEndian`].
- `SteakPositionRandom`(기본 0)이 켜져 있을 때만:
  - `ang = SyncRandRangeF(-0.2, 0.2) * 0.5` → `localRot = (0, sin ang, 0, cos ang)`(y축 회전 각 = 2·ang). sin/cos 는 엔진 다항식 표(`SinCoefficients`/`CosCoefficients`) [판독].
  - 회전한 메시의 x·z 범위로 `x = SyncRandRangeF(-2.696 - minX, 2.696 - maxX)`, `z = SyncRandRangeF(-1.28 - minZ, 1.28 - maxZ)`. 범위가 뒤집히면 0.
- `minX/maxX`(+0x408/+0x40C) = 회전한 메시 x 범위 + 오프셋 x. 기본(회전·오프셋 0)에서는 메시 원래 x 범위다.

### 6.2 칼 평면 [판독 `adjustKnife @0x71000087e0`, `getKnifeOrigin @0x710000a314`, `getKnifeNormal @0x710000a560`]

```ts
p0 = players[0].pointEntity.translation; p1 = players[1].pointEntity.translation;
mid = (p0 + p1) * 0.5; mid.y = 0;                       // NEON 4성분 곱
ang = atan2f(p0.x - p1.x, p0.z - p1.z);                 // libm atan2f
knifeXZ.setTranslation(mid);
knifeXZ.setRotationFromEuler(0, ang + 3.1415927, 0);    // f32 상수 0x40490FDB
```

- 칼 엔티티 로컬 X축이 절단 평면의 법선이다. Bezel 오일러 규약(R = Rz·Ry·Rx, 03_graphics)으로 `normalWorld = (cos θ, 0, −sin θ)`, θ = ang + π.
- `getKnifeOrigin(r)` = (스테이크 r 월드 행렬의 역) × knifeXZ 위치. `getKnifeNormal(r)` = (스테이크 회전 3×3의 역) × knifeXZ 행렬 첫 열. 둘 다 **스테이크 로컬 공간** 값이다.
- 두 사람의 z는 항상 −3/+3이라 `p0.z − p1.z = −6`이다. x가 같으면 ang = π, θ = 2π, 법선 ≈ (1, 0, 0) → **양(+) 쪽 = x가 큰 쪽**이다 [재구현 계산으로 확인: 팀0 시작(왼쪽 끝)에서 양쪽 비율 92~95%].

### 6.3 메시 나누기 `Cutting::MeshDivide @0x71000060b0` + `Process @0x7100005020` [판독]

입력: 삼각형 수프 V, 원점 o, 법선 n(4성분). 출력: 양 목록, 음 목록, 단면 모서리 목록.

```ts
d(p) = { const v = (p - o) * n;  return (v.x + v.z) + (v.y + v.w); }   // ext+fadd.2S+faddp 순서, f32
for each tri (v0,v1,v2):                                  // 인덱스 0,3,6… (꼭짓점 3개 미만이면 빈 결과)
  d0,d1,d2 = d(v0),d(v1),d(v2)
  if (d0*d1 < 0 && d0*d2 < 0)      A,B,C = v0,v1,v2
  else if (d0*d1 < 0 && d1*d2 < 0) A,B,C = v1,v2,v0       // (dA, dB, dC 도 같이 돌린다)
  else if (d0*d2 < 0 && d1*d2 < 0) A,B,C = v2,v0,v1
  else { (d0 < 0 ? neg : pos).push(v0,v1,v2); continue; }  // ★ d0 만 보고 통째로 보냄
  t1 = dA / (dA - dB);  t2 = dA / (dA - dC);
  Pab = A + (B - A) * |t1|;  Pac = A + (C - A) * |t2|;    // Vtx 0x00~0x3F 전 성분 보간, +0x40~0x4F 는 0
  sideA = dA < 0 ? neg : pos;  sideB = 반대
  sideA.push(A, Pab, Pac);  sideB.push(Pab, B, C,  C, Pac, Pab);
  edges.push(Pab, Pac)                                    // createDanmen 용
```

- **원본 특이점**: 꼭짓점이 평면 위(d=0)에 있으면 곱이 0이라 나누지 않는다. 그 삼각형은 `d0`의 부호만으로 통째로 한쪽에 간다(`d0 == 0`이면 양 쪽) [판독].
- 반대쪽 사각형을 두 삼각형으로 쪼개는 순서(`Pab,B,C` / `C,Pac,Pab`)는 `param_9` 분기 중 한쪽만 판독했다. 다른 분기는 감는 방향만 다를 수 있다 [미확정]. 면적 합에는 영향이 없다(반올림 차만).
- `Steak::cut`은 같은 평면 판정 결과(첫 MeshDivide)만 점수에 쓴다. 이어지는 `MeshDivide(4인자)` 12회(±0.3, ±0.6 평행 이동, y 0.12/0.24/0.36 수평 평면)와 `createDanmen`은 조각·단면 **표시 메시**를 만드는 일이다 [판독].

### 6.4 면적과 라운드 판정 [판독 `calcArea @0x7100007470`, `getPositiveRate @0x710000baa4`, `OnGameMain` 상태 16 @0x7100013230]

```ts
calcArea(tris) {                                     // 삼각형마다, 목록 순서대로 f32 누적
  let s = 0;
  for (a,b,c) of tris:
    a.y = b.y = c.y = 0;                             // ★ y 성분을 지운다 → XZ 평면 투영 면적
    e1 = b - a; e2 = c - a;                          // 4성분(w 포함, 원본 w = 0)
    L2 = hsum(e1*e1);                                // (x+z)+(y+w)
    r  = frsqrte(L2); r *= frsqrts(r, L2*r); r *= frsqrts(r, L2*r);   // 뉴턴 2회
    u  = L2 == 0 ? 0 : e1 * r;
    h  = e2 - u * hsum(e2*u);
    s += (sqrt(L2) * sqrt(hsum(h*h))) * 0.5;
  return s;
}
areaPos = calcArea(pos); areaNeg = calcArea(neg);    // Steak+0xA8 / +0xAC
rate    = areaPos / (areaPos + areaNeg);             // Field::getPositiveRate
p  = Math.trunc(f32(rate * 100));                    // fcvtzs (0 쪽 절삭)
v  = p < 50 ? 100 - p : p;                           // 50~100
// 팀0 v0, 팀1 v1
result = (v0 == v1 || params.AlwaysDraw) ? 0 /*무승부*/ : (|50 - v1| <= |50 - v0| ? 2 /*팀1*/ : 1 /*팀0*/);
```

- **점수는 부피가 아니라 "위에서 본 면적"이다.** 스테이크 메시는 밑면이 거의 없다(아래로 향한 면의 투영 면적이 위로 향한 면의 1~4%) [재구현 계산]. 그래서 실제로는 윗면 실루엣을 둘로 나눈 비율이다.
- **원본 특이점**: `p`를 절삭한 뒤 접기 때문에 판정이 비대칭이다. 양쪽 50.0~50.99% → v = 50(최고), 양쪽 49.99% → p = 49 → v = 51.
- 결과값 `Scene+0x328`: 0 무승부, 1 팀0 승, 2 팀1 승. 점수판 숫자는 접기 전 값이다: 팀 k의 `T_point_L` = 100 − p_k, `T_point_R` = p_k(`setRate`, `sprintf("%d")`).
- `PhysX`는 절단·판정에 쓰이지 않는다. 판정은 전부 CPU 메시 계산이다 [판독: cut/MeshDivide/calcArea 경로에 물리 호출 없음].

```ts
let in = hold & (1<<8) ? -1 : hold & (1<<9) ? +1 : GetStickLeft(pid).x;   // 십자 ←/→ 우선
// COM 은 in = updateCom(x)
if (Math.abs(in) <= 0.2) {                      // 데드존
  if (|bodyPos - prevBodyPos| <= 0.005) { play('idle'); walkState = 0; } else setWalkMotion(bodyPos.x - prevBodyPos.x);
} else {
  const s = f32(in * 0.02);
  x = fmadd(s, params.PlayerWalkSpeed, x);       // x + s*1.0, 한 번 반올림
  setWalkMotion(s * params.PlayerWalkSpeed);
}
prevBodyPos = bodyPos;
const bx = cuttingboard.translation.x, st = steaks[round];
const lo = fmadd(st.minX, 0.8, bx), hi = fmadd(st.maxX, 0.8, bx);
if (x < lo) { x = lo; comState = 0; }
if (x > hi) { x = hi; comState = 0; }           // (lo > hi 면 hi 가 이긴다)
pointEntity.setTranslation((x, y, z)); input = (in, …);
```

- **이동은 dt가 아니라 프레임당 0.02 × 속도다** [판독]. 기본 속도 1.0이면 60 fps에서 1.2 단위/초.
- 비율 50(v=50)이 되는 x 구간은 칼이 세로일 때 폭 0.02~0.04다(아래 10절 표). 프레임당 이동량 0.02와 같은 크기라 1~2프레임 차이로 승패가 갈린다 [재구현 계산].
- 시작 위치(`Field::gameInit @0x7100009200`): `StartFromEdge`(기본 1)면 팀0 두 사람 x = 도마 소켓 x + steak0.minX×0.8, 팀1은 + maxX×0.8. 꺼져 있으면 소켓 x. z는 칸0 −3, 칸1 +3.
- 라운드 사이 `backToCenter`: 같은 시작 위치(다음 라운드 스테이크 기준, r>1이면 2로 클램프)로 `PlayerBackSpeed × 2 / 60`씩 걷는다 [판독, 걷기 세부는 미판독].

### 6.8 COM [판독 `Field::beginRound`, `Player::updateCom @0x710000df4c`, 디스어셈블]

목표 비율(팀마다, 라운드 시작):

```ts
lv = max(comLevel(p0), comLevel(p1));
idx = (type(p0) == COM && type(p1) == COM) ? lv : max(lv, 2);   // 사람이 끼면 최소 레벨 2
x = BASE[idx] + syncRandMod(RANGE[idx]);     // BASE=[35,40,45,48], RANGE=[10,8,6,3]
comTargetPct = x <= 50 ? x : 100 - x;        // 실제로는 항상 ≤ 50
```

`PlayerWork::GetPlayerType() == 1`이 COM이다(02_rhythm 3.2와 같은 판정) [판독].

COM 한 명의 프레임 처리(남은 시간 < 1.0초면 아무것도 안 함, 입력 0):

| comState | 동작 |
|---|---|
| 0 | `comWait -= 1`; 0이 되면(또는 이미 ≤0) 1 |
| 1 | 현재 칼로 `MeshDivide`+`calcArea`를 직접 돌려 `pct = trunc(rate*100)`. `diff = target − pct`. `diff ≠ 0` 이고 (`pct > 50` 또는 팀에 사람 없음 또는 `pct ≤ target`)이면: 보폭 `step` = |diff| ≥ 21: 1.0, 11~20: 0.7, 6~10: 0.5, 3~5: 0.3, 1~2: 0.1. `goal = x ∓ (step + SyncRandModF(step))`(diff ≥ 0 이면 −, 아니면 +). comState 2. 조건이 안 맞으면 3 |
| 2 | `|x − goal| > 0.12`면 입력 = goal 쪽 ±1, 아니면 3 |
| 3 | `comWait = W[lv] + syncRandMod(W[lv])`(W = [60,50,40,40], lv = 그 COM 자신의 레벨), comState 0 |

- 사람과 같은 팀일 때 `pct`가 (target, 50] 안이면 COM은 멈춘다. 사람이 맞출 여지를 남기는 동작으로 보인다 [판독, 의도는 추정].
- 클램프에 걸리면 comState가 0으로 돌아간다(6.7).
- `pct`는 양 쪽 비율이므로 목표(≤50)를 "양 쪽을 작게" 맞춘다. 칼이 세로일 때 x를 줄이면 양 쪽이 커진다 → diff ≥ 0(양 쪽이 작음)이면 x를 줄인다 [판독 + 재구현 계산 방향 확인].

### 6.9 칼 불투명도 [판독 `updateKnifeOpacity @0x7100008e58`]

두 사람 위치가 지난 프레임과 같으면(거리 ≤ 0) `knifeStillFrames += 1`, 60프레임을 넘으면 `opacity += (1 − opacity) × 0.1`(1 넘으면 1). 하나라도 움직이면 `knifeStillFrames = 0`, `opacity = max(opacity × 0.9, 0)`. 칼 재질 `mg0508_knife_mat`의 `material_utility_parameter0`에 넣는다(시각 전용).

### 6.10 절단 애니 중 표시 [판독 `cutStake @0x710000a7d0`, `Steak::update @0x7100019dc0`, `divMove @0x7100019fd4`]

- 매 프레임: 소켓의 시작점 대비 수평 거리(부호 = z 변화)와 y 변화로 `Steak::update(depth, dy)` → 스테이크 재질 `material_utility_parameter0/1/2`에 (tangent × depth × SteakForwardMoveScale, 누름량)을 넣는다. **스테이크 눌림은 셰이더 변형이다(로직 아님)**.

## 8. 다른 기능과의 상호작용

- **타이머**: 라운드 시간은 `bq::ComUiTimer`가 컴포넌트 Tick(0x5f454e00)에서 `GetDeltaTime`만큼 줄인다(SHARED [mgC]). 이 게임은 리듬 장면이 아니므로 오프라인 GetDeltaTime은 **실측 프레임 시간(최대 0.05초)**이다(01_core). 이동은 프레임 단위라 프레임이 느려지면 10초 동안 움직일 수 있는 거리가 줄어든다. 웹은 dt = 1/60 고정으로 근사한다.
- **입력 차단**: 게임이 직접 `GetHold`/`GetStickLeft`를 읽는 곳은 `Player::update`뿐이고, 이것은 상태 2(`updateRound`)에서만 불린다. 그래서 입력이 먹는 구간 = 상태 2다. `enablePadControl`은 beginRound·timeUp 모두 **false**로 불러 캐릭터 액터 자체의 스틱 이동을 끈다(`Player::gameInit`도 `SetInputControlEnabled`) [판독].
- **팀 순서**: 매 프레임 팀0의 두 사람 → 스테이크 → 칼 → 팀1 순이다. COM 판단은 팀원이 이번 프레임에 이미 움직인 위치를 본다(칸1 COM은 칸0의 이번 프레임 이동 뒤 값).
- **절단 시점**: 타이머가 끝난 프레임의 다음 프레임(상태 3)에 칼 위치를 읽는다. 그 사이 위치는 바뀌지 않는다(updateRound 안 불림).
- **난수**: 모두 동기 난수(`bex::RandModule` sync)다. 장면 시작 시드는 01_core 6.7.

- 이동·진행값 증가는 프레임 단위(dt 아님).

- 평면 위 꼭짓점 처리(d=0) 특이점 유지.
- 무승부는 두 팀 모두 +1.
- 결과 공개는 세 라운드를 모두 자른 뒤.
