## 1. 기능 개요와 사용자에게 보이는 동작

4인 대결(Showdown, 큰 미니게임)이다. 플레이어마다 자기 핀볼 테이블을 4분할 화면으로 친다. 제한 시간 안에 점수가 가장 높은 사람이 이긴다.

- 조작 [데이터 `mg_inst.json`]:
  - 오른쪽 스틱을 아래로 기울였다 떼면 공을 발사한다.
  - L(또는 한쪽 Joy-Con 버튼)로 왼쪽 플리퍼, R(또는 A)로 오른쪽 플리퍼를 움직인다.

- 공을 다 잃으면 메인 볼이 1초 뒤 다시 나온다(6.6). 게임 동안 점수만 쌓인다. 점수 상한은 99,999다.

## 3. 진입점과 전체 호출 흐름

### 3.1 클래스 구성 [판독: 함수 이름·생성 순서]

```
mg0911::Scene : bq::MinigameScene (wl::IMinigameScene 구현)
  └ GameMgr                          SyncedSetupGameImpl 에서 생성
      ├ GameParam(+0x30)             mg0911_config.csv → F[]/I[]
      ├ CharaDemoFrameParam(+0x48)   mg0911_demo_frame.csv
      ├ MapMgr(+0x38) ─ PinballMgr ─ PinballTable ×4 (플레이어별)
      │                   ├ 공용 오브젝트(레이어 2): CommonBumper×3, CommonRedGate, CommonCurveGate×2, CommonCirclePanel×4,
      │                   │   CommonStarSpinner×2, CommonStarSwitch, CommonPinballTableInSide, CommonSlingShot×2
      │                   ├ StageCollision(pinballtable_col.nbmap), Pipe×2, SilverCurvePoint
      │                   └ 테이블별: Flipper×4, Plunger, RedGate, CurveGate×2, WaluigiMedalMgr, SlingShot×2, Monitor,
      │                       Bumper×3, StarSpinner×2, CirclePanel×4, StarSwitch, WaluigiLamp×7, PinballTableInSide,
      │                       MainBall×1, SubBall×I10(5), Cannon, ElectricSpectaculars
      ├ CameraMgr(+0x28)  NpcMgr(+0x40: Npc_Waluigi, Npc_Gesso)  PlayerMgr(+0x18: Player×4)  UIMgr(+0x20: 타이머·ScoreUI)
```

- `Scene::Scene @0x7100068110`이 NPC 0x21·0x6B와 플레이어 캐릭터 5(WALUIGI)를 미리 싣는다.
- `Scene::SyncedSetupGameImpl @0x7100068500`이 Params(timelimit, slotstoptimesec)를 SceneParam에 복사한다. 이어서 `GameMgr::Initialize @0x7100033240`를 부른다.
- `GameMgr::SetUpGame @0x71000335b0`은 GameParam → CharaDemoFrameParam → MapMgr → CameraMgr → NpcMgr → PlayerMgr → UIMgr 순서로 만들고 각각 vt+0x18(Initialize)을 부른다.
  - `bq::flag::Check(0)`이면 `+0x84 = 8`로 둔다.
  - 아니면 어드밴티지 플레이어가 있을 때 바로 반환한다. 둘 다 아니면 `+0x88 = 4`다. 이 값들의 뜻은 **[미확정]**이다.
- 이어서 `PhysicsModule::DisableCollisionBetween`을 18쌍에 건다(4.5).

### 3.2 매 프레임 [판독, 부분]

- 오브젝트는 `PinballObjectBase::Run`이 `this+0x10`의 std::function(현재 상태 함수)을 부르는 상태기계다. 상태가 바뀌면 이 함수를 갈아 끼운다.
- `PinballTable::Run`은 테이블 오브젝트의 vt+0x20, 서브볼, ElectricSpectaculars 순서로 돈다.
- `PinballTable::PostUpdate`는 오브젝트 vt+0x100을 부른다. `appear && +0x519`이면 센서 판정(CheckHitBall)을 한다.
- `PinballTable::TickPostPhysics`는 물리 뒤에 공마다 vt+0x108(`CountermeasurePenetrationFlipper`)을 부른다.
- 엔진 타이밍:
  - 게임 코드는 CoreSystem 타이밍 0x0E에서 돈다.
  - PhysX 시뮬레이션은 타이밍 0x0F(FixUpdate 서브스텝)에서 그 뒤에 돈다. 등록자 `main @0x7100613f5c`가 PhysicsModule이다 [판독, core_b5.c].
  - TickPostPhysics의 타이밍 번호는 **[미확정]**이다.
- `Player::GameMainUpdate @0x7100063d7c`가 입력을 플리퍼·플런저에 넘긴다(6.1). 이 함수를 누가 어느 순서로 부르는지, Run/PostUpdate와의 상대 순서는 **[미확정]**이다(판독자 B 결과 미수령).
- 게임 끝: `GameMgr::IsGameEnd @0x71000347b0` = `UIMgr::IsFinishedTimer`.
  - 타이머 길이는 Params `timelimit`(기본 180초)로 보인다 **[추정]**. mgSetting의 `GameEndTime 300`과의 관계는 **[미확정]**이다.

### 4.5 충돌 레이어 [판독: `GameMgr::Initialize` 디스어셈블(판독자 A)]

- 비활성 쌍은 18개다: (6,7) (6,8) (6,9) (6,11) (6,12) (6,13) (7,8) (7,9) (7,10) (7,12) (7,13) (8,9) (8,10) (8,11) (8,13) (9,10) (9,11) (9,12).
- 레이어 배정:
  - 공 = 6 + p
  - 플레이어별 오브젝트(플리퍼·플런저·대포 등) = 10 + p
  - 공용 오브젝트 = 2
- 결과: 공은 자기 10+p 레이어와 공용·고정 레이어하고만 부딪친다. **다른 플레이어의 공이나 플리퍼와는 부딪치지 않는다.**
- 4개 테이블은 같은 좌표에 겹쳐 있고 레이어와 표시 비트(1<<p)로만 나뉜다 **[추정, 강함]**.
- 레이캐스트 마스크 4 = 레이어 2다.

## 5. 상태 전이와 전체 수명

### 5.1 메인 볼 [판독]

```
(없음) ─StartPut(t)─▶ ReplenishmentWait(t초) ─▶ ShotBefore(플런저 레인) ─레인 이탈─▶ Landing ─바닥 레이 적중─▶ Move
   ▲                                                                                                      │
   └──────── CheckBallAllLost(메인·서브 모두 !onStage) → StartPut(F14=1.0) ◀── Lost(fallPos.z 넘음 또는 y ≤ −20) ┘
```

- **Replenish 끝**: initPos로 순간이동한다. 속도를 0으로 두고 충돌을 켜고 **PhysX 중력도 켠다**. 그리고 appear를 켠다.
- **ShotBefore**: 매 프레임 플런저 접촉을 레이로 검사해 `hitPlunger`를 쓴다(6.2). 경사(`PlungerSlope`/`Wall` 태그) 레이가 끊기는 순간 다음을 한다.
  - `onStage = 1`
  - 관찰자 알림 0x31
  - 게임 카메라 애니
- 경로 이동(파이프·패널 레일)과 대포는 Move 도중에 들어갔다가 끝나면 Landing으로 돌아온다(6.5, 6.7).
- **PinballPlayEnd**(게임 끝): 공이 보이면 SE `SQ_SE_MG0911_DIS`와 이펙트 `mg0911_entry_exit03_primitive`(0.4)를 낸 뒤 사라진다. 상태 함수는 null이 된다.

### 5.2 서브 볼 (멀티볼) [판독]

- 테이블마다 I10 = 5개를 만든다.
- `SubBall::EnterStart(t)` → t초 대기 → `Enter`: 동기 난수 `SyncRandMod(2)`로 옆 방향 ±0.3을 정하고 `ApplyImpulse((±0.3, −1, 0)·F12)`를 건다. 그다음 Landing 상태가 된다.
- 등장 간격 합 = `GetSubBallSumAppeartime` = 아직 안 나온 서브볼마다 F13(0.5) × i.
- 서브볼을 부르는 이벤트(모니터·와루이지 이벤트 쪽)는 **[미확정]**이다.

### 6.1 입력 [판독 `Player::GameMainUpdate @0x7100063d7c`]


### 6.8 공에 거는 힘과 기울기 [판독 `BallBase::MoveUpdate @0x71000070e8`, `PinballTable::CreatePinballObject`]

- 스테이지 회전은 X축 10°다. 여기서 두 방향을 만든다.
  - `tilt = normalize(0, −sin10°, cos10°)` ≈ (0, −0.1710, 0.9853)
  - `up = cross(tilt, UnitX)` ≈ (0, 0.9853, 0.1711)
  - 오일러 분해 분기 일부는 [추정]이다.
- 매 프레임 `ApplyForce(up·F9·dt + tilt·F10·dt)`를 건다.
  - ApplyForce는 `PxRigidBody::addForce(…, eFORCE)`다 [판독, mgD 덤프 main @0x710062e92c]. eFORCE는 다음 시뮬레이션 스텝에서 Δv = F·dt_sim / m이 된다.
  - 그래서 Δv ≈ (F9·up + F10·tilt)·dt·dt_sim이다. **게임 코드의 dt와 물리 스텝 dt가 겹쳐 곱해진다.**
  - 고정 60에서 한 프레임 힘 벡터는 (0, −33.33, −8.33)이다. `ball_force(dirA = up 근사, dirB = tilt 근사)`의 단순 축 예시는 analysis/mgB_calc.json에 있다 [재구현 계산].
- PhysX 월드 중력도 켜져 있다(Replenish에서 SetGravityEnabled(true)). 월드 중력 값은 **[미확정]**이다.
- 이 장면은 리듬 장면이 아니다. 그래서 `GetDeltaTime`은 실측 프레임 시간(최대 0.05 s)이다([../engine/01_core.md](../engine/01_core.md)). 원본에서도 프레임 시간이 흔들리면 힘의 크기가 흔들린다. **웹은 고정 1/60으로 근사한다.**

### 6.10 이벤트: WALUIGI 램프 → 모니터 룰렛 [판독: 판독자 B]

**램프**
- 테이블에 램프가 7개 있다. 공에 맞은 램프는 꺼진다(다시 맞지 않는다). 카운트 +0x140이 늘어난다.
- 7번째에 broadcast(0x41)을 보내고 `Monitor::MonitorRouletteStart`를 부른다. 그다음 카운트는 0이다.
- 공을 다 잃으면(0x32) 카운트와 램프가 초기화된다. 그래서 **한 볼 안에서 7개를 모두 켜야 한다.**
- 이벤트 종료(0x42)에 램프가 리셋된다.

**확률 표** (`ProbabilityParam`): 1위와의 점수 차 구간별 이벤트 가중치(합 100)다.

| 점수 차 | 0 메달 | 1 미러볼 | 2 멀티볼 | 3 겟소 먹물 | 4 간판 |
|---|---|---|---|---|---|
| 0~19 | 5 | 10 | 0 | 50 | 35 |
| 20~49 | 10 | 20 | 5 | 40 | 25 |
| 50~99 | 20 | 20 | 20 | 20 | 20 |
| 100~199 | 50 | 5 | 40 | 0 | 5 |
| 200~9999 | 30 | 5 | 65 | 0 | 0 |

- 고르는 방법: `x = SyncRandMod(100)` 한 번, 가중치 누적에서 x가 속한 이벤트다.
- 제외 규칙: 미러볼이 등장 중이면 1을, 간판이 등장 중이면 4를 뺀다. 뺀 가중치는 남은 양수 항목에 정수 나눗셈으로 나눠 준다.
- **제외 목록이 비면 작업본을 리셋하지 않는다.** 이전 호출의 재분배가 남는다. 원본 특이점이므로 정리하지 않는다.

**룰렛 회전**
- 슬롯 모션 프레임 `pos += spd`(프레임 단위, dt 미적용), `spd = clamp(spd + acc·dt, min, max)`.
- 회전: acc F[0x2c]=2, max F[0x2d]=3, 3.0 s.
- 감속: acc −F[0x2e]=−2, min F[0x2f]=1.
- 멈춤: `|ev·20 − pos| ≤ spd`이면 ev·20으로 스냅한다. 20프레임마다 SE `…MONITOR00_RLT`, 정지 SE `…RLT_DEC`, broadcast(0x33).
- 1.0 s 뒤 남은 이벤트 시간 = **`slotstoptimesec`(기본 10 s)**다. 매 프레임 dt만큼 줄인다.

**이벤트 효과**

| 이벤트 | 효과 |
|---|---|
| 0 와루이지 메달 | 와루이지가 걸어 들어와 메달을 던진다. 위치는 토큰 본 14곳을 `SyncRandMod(14)` 14회로 섞어 정하고, 개수는 최대 10이다. 착지 뒤 빈 토큰 섞기(`SyncRandMod(빈 수)`×빈 수)와 메달마다 `SyncRandModF(0.3)` 등장 지연이 있다. 공이 메달(구 r 0.23)에 맞으면 I7 = 10점이다 |
| 1 미러볼 | 점수 배율 I9 = 2를 30 s(F[0x32]) 동안 건다. 끝(0x3c)에 1로 돌린다. 대포로 공을 흡입했다가 발사한다 |
| 2 멀티볼 | 정지 때 서브볼 SetOnStage. 등장하지 않은 서브볼 i마다 `EnterStart(0.5·k)`(5.2), 타워 점등 |
| 3 겟소 | 자기 화면에 먹물을 3번 뿌린다(`UIMgr::GessoInkStart`, 회전 `SyncRandModF(90) − 45`). 방해 연출이고 점수 변화는 없다 |
| 4 간판 | 30 s(F[0x33]) 등장한다. 공이 맞으면 같은 공당 1회 회전하고 I8 = 10점이다 |

이벤트 동안 카메라: 0x34 미러볼, 0x37 타워, 0x39 와루이지, 0x3b 간판(fever 파일). 줌 30프레임, 대기 0.5~1.0 s다.

### 6.11 CPU [판독: 판독자 B]

**ComParam** (`mg0911_com_param.csv`, 행 = ID, 열 1..4 = 레벨 0..3)

| ID | 행 이름 | ID | 행 이름 |
|---|---|---|---|
| 0 | PlungerPowerMin | 6 | ShotRange |
| 1 | PlungerPowerMax | 7 | IntervalSec |
| 2 | PlungerMissingShotParsent | 8 | IntervalShare |
| 3 | PlungerMissingShotContinuousNum | 9 | BallSearchRange |
| 4 | PlungerShotWaitTimeMin | 10 | SearchBallShotParsent |
| 5 | PlungerShotWaitTimeMax | | |

레벨 = `bq::PlayerWork::GetComLevel()`이고 0이 가장 약하다.

**GameStart (0x14) — 사람 포함 4명 전원, P0→P3**
- 목표 당김 = Min + `SyncRandModF(|Max−Min|)`
- 대기 = Wmin + `SyncRandModF(ΔW)`
- 즉 플레이어마다 동기 난수 2회다.

**플런저**
- 공이 레인에 있으면 대기 시간 뒤 스틱 오버레이로 `pull += dt·(−4)`를 한다.
- |pull| ≥ 목표면 놓고(발사), 대기·목표를 다시 뽑는다.

**미스샷** (0x32 공 전부 잃음, 사람 슬롯에서도 실행됨)
- missCnt < ContinuousNum이면 `SyncRandMod(100) < Parsent`일 때 미스다. 미스면 `0.8 + SyncRandModF(0.2)`를 추가로 뽑는다.

**플리퍼** (`ComBallShot`)
- `BallBase::IsComFlipperRange`(플리퍼별 거리 1.232/1.12 안 + 삼각형-구 판정)로 판정한다.
- 축~공 거리가 ShotRange 이상이면 0.2 s 홀드한다. 쿨다운은 IntervalSec, IntervalShare면 양쪽 공용이다.
- 탐색 굴림 `SyncRandMod(100) < SearchBallShotParsent`의 결과는 **읽는 곳이 없다**(난수만 소비).

### 9.2 웹 물리 (PhysX 대체)

원본 PhysX 바이너리는 NX64 직렬화라 웹 PhysX에 그대로 넣을 수 없다([../engine/06_scene_data.md](../engine/06_scene_data.md) 5절). 대신 기하는 모두 뽑혀 있다.

- **권장: 직접 구현한 구-메시 충돌**(06_scene_data 5.3 안 A). 이유는 세 가지다.
  - 동적 물체가 구 하나(공)뿐이다.
  - 플리퍼·플런저는 각도와 위치를 게임 코드가 정하는 사실상 키네마틱 물체다.
  - 범퍼·슬링샷·플리퍼의 "튕김"은 대부분 게임 코드의 임펄스다.
- 구현 요소:
  1. 정적 trimesh: 바닥·벽·경사(`mgB_apx.json` 메시) → BVH.
  2. 키네마틱 trimesh: 플리퍼 4개. 매 스텝 훅 변환으로 옮긴다. 플리퍼 표면 속도(각속도 × 반지름)를 접촉 응답에 넣는다.
  3. 범퍼 캡슐, 스위치 box, 게이트 트리거 box.
  4. 공: 반지름 0.2, 질량 1. 반발은 위 [추정] 표를 쓰고 마찰은 0이다. 회전은 마찰 0이라 무시할 수 있다 [판단].
  5. CCD: 공 이동 선분 스윕.
- 동등성:
  - 같은 dt에서 게임 쪽 식(힘·임펄스·순간이동·센서·점수)은 원본과 **식이 같다**.
  - 접촉 해(PGS 반복·접촉 오프셋)는 원본과 **비트 단위로 같을 수 없다**. 골든 대조는 "사건 순서·점수" 수준으로 한다.
- PhysX wasm(안 B)은 원본 설정을 맞춰도 결과 일치 보장이 없다. 대안으로만 둔다.

### 9.3 구현 순서

1. data.ts 생성, 테이블 기하 로드(nbmap·apx·gmk_pos 본).
2. 공 + 정적 충돌 + 6.8 힘 → 공이 경사를 따라 굴러 내려가는지 확인.
3. 플리퍼(6.2)·플런저(6.3) → 발사와 받아치기.
4. 범퍼·슬링샷·스위치·게이트·점수(6.4, 6.5).
5. 파이프·패널 레일·대포.
6. 흐름·타이머·이벤트(모니터 룰렛, WALUIGI 램프, 메달, 미러볼 ×2, 서브볼)·CPU·순위 — **추가 판독 필요(11절)**.
