## 1. 기능 개요와 사용자에게 보이는 동작

보드 게임 중 **아이템 미니게임**(1인)이다. 플레이어는 Joy-Con 하나를 기울여 정사각형 판(스테이지)을 기울이고, 판 위의 구슬을 원하는 아이템 칸으로 굴려 넣는다.

- 판은 2층이다. 윗층 판(아이템 등급 0, 가장 흔한 아이템)에 구멍이 나 있고, 구멍 아래 아랫층 바닥이 등급 1~4 칸으로 나뉜다.
- 구슬이 아랫층 칸 바닥에 닿는 순간 게임이 끝나고 그 칸의 아이템을 얻는다. 제한 시간(15초) 안에 떨어뜨리지 못하면 윗층(등급 0) 아이템이다.
- 판의 방향(90° 단위 회전)은 매번 무작위다.
- 시작 전 오프닝에서 판이 저절로 기울어 구슬을 시작 자리로 굴린다.
- 플레이어가 A를 누르면(=보정) 조작이 시작된다. 타이머는 그 전부터 돈다.

`GameManager::Initialize @0x7100007240`:

3. `ControllerManager::Initialize` → 엔티티 "controller" + `ComActorSixAxisSensor` + `SixAxisSensorInput` + `ComController`.

5. 엔티티 `camera`: 모션 "game"=`mg1002_cam_game.fsnb`, "op"=`mg1002_cam_start.fsnb`, 기본 그래픽 레이어 카메라로 지정.

7. UI: 엔티티 `account`에 `ComUiStatus(타입 0x10, 위치 0x1f, PlayerID)` → `In`. 엔티티 `timer`에 `ComUiTimer(0)` → `SetTimer(Params.TimeLimit)`(+0x20에 보관).

`MapManager::Initialize @0x7100013c70`:
1. `variation = Params.StageVariation == -1 ? SyncRandMod(4) : Params.StageVariation` (동기 난수 1회 소비, 인자 4는 디스어셈블 `mov w1,#0x4 @0x7100013cd4`로 확인).
2. `Map::Map(variation × π/2, PlayerID, Color)`.
3. 두 번째 그래픽 레이어(Joy-Con 화면) 켬: 엔티티에 카메라 `mg1002_cam_joycon.fsnb` 모션 재생, 환경 `ObjectList::EnvFilePath(0x1a)`.
4. 등급 0~4마다 `ItemTextures(GameWork::GetMinigameEntryItem(game, i))` → `MapModel::SetItemTextures`(판 장식 재질 `mg1002_item0{1..5}_mt`에 아이템 그림 텍스처 3장).
5. 파이버 `"MapManager_PostUpdate"`(우선순위 1): 매 프레임 `Map::PostFiberUpdate` 후 `Wait()`.

`Map::Map @0x7100012aa0`: `MapModel(yaw)` → `MapCollision(yaw, PlayerID)` → 엔티티 `pos_joycon`(mg1002_pos_joycon.fmdb) + `joycon`(ComJoyConModel, 뼈 소켓 `pos_joycon`에 붙임) → 공 충돌 콜백(공 변환 → `MapModel::SetBallLocalTransform`) → 공 소리 액터 연결.

`MapCollision::MapCollision @0x7100011e10`:
1. `actor::Util::LoadNbmap("map_collision", "mg/mg1002/map/mg1002_stage.nbmap")`.
2. 루트 엔티티 회전 = Y축 `yaw` 회전(쿼터니언 반각 계산 그대로).
3. 자식(충돌 엔티티) 순회 람다 `@0x71000157b0`: 모델 `SetVisible(false)`, `ComCollision::SetRestitution(1e-05)`.
4. 루트에 `ComMatter("mg1002_stage.fmdb")`를 붙이고 숨긴다(뼈 위치 질의용).
5. 엔티티 `ball_collision` + `ComBallCollision`(4.4) → `+0x110 = PlayerID`.
6. 공 위치 = `GetBallInitialPosition()`(뼈 `start00_pos` + 위로 0.18) → `SetTranslation` + `Teleport`.

### 3.3 Sequencer 와 장면 흐름의 동기 [판독]

`Sequencer`는 단계 함수 표(+0x00 + phase×0x30), 현재 단계(+0xD8), 끝남 플래그(+0xDC), 공유 문맥 `SequenceContext{int a(+0xE0), int b(+0xE4)}`를 가진다.
`LaunchSequence(phase) @0x71000185b0`: 기존 파이버를 멈추고 `FiberLite::Create("sequencer_fiber", prio 0)`. 파이버 본문(@0x7100018a88)은 단계 함수(ctx)를 부른 뒤 `+0xDC = 1`.

| Scene 가상 함수(MinigameFlow 가 부름) | 동작 | 반환 |
|---|---|---|
| `OnGameInit` | Launch(0) Opening | 1 |
| `OnGameOpening @0x71000186c8` | — | 끝남 플래그 |
| `OnGameStartBefore @0x71000186d4` | Launch(2) Main | 1 |
| `OnGameStart @0x71000186f4` | ctx = (0, 1) | 1 |
| `OnGameStartAfter @0x7100018708` | ctx = (0, 2) | 1 |
| `OnGameMain @0x710001871c` | — | `ctx == (1, 0)` |
| `OnGameFinish @0x7100018734` | ctx = (1, 1) | 1 |
| `OnGameFinishAfter @0x7100018748` | ctx = (1, 2) | 끝남 플래그 |
| `OnGameEndingBefore @0x7100018764` | Launch(3) Ending | 1 |
| `OnGameEnding @0x7100018784` | — | 끝남 플래그 |
| `OnGameOpeningSkip` | — | 1(건너뛰기 허용) |

main `MinigameFlow` 처리기 표(SHARED [mgC], main 0x71019e3250)에서 다음이 확인된다.
- 단계 7은 매 프레임 `OnGameStart`를 부른다.
- 단계 9는 `OnGameMain`이 참이면 단계 10(`OnGameEnd`)으로 간다.

따라서 `OnGameMain`이 참이면 본편이 끝난다 [판독: mgC]. `ComUiTimer`는 `TickUpdate`마다 `GetDeltaTime`만큼 줄어든다. `IsEndTimer`는 상태 0(시작 전) 또는 3(끝)일 때 참이다 [판독: mgC].

### 3.4 단계 함수 [판독]

**Opening `GameManager::Opening @0x71000082a0`**
1. 카메라 모션 "op" 재생 후 `SetPauseEnabled`를 부른다. bool 인자는 디컴파일에서 빠졌다. 4단계의 두 번째 호출과 짝을 이루어 "멈춤 → 풀기"로 본다 **[추정]**.
2. `Fiber::Sleep(3.0, 자동 기울기 람다 @0x710000d9d4)`: 매 프레임 람다를 부르고 람다가 거짓이거나 3초가 지나면 끝([../engine/01_core.md](../engine/01_core.md) 6.5, `bex::Fiber::Sleep(float, function) @main 0x710018ce90` 판독). 람다는 6.5.
3. `Map+0xD0 = 1`(회전 잠금 → PostFiberUpdate 가 판을 평평하게 되돌림, 6.4) → `Sleep(1.0)`.
4. `SetPauseEnabled`(풀기로 추정) → `WaitUntil(카메라 모션 끝)`(람다 `@0x710000e614` = `ComActorMotion::IsFinished`).
5. 텔롭 엔티티 `telop_objective`에 `ComUiGenericTelop(0)`, 메시지 `mg1002_instruction` → `Start` + `Play("SQ_SE_TLP_MG1002_ORDER")` → `Sleep(2.0)` → `Out` → `WaitUntil(텔롭 끝)`.

**Main `GameManager::Main @0x710000889c`**: ctx = (0,0) → `WaitUntil(ctx == (0,2))`(= OnGameStartAfter) → `GameMain`.

**GameMain `@0x7100008970`**
```ts
map.locked = false;  map.setRotation(IDENTITY);  controller.setInputEnabled(true);
timer.start();  mapManager.fadeInJoyCon();
await waitUntil(() => { joycon.setType(GetPadType(pid));
                        return controller.enabled && input.isTriggerRespawn() /*A*/ || timer.isEnd(); });
input.calibrate();  controller.q = IDENTITY;
if (controller.enabled && input.isTriggerRespawn()) joycon.playDecisionSoundAndVibration();
joycon.state(+0x74) = 2;  mapCollision.setPhysicsEnabled(true);
guide("ui_guide", place 3, "mg1002_guide");  if (!isGameFinished()) guide.in();
Play2D("SQ_VOI_PC%02d_JOY_MID" /* 캐릭터 PC 번호 2자리 */);
await waitUntil(() => { map.setRotation(controller.getQuaternion()); return isGameFinished(); });   // 매 프레임
timer.suspend();  guide.out();
if (!ball.notOnItem /* +0x7D == 0 : 지금 아이템 면에 닿아 있음 */) {
  if (ball.maxRarity < 1) mapCollision.setPhysicsEnabled(false);
  mapModel.playBallFallEffect();  map.locked = true;
  await sleep(0.5);  mapModel.illuminateItem(ball.maxRarity);  await sleep(0.5);  ctx = (1,0);
} else {                                   // 공이 공중(아이템 면과 접촉 없음)일 때 끝남
  ctx = (1,0);  map.locked = true;
  await waitWhile(() => ball.notOnItem);   // 어딘가 닿을 때까지
  if (ball.maxRarity < 1) mapCollision.setPhysicsEnabled(false);
  mapModel.playBallFallEffect();  await sleep(0.5);  mapModel.illuminateItem(ball.maxRarity);
}
```

`IsGameFinished @0x7100009d00` = `ball.maxRarity(+0x78) > 0 || timer.isEnd()`.
- **등급 1 이상 칸(아랫층)에 닿으면 즉시 끝**난다.
- 등급 0(윗층 판) 접촉으로는 끝나지 않는다. 시간이 다 되어야 끝난다.

**Ending `GameManager::Ending @0x7100009280`**
1. `item = GameWork::GetMinigameEntryItem(game, ball.maxRarity)`, `GameWork::SetMinigameGetItem(game, item)`. 인자는 디스어셈블로 확인했다(`ldr w19,[x8,#0x78]`, `mov w1,w19 @0x71000092e0`).
2. `Sleep(0.5)`.
3. 엔티티 `bgblur` + `ComUiItemMGBgBlur`(가상 +0x160 "in").
4. 엔티티 `gotitem` + `ComUiItemMGTelop(item)` → `Start` → `Sleep(3.0)` → `Out` → `WaitUntil(끝)`.

### 3.5 한 프레임 안의 순서 [판독 + 엔진 문서]

| 단계 | 내용 | 근거 |
|---|---|---|
| CoreSystem 0x0E | 장면 Update → 파이버: sequencer_fiber(GameMain 대기 람다: 입력 → `Map::SetRotation` → 중력 방향 갱신) → MapManager_PostUpdate(우선순위 1, 잠금이면 판 되돌리기) | 01_core 3.4, 파이버는 우선순위 오름차순 |
| 컴포넌트 TickUpdate(0x5f454e00) | `ComBallCollision`: 중력 힘 `ApplyForce` | SHARED [mgD] Tick ID |
| CoreSystem 0x0F × n | PhysicsModule 시뮬레이션(고정 60이면 1회) | SHARED [mgB] 0x0F = PhysicsModule |
| 물리 뒤 Tick(0x5f454e08) | `ComBallCollision`: 공 변환 → 시각 모델, 각감쇠 설정, 소리·진동, 속도 기록 | [추정: TickPostPhysics] |
| 충돌 메시지 0x5f503100/01 | 접촉 시작/끝: 등급·접촉 수·착지/벽 소리 | 메시지 수신은 시뮬레이션 결과 배달 시점 [미확정] |

TickUpdate 컴포넌트 메시지와 파이버(0x0E) 사이의 앞뒤 순서는 **[미확정]**이다. 그래서 회전·중력 방향이 이번 프레임 힘에 반영되는지 다음 프레임에 반영되는지 1프레임 차이가 남는다.

### 3.6 시간 단위

mg1002는 리듬 장면이 아니므로 `GetDeltaTime`은 실측 프레임 시간(최대 0.05 s)이다([../engine/01_core.md](../engine/01_core.md) 6.1, SHARED [core]). mg1002 게임 코드는 dt를 직접 쓰지 않는다. 대신 다음이 시간에 묶인다.
- `Sleep`·타이머: 실측 delta
- 판 되돌리기 `slerp 0.1/프레임`, 자동 기울기 `slerp 0.05/프레임`: **프레임 수**에 묶인다
- 물리: 서브스텝 dt(고정 60이면 1/60)

웹은 고정 1/60으로 근사한다(DESIGN.md 3절).

## 5. 상태 전이와 전체 수명

```
[장면 생성] → Initialize(판 yaw 무작위, 공 = start00+0.18)
   → Opening: 자동 기울기(≤3 s, start01 에 0.1 m 안이면 멈춤) → 잠금 1 s(판 되돌림) → 카메라 "op" 끝 → 텔롭 2 s
   → [OnGameStartAfter] → GameMain: 타이머 시작, A 대기(또는 시간 끝)
      → 보정·물리 켬 → 매 프레임 기울이기 ──(등급≥1 칸 접촉 또는 시간 끝)──▶ 결과 연출
   → Ending: 아이템 획득 기록, 텔롭 3 s
```

- **공 물리 켜짐**: `ComBallCollision+0x7C`는 생성 때 1이다. 그래서 오프닝부터 공은 굴러다닌다(자동 기울기가 공을 굴린다) [판독].
- **입력**: `ControllerManager::SetInputEnabled(1)`은 GameMain 시작 때다. A를 누르기 전에도 `ComController::GetQuaternion`이 입력 자세를 쓴다. 다만 GameMain의 매 프레임 회전 적용은 A 대기 뒤에 시작한다.
- **판 잠금(Map+0xD0)**: 1이면 `SetRotation`을 무시하고 `PostFiberUpdate`가 판을 단위 회전 쪽으로 되돌린다.
- **물리 끄기**: `SetPhysicsEnabled(false)` → `ComBallCollision::SetEnabled(false)`. 이때 +0x70/+0x74를 0으로 지우고, `ComCollision::SetEnabled(false)`, 굴림 SE를 멈추고(Stop_Preset 1), 진동을 멈춘다. 등급 0일 때만 끈다(그 밖에는 공이 계속 떨어져 칸에 자리 잡게 둔다).
- **재시작**: 장면 단위다. `CleanupGame`이 Sequencer와 GameManager를 지운다.

## 6. 계산식·조건·상세 의사코드

### 6.1 Joy-Con 자세 → 판 회전 `SixAxisSensorInput::GetQuaternion @0x710000a680` [판독, 재구현 계산]

입력은 `actor::ComActorSixAxisSensor::GetPosture()`(최근 자세 쿼터니언, main `SixAxisSensorConverter::GetPosture @0x710003f8d0`)이다. 쿼터니언 곱은 nn::util Hamilton 곱 (x, y, z, w)이다. 순서는 디컴파일의 TBL 셔플을 풀어 확인했다.

```ts
// Calibrate @0x710000ba44: calib = conj(posture) / |posture|²  (즉 posture⁻¹)
q1 = mul(calib, posture);                         // 보정 뒤 상대 자세
QA = axisAngle(X, -π/2);  QB = axisAngle(X, +π/2);
q2 = mul(mul(QA, q1), QB);                        // 축 바꿈: Joy-Con 자세 축 → 판 축
// 오일러 분해 (X 성분 A, Z 성분 B; Y 회전은 버림)
s = 2(Z·W + Y·X);  n = W²+Z²+X²+Y²;
if (s - n >= -1.1920929e-7)      { A = 0; B = +π/2; }
else if (s + n <= 1.1920929e-7)  { A = 0; B = -π/2; }
else { A = atan2(2(W·X − Y·Z), W²+Y²−X²−Z²);  B = asin(s / n); }
hi = MaxAngleDeg · 0.017453292;
A = clamp(A · GyroRate, -hi, hi);  B = clamp(B · GyroRate, -hi, hi);
return mul(axisAngle(X, A), axisAngle(Z, B));     // = (sA·cB, −sA·sB, cA·sB, cA·cB), 반각 s/c
```

- 삼각함수는 원본이 nn::util 다항식 근사(`SinCoefficients`, `CosCoefficients`, `AtanCoefficients`)를 쓴다. 계수 값은 읽지 않았다. 웹은 `Math.sin/atan2`를 쓰고 차이는 f32 수준이라고 본다 **[추정]**.
- 재구현 계산 결과(`analysis/mgD_calc.json` tilt_from_posture, 기본 Params):

| 입력 자세(보정 = 단위) | A(X축) | B(Z축) | 맵 로컬 중력 |
|---|---|---|---|
| 단위 | 0 | 0 | (0, −1, 0) |
| X축 +20° | +10° | 0 | (0, −0.985, +0.174) |
| X축 +40° | **+17° 클램프** | 0 | (0, −0.956, +0.292) |
| Y축 +20° | 0 | −10° | (+0.174, −0.985, 0) |
| Y축 −40° | 0 | +17° 클램프 | (−0.292, −0.956, 0) |
| Z축 +30° | 0 | 0 | 변화 없음(버림) |
| X+20 다음 Y+20 | +10.586° | −9.374° | (0.160, −0.970, 0.184) |
| 시작 자세 임의 p0에서 X+20 (보정 p0) | +10° | 0 | 보정이 기준 자세를 지운다 |

- 컨트롤러를 20° 기울이면 판은 10° 기운다(GyroRate 0.5). 34° 이상이면 17°에서 멈춘다.
- Joy-Con 자세의 물리적 축(어느 방향으로 쥐고 기울이면 X인지)은 `GetPosture`의 좌표계에 달려 있다. 이 좌표계는 이 문서 범위 밖이다 **[미확정]**. 가로 쥐기 축 변환은 05_ui_input의 단일 Joy-Con 규칙(SHARED [ui])을 참고한다.

`ComController::GetQuaternion @0x710000ff44`:
- 입력이 꺼져 있으면(+0x50 == 0) 저장된 q(+0x40)를 돌려준다.
- 켜져 있으면 `q = slerp(q, input.GetQuaternion(), 1.0)`이다. 결과는 목표값이고, 내적이 음수면 부호만 뒤집힌다. 그 값을 +0x40에 저장한다. 계수 1.0은 코드에 상수로 박혀 있다(mg0119는 Params.RotateCoef).

### 6.2 판 회전과 중력 `Map::SetRotation @0x71000136bc` [판독, 재구현 계산]

```ts
setRotation(q) { if (this.locked) return; setRotationInternal(q); }
setRotationInternal(q) {
  modelRoot.setRotation(q);                               // 시각: 판·공(자식)·스포트라이트
  ball.gravityDir = normalize(rotate(inverse(q), (0,-1,0)));   // MapCollision::SetGravityDirection
  joyconModel.setRotation(q);                             // 화면 구석 Joy-Con 모형
}
```

- **물리 세계(충돌 메시)는 기울지 않는다.** 판은 nbmap 루트의 yaw만 받는다. 기울기는 "맵 로컬 중력 방향"으로만 물리에 들어간다.
- 화면의 공은 판 모델 루트 아래 어태치먼트다. 로컬 변환은 물리 결과(맵 로컬)를 그대로 넣는다(6.3 물리 뒤 갱신 → `SetBallLocalTransform`).
- 따라서 웹도 "기울지 않은 판 + 회전한 중력"으로 시뮬레이션하고, 그리기만 판 루트에 q를 건다. 이 방식이 원본과 같다.

```ts
onTickUpdate() {                                  // 0x5f454e00, 매 프레임
  if (!enabled) return;
  rigidBody.applyForce(gravityDir * 9.8 * Params.GravityScale);   // eFORCE, 질량 1 → 가속 29.4·g방향
}
onAfterPhysics() {                                // 0x5f454e08
  if (onTransform) onTransform(entity.translation, entity.rotation);   // → MapModel::SetBallLocalTransform
  if (!enabled) return;
  notOnItem = (itemContactCount === 0);
  rigidBody.setAngularDamping(contactCount < 1 ? 0.05 : Params.StageDamping);   // 공중 0.05, 접촉 중 10
  updateBallRollSound();  updateBallRollVibration();
  velHistory.pushBack(rigidBody.linearVelocity); velHistory.popFront();        // 길이 5 유지
}
onCollisionEntered(other, contact) {             // 0x5f503100
  const r = getItemRarity(other);                 // 4.3
  maxRarity = max(maxRarity, r);  contactCount++;  if (r >= 0) itemContactCount++;
  const ny = contact.normal(+0x40) · UnitY;
  if (ny > 0.8660254) {                           // 바닥(30° 이내)
    if (skipFirstLanding) { skipFirstLanding = 0; }
    else if (!landSe.isAttached()) { landSe = Play3D("SQ_SE_MG1002_BALL_HIT_LND"); landSe.writeLocalVariable(15, …); }
  } else if (ny < 0.8660254) {                    // 벽 (같을 때는 아무것도 안 함)
    wallSe = Play3D("SQ_SE_MG1002_BALL_HIT_WAL");
    const vMean = sum(velHistory) / 5 /* ×0.2 */;
    wallSe.writeLocalVariable(15, (normal.x·vMean.x + normal.z·vMean.z) /* [판독 일부] */);
  }
}
onCollisionLeft(other) { const r = getItemRarity(other); contactCount--; if (r >= 0) itemContactCount--; }   // 0x5f503101
```

- `maxRarity`는 줄지 않는다. "지금 닿아 있는 칸"이 아니라 **"닿은 적 있는 가장 높은 등급"**이다.
- 착지 SE에 넘기는 로컬 변수 15번 값은 디컴파일에서 float 인자가 빠졌다. 접촉 충격량(+0x50..0x5C)의 제곱합으로 보인다 **[미확정]**.
- 벽 SE 값에 쓰는 속도 평균은 x·z만 쓰는 것으로 보인다 **[판독 일부]**.

`UpdateBallRollSound @0x71000042e8`:
- `|v|² > 0.0225`(속력 > 0.15)이고 `!notOnItem`이면 다음을 한다.
  - 루프 SE `SQ_SE_MG1002_BALL_ROL_LOP`를 소리 액터 훅으로 재생한다(없을 때만).
  - 로컬 변수 15번에 속력(sqrt)을 쓴다.
- 그 밖에는 `Stop_Preset(1)`이다.

`UpdateBallRollVibration @0x71000044e8`:
- `!notOnItem`이고 속력 > 0.15이면 진동을 재생한다(없을 때만, 진동 이름은 인자 누락으로 **[미확정]**).
- gain = `((speed − 0.15) / 1.85) × 0.8 + 0.2`. high·low 둘 다 이 값이다. **위쪽 클램프가 없다**(속력 2 이상이면 1을 넘는다) [판독].
- 그 밖에는 Stop이다.

### 6.7 굴림 근사 모델 (웹 대체용, PhysX 판독 + 재구현 계산)

PhysX 4.1 적분 순서는 `DyBodyCoreIntegrator.h bodyCoreComputeUnconstrainedVelocity`를 직접 읽어 확인했다(`tools/oss/PhysX-4.1`).
- 힘 → 속도: `v += F/m·dt`
- 감쇠: `ω *= max(0, 1 − c·dt)` (명시형)
- 그 뒤 접촉 해를 구한다.

미끄럼 없는 속이 찬 구(I = 0.4 m r²)로 근사하면 다음이 나온다.

```
dv/dt = (5/7)·g'·sinθ − (2/7)·c·v,   g' = 9.8 × GravityScale = 29.4
v_term = g'·sinθ / (0.4·c),   τ = 7 / (2c)
```

| 조건(θ = 17° 최대) | c | 종단 속력 | 시간 상수 | 1/60 이산 적분 0.5 s / 1 s / 3 s |
|---|---|---|---|---|
| 판 위(접촉 중) | 10 | **2.149 m/s** | 0.35 s | 1.652 / 2.034 / 2.149 |
| 공중 | 0.05 | 사실상 없음 | 70 s | 3.06 / 6.10 / 18.03 (자유 구름 가속 6.14 m/s²) |

- 미끄럼 검사: 필요한 마찰은 초기 2.46 N, 종단 8.60 N이다. μN은 0.75 × 29.4 × cos17° = 21.09 N이다. 따라서 **구름 유지**다 [재구현 계산].
- 이 모델은 원본 PhysX 실행과 대조하지 않은 근사다. 판 위 체감 속도를 정하는 주된 원인이 각감쇠 10이라는 점만 확정이다 [판독].

## 8. 다른 기능과의 상호작용

- **PhysX가 하는 것과 게임 코드가 하는 것**

| 대상 | PhysX | 게임 코드 |
|---|---|---|
| 공 운동 | 적분, 각감쇠 적용, 접촉·마찰·반발, CCD | 중력 힘(매 프레임 방향·크기), 각감쇠 값 선택(접촉 수 기준) |
| 판 | 정적 trimesh(기울지 않음) | 기울기 = 중력 방향 회전, 시각 회전, 잠금·되돌리기 |
| 칸 판정 | 접촉 시작/끝 메시지 | 태그 → 등급, 최대 등급, 끝 판정 |
| 소리·진동 | — | 속도·법선 기반 |

- **보드 게임**: `GetMinigameEntryItem`(등급별 아이템 5개)을 보드가 미리 채운다. 결과는 `SetMinigameGetItem`이다.
- **동기 난수**: `SyncRandMod(4)` 1회(스테이지 방향)뿐이다. 게임 중 난수 소비는 없다 [판독].
- **가변 프레임**: 힘은 TickUpdate(프레임당 1회)에서 넣는다. PhysX는 시뮬레이트마다 힘을 비운다. 그래서 한 프레임에 서브스텝이 2번이면 둘째 서브스텝에는 중력이 없을 수 있다 **[추정: 엔진 서브스텝 + PhysX 힘 소거 규칙]**. 웹(고정 1/60, 서브스텝 1)에서는 생기지 않는다.

### 9.2 물리 대체 설계 (직접 구현 권장)

판단: **직접 구현(06_scene_data 5.3 안 A)**을 권한다. mg0911(mgB)의 판단과 같은 방향이다.
- 동적 물체가 구 하나다. 상대는 모두 정적 trimesh다(판은 물리상 움직이지 않는다).
- 원본 게임 규칙이 PhysX에 기대는 부분은 세 가지뿐이다.
  - 접촉 시작/끝 이벤트(태그 → 등급)
  - 감쇠·마찰이 만드는 굴림 속도
  - 구멍 가장자리에서 떨어지는 기하
- PhysX wasm(안 B)으로도 같은 설정(구 0.18, 질량 1, 마찰 1.0/1.0 × 0.5/0.5 average, 반발 ~0, 각감쇠 0.05/10, contactOffset 0.02, CCD)을 그대로 줄 수 있다. 다만 원본 바이너리와 버전·솔버 반복 수·PCM 설정이 같다는 보장이 없어 비트 일치를 기대할 수 없다. 체감 비교용 대안으로 둔다.

직접 구현 요소(한 스텝, dt = 1/60):
```ts
// 1) 게임 TickUpdate: F = gravityDir * 29.4 (질량 1)
v += F * dt;                                          // PhysX: 힘 → 속도
w *= Math.max(0, 1 - angDamp * dt);                   // PhysX 명시형 각감쇠 (DyBodyCoreIntegrator.h)
// 2) 접촉 생성: 구 중심 p, 반지름 0.18, 정적 trimesh(BVH). 접촉 = 최근접점, 법선, 침투 깊이
//    contactOffset 0.02 안의 근접도 접촉으로 보고 이벤트 집계(Entered/Left 는 "셰이프(엔티티) 단위"로 이전 프레임과 비교)
// 3) 순차 충격량(PGS 근사, 반복 4회 권장 — PhysX 기본 위치 4/속도 1 [원본 설정 미확정])
//    법선: 반발 0 (≈5.5e-5), 침투 보정(바이어스)
//    마찰: 접점 속도 vt = v + w×(−n·r) 의 접선 성분을 μ=0.75 원뿔로 제한한 충격량, 각운동량에 r×P/I 반영
// 4) 위치 적분: p += v*dt, 회전 q += 0.5*(w,0)*q*dt (정규화)
// 5) 터널링: |v|dt < r 이면 불필요. 낙하 등 빠를 때는 구 스윕(이동 선분 vs 메시)으로 보정
```

동등성 검사 기준([재구현 계산] 값, 9.4):
- 17° 고정 기울기, 판 위 종단 속력 2.149 m/s, 시간 상수 0.35 s
- 공중 접촉 수 0 → 각감쇠 0.05
