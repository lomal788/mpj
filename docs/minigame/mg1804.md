## 1. 기능 개요와 사용자에게 보이는 동작

4인 협력 리듬 미니게임이다. 가운데 회전 테이블에 버거 자리(슬롯) 8개가 있다. 네 플레이어는 테이블 둘레에 서서 각자 맡은 재료를 받아 박자에 맞춰 던진다.

- 플레이어마다 재료가 정해져 있다. 1P 패티(P), 2P 치즈(C), 3P 토마토(T), 4P 양상추(L) [데이터: 채보 열과 글자].
- 아래 번(B)과 윗번(E)은 NPC 쪽에서 위에서 떨어진다(채보 `OBJ1`).
- 재료는 위(높이 20)에서 떨어져 플레이어 손에 들어온다(2×8분). 받은 뒤 **박자에 맞춰 Joy-Con을 흔들면** 테이블의 해당 슬롯 버거 위로 날아간다(2×8분).
- 판정은 던진 순간의 시계로 정한다. |오차| < 0.09 s면 JUST(정확히 쌓임), 아니면 SUCCESS(FAST/SLOW 텔롭, 테이블 회전 방향으로 ±10° 어긋나게 떨어진다).
- 들고만 있다가 시간이 지나면 재료가 연기와 함께 사라진다(놓침, 점수 0).
- 테이블은 채보 `OBJ2` 명령으로 22.5°씩 돌고 멈춘다. 윗번이 얹히면 버거가 완성되어 쟁반으로 옮겨진다.
- 점수는 JUST 2, SUCCESS 1, 놓침 0. 별 판정은 공용이다.

## 3. 진입점과 전체 호출 흐름

### 3.1 클래스 구성 [판독]

mg1801·mg1805와 **다른 틀**이다. 장면과 게임 객체가 "티켓"으로 소통한다.

```
mg1804::Scene : ca::rm::RmMgSceneBase      장면(+0x478 SceneLiaison*)
  SceneLiaison : Transceiver               장면 → 단계 요청(티켓 2), 완료 확인(티켓 4)
  Sequence(::Impl) : Fiber(0x10000)        단계 진행, 채보·총점, CommandAndControlSystem·Stage·PlayerManager 소유
    ├ ParamManager(싱글턴, Fiber 0)         mg1804_param.csv + 코드 기본값(4.3)
    ├ CommandAndControlSystem(Fiber 0x3f000) 지연 소리·이펙트·단계 명령
    ├ Stage(::Impl) : Fiber(0x20001)        테이블·재료(Parts 6종×9)·버거·결과·NPC·카메라
    └ PlayerManager(::Impl) : Fiber(0x20000) 플레이어 4명(Player : ca::mg::MGActorPlayer)
  TicketExchanger(Fiber 0x40000)           티켓 큐 배달
```

- 파이버 우선순위(생성자 첫 인자): ParamManager 0, Sequence 0x10000, PlayerManager 0x20000, Stage 0x20001, CommandAndControlSystem 0x3f000, TicketExchanger 0x40000 [판독: 각 `Impl::Impl`]. 01_core 규칙(오름차순)에 따라 한 프레임 순서는 **장면 흐름(우선순위 0) → Sequence → PlayerManager → Stage → CommandAndControl → TicketExchanger**다 [판독 + 규칙 적용]. mg1801(모두 0, 장면 흐름이 마지막)과 반대다.
- `Scene::Scene @0x7100010ee4`: `SetMinigameScene(this)`, SceneLiaison 생성, `LoadSceneNonPlayerCharacter(5, 0, 1)` = HEYHO(`chara/npc002`) [판독, mg1801 3.2와 같은 NPC].

### 3.2 티켓 [판독 `TicketExchanger::SendTicket @0x71000207e0`, `Update @0x7100020c90`]

- `Transceiver::DistributeTicket(kind, value, immediate)`: immediate=1이면 그 자리에서 모든 수신자의 `ReceiveTicket`을 부른다. 0이면 큐에 넣고, 프레임 마지막 `TicketExchanger::Update`가 큐를 비울 때까지 배달한다(배달 중 새로 들어온 것도 같은 Update에서 배달).
- 종류: 2 = 단계 요청, 4 = 단계 완료, 3 = 단계 시작, 5 = 박 코드(0 현재 줄, 1 다음 줄).

장면 훅 → 단계 번호(`Scene::Trig*`가 `SceneLiaison::RequestSequence(n)`) [판독]:

| 장면 훅 | 주소 | 단계 n | Stage `(3,n)` | PlayerManager `(3,n)` |
|---|---|---|---|---|
| `RmSyncedSetupGame` | @0x7100010fdc | 9 (즉시 `(2,9)`) | Initialize(이펙트·플레이어 훅) | Initialize(위치·연습 화살표) |
| `OnRmGameStartAfter` | @0x7100011618 | 0 | — | — |
| `TrigRmGameMainBgmPracticeStart` (단계 2) | @0x7100011660 | 1 | — | 입력 켬(`Player+0x30=1`) |
| `TrigRmGameMainBgmTopStart` (단계 5) | @0x71000116ac | 3 (계속 도는 명령) | 테이블·재료 갱신 켬(`+0x581=1`), NPC 8명 모션 1박 맞춤 | — |
| `TrigRmGameMainChartEnd` (단계 7) | @0x71000116f0 | 4 | 테이블 끔, 보이는 재료 전부 연기와 함께 지움, NPC 2박 맞춤 | 입력 끔 |
| `TrigRmGameEndingSetting` | @0x7100011744 | 7 | `Result` | — |
| `TrigRmGameResultCaptureSetting` | @0x7100011788 | 8 | 카메라 `capture` | — |

- 단계 요청 흐름: `(2,n)` → Sequence가 돌던 명령을 멈추거나 바로 `(4,·)` → Sequence가 단계 명령 n을 만든다. n=3은 명령으로 등록되어 `CommandAndControlSystem`에서 돈다(Prep에서 `(3,3)`), n=9는 Initialize, 그 밖은 곧바로 `(3,n)` → `(4,n)`이 SceneLiaison에 기록된다(`Sequence::Impl::ReceiveTicket @0x7100012bb0`, `PhaseCommand::Prep @0x7100013598`/`Post @0x71000135a8`).
- 그래서 `(3,n)`은 훅 프레임의 마지막(TicketExchanger)이나, 명령을 거치는 3·4는 1~2프레임 뒤에 도착한다 [판독 + 추정: 명령 첫 실행 프레임].
- 기반 클래스는 훅의 반환값을 쓰지 않는다(main `OnGameStartAfter`·`OnGameMain` 단계 7에서 한 번 부르고 무시) [판독 main_ca_rm.c].

### 3.3 준비 (`Sequence::Impl::Setup @0x710001261c`) [판독]

```
SetGameBgmName("SQ_BGM_MG1804_A"); SetGameBgmFinName("SQ_BGM_MG1804_A_MG_ENDING")
SetMainBeatType(1); SetMainBgmName(…)
채보: 모드 3 → "mg/mg1804/data/mg1804_rm_chart%02ds.json"(GetRemixChartNo), 모드 2 → chart01, 그 밖 → chart00
ReadChartData; SetStatusType(2); SetStarTotalScore(CalcTotalPoint())   // 6.1
CommandAndControlSystem::Setup; Stage::Setup; PlayerManager::Setup
Scene::RmSyncedSetupGame: SetNextChartDataOffset(2); DistributeTicket(2, 9, 1)
```

- **Params.chartNo(자유 채보)를 쓰지 않는다.** `IsChartDataFree`를 부르지 않는다 [판독]. Scene::Params(0x238 B, 생성 때 +0x20 = 120 외 대부분 0)는 mg1804.nro 안에 `GetSceneParam`·vtable +0x88 호출이 0건이라 게임 로직이 읽지 않는다 [판독: 디컴파일 전수 grep]. 속성 이름 목록은 정적 초기화 쪽이라 뽑지 않았다(11.2).
- 리믹스 파일은 `chart00s.json` 하나뿐이다 [데이터].
- BeforeOneBeat 없음, NextChartDataOffset 2 → 02_rhythm 10절 표와 같다.

### 3.4 박 코드 → 재료 등장 [판독]

| 장면 훅 | 주소 | 하는 일 |
|---|---|---|
| +0x328 `OnRmRecieveBeatEntry(Data 줄 r)` | @0x7100011030 | `Sequence::SetBeatCode(0, Data)` → `DistributeTicket(5, 0, 1)` 즉시 |
| +0x338 `OnRmRecieveBeatNextEntry(Data 줄 r+2)` | @0x7100011308 | `SetBeatCode(1, Data)` → `DistributeTicket(5, 1, 1)` 즉시 |

`(5,0)` = 현재 줄의 `OBJ1`(번)과 `OBJ2`(테이블 명령), `(5,1)` = 두 줄 뒤의 `1P~4P`(플레이어 재료)다(`Stage::Impl::ReceiveTicket @0x7100018ae0`, `PlayerManager::Impl::ReceiveTicket @0x710000f1b0`). `OBJ3`·`OBJ4`는 읽지 않는다 [판독].

### 3.5 한 프레임 순서 [판독]

```
1. 장면 흐름 OnGameMain: 단계 → 줄 배분 꼬리(Lock → Entry → NextEntry) → 티켓 5 즉시 배달(Stage·Player 가 받음)
2. Sequence::Impl::Update  (Wait 만)
3. PlayerManager::Impl::Exec (@0x710000ea90): [0,1,2,3] 을 SyncRandMod 로 섞고(4,3,2 — 3회) 그 순서로 Player::Exec
4. Stage::Impl::Exec (@0x7100017cc0): +0x581 이면 TurnTable, 재료 6종×9 의 +0x54 -= dt 와 상태 함수, 쟁반 정리
5. CommandAndControlSystem (지연 소리·이펙트·단계 명령)
6. TicketExchanger::Update (큐 티켓 배달)
```

- 같은 프레임에 등장한 재료는 그 프레임 Stage에서 바로 첫 갱신을 받는다(mg1801·1805와 다르다).
- 플레이어의 던지기(3)는 같은 프레임 Stage 갱신(4)보다 먼저다.

## 4. 구조체·필드·상수·열거형

### 4.1 재료 종류 [판독 Stage ReceiveTicket + Parts::Create @0x71000178dc]

| 글자 | 종류(`Parts+0x44`) | 모델 | 나오는 곳 |
|---|---|---|---|
| `B` | 0 아래 번 | `mg1804_obj00`(+`in00`, `put00`, `put01`=impact) | `OBJ1` `B` 뒤 숫자들 = 슬롯 |
| `P` | 1 패티 | `obj01` | `1P` |

| `T` | 3 토마토 | `obj03` | `3P` |
| `L` | 4 양상추 | `obj04`, 등장 때 SyncRandF 로 무작위 회전 | `4P` |

### 5.4 회전 테이블 [판독 `Stage::Impl::TurnTable @0x7100018534`, 명령 해석 `ReceiveTicket(5,0)`]

`OBJ2` 칸은 `:`로 나뉜 `키=값` 목록이다. 값은 다음 명령 칸(현재 명령의 복사본)에 덮어쓴다(지정 안 한 필드는 현재 값 유지).

| 키 | 필드 | 값 |
|---|---|---|
| `D` | dir | `S` 0(정지), `L` +1, `R` −1 |
| `W` | wait | 8분 × 값 |
| `T` | turn | 8분 × 값 |
| `A` | angle | 도 |
| `C` | ease | 값의 둘째 글자가 `N`이면 1(`ON`) |

- 첫 명령(Stage::Impl::Impl): ease 1, dir 0, wait 0, turn 8분×TURN_BEAT(1), angle 0 [판독].
- 매 프레임: dir 0이면 다음 명령으로 넘어가며 경과 = −wait. 경과 += dt; 음수면 대기. 0이 된 프레임에 `SQ_SE_MG1804_TABLE_TURN`(지연 turn − 경과). 진행 p = 경과/turn(ease면 `sin(p·π/2)`), 각도 = 누적 + dir·angle·p. turn을 넘기면 누적 += dir·angle, 다음 명령이 있으면 넘어가고 경과 = (경과 − turn) − 다음 wait [판독].
- 실채보 명령 예(chart00): 8번 줄 `D=L:W=3:A=22.5:T=1`, 62번 `D=S`, 72번 `D=R::W=3:A=22.5:T=1`(빈 토큰은 건너뜀) … [데이터, 전체는 calc json `table_cmds`].
- 재료가 떨어질 위치(`GetTargetPosition @0x710001c3a0`)는 비행 시간 뒤의 테이블 각도를 미리 계산해 정한다. 비 JUST는 dir·10°를 더한다 [판독].

```ts
if (player < 0) target = turntable.boneWorldPos(`hook_ingredients${slot}`);
else            target = player.boneWorldPos('attach_R_hand');
pos = (target.x, P.OVER_HEIGHT, target.z); show; play('entry');
state = 1; t = 0; dur = beatToSec(1,1)*2;
justTimer = beatToSec(1,1) * n; holdTimer = beatToSec(1,1) * (n + 2); if (type === 5) holdTimer = beatToSec(1,1) * 4;
```

- 실채보에서 종류별 순환 큐(9개)가 바쁜 재료를 고르는 경우는 없다 — 재료가 버거 윗번 줄 + 32줄까지 살아 있다고 넉넉히 잡아도 0건 [재구현 계산, 생존 구간은 추정].

### 6.5 Fall / Hold / Fly / Mount / PutOn [판독, 주소 4.2]

```ts
fall:  t += dt; if (t < dur) pos.y = lerp(start.y, target.y, t/dur);
       else { 위치 = target; play(null /*bound*/);
              if (player < 0) { EntrySound(type===5 ? 'BUNS_TOP' : 'BUNS_BOTTOM'); stackParts(slot); height[slot] += thickness; state = 3 }
              else { player.play('CATCH'); player.stack('HOLD'); 손에 붙임 }
              holdTimer -= t; t = 0; state += 1 }          // 번: 3→4, 재료: 1→2
hold:  t += dt; holdTimer -= dt; if (holdTimer <= 0) { player.play('IDLE'); state = 7 }
fly:   t += dt; if (t < dur) { k = t/dur; pos = lerp(start, target, k) + (0, 2·sin(k·π), 0) }
       else { just = |throwOffset| < JUST_RANGE; if (just) target = getTargetPosition(0,0,slot);
              위치 = target; stackParts(slot); play(null); EntrySound(`FOOD_LAND_${just?'JUST':'SUCCESS'}`); state = 4 }
clear: 보이면 (type 0: 'mg1804_vns_smoke01' + 'BUNS_MISS', type 5: 없음, 그 밖: 'mg1804_vns_smoke00' + 'MISS'); 떼고 숨기고 state 0
```

Mount·PutOn은 5.3 설명과 같다. PutOn 위치: `p = 1 − t/dur`, 수평 `cos` 보간, 높이 `MOVE_HEIGHT·sin(…)` [판독].

### 6.6 CPU [판독 6.2의 CPU 분기]

- CPU는 큐 앞 타이머 기준으로 JUST 직전 프레임(오차 +1/60 s)에 던진다. 받지 못한 재료가 없으므로 기본적으로 모든 재료가 JUST다 [재구현 계산].
- 실수 계획·난이도 분기가 없다. `RmGameWork` COM 레벨도 읽지 않는다 [판독: 디컴파일 전수 검색에서 사용처 없음].

## 8. 다른 기능과의 상호작용

- **박자 ↔ 판정**: 재료 등장은 사운드 시계(G14)를 따르고, 판정은 재료마다 dt 누적(`justTimer`)이다. 플레이어 큐 타이머도 별도 dt 누적이다. 두 타이머는 같은 프레임에 같은 dt를 빼므로 어긋나지 않는다 [판독].
- **입력 차단**: (3,1) 전과 (3,4) 뒤에는 Player::Exec가 바로 끝난다(큐 타이머도 멈춘다). (3,4)에서 테이블·재료 갱신도 멈추고 보이는 재료는 모두 지워진다.
- **테이블 켜기 지연**: (3,3)이 명령을 거쳐 1~2프레임 늦게 오므로 0번 줄 번의 낙하가 그만큼 늦게 시작된다. 플레이어 재료는 14번 줄부터라 영향이 없다 [판독 + 추정].
- **동기 난수**: 플레이어 셔플이 매 프레임 3회 소비한다. 양상추 회전값은 이 소비 이력에 달려 있다.
- **결과**: 별·징글·PERFECT는 공용 점수, 결과 무대 애니(`map01_result0N`)는 완성 버거 수다.
