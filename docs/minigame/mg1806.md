## 1. 기능 개요와 사용자에게 보이는 동작

4인 협력 리듬 미니게임이다. 무대 가운데 **멘토**(기본 와루이지)가 박자에 맞춰 포즈를 보여 주고, 다음 마디에 플레이어들이 같은 박자로 Joy-Con 을 휘둘러 포즈를 따라 한다. 성공하면 손에 든 향신료 병에서 가루가 냄비로 들어가고 카레 색이 진해진다.

- 한 판은 **멘토 단계(M) → 플레이어 단계(P)** 쌍의 반복이다. 사이에 쉬는 단계(W)가 있다(5.3).
  - M 단계: 멘토가 포즈를 취한다. 플레이어는 입력이 꺼진다.
  - P 단계: 멘토 단계와 **같은 리듬·같은 포즈 순서**를 단계 길이만큼 늦춰 플레이어가 한다.
  - 단계마다 참가자가 정해진다(채보 3P 열 `1234`, `12`, `34`, `13` …). 참가하지 않는 플레이어는 그 단계에 입력이 꺼진다.
- 포즈 종류는 5개(`POSE_00~04`)지만 **입력은 "휘두름 한 번"뿐**이다. 어느 포즈인지는 채보가 정하고, 플레이어는 타이밍만 맞춘다(6.4). 휘두른 플레이어 캐릭터는 채보의 포즈 모션을 재생한다.
- 판정: JUST / FAST / SLOW / 없음. 점수 JUST 2, FAST·SLOW 1(6.6).
- 단계 시작마다 휘슬이 카운트를 센다(카운트 수 2·4·8, 6.3). 스포트라이트가 참가자와 카운트를 표시한다.
- P 단계가 끝날 때마다 카레 냄비 색이 그때까지의 득점률만큼 진해지고, 득점률 30 %·60 %·80 % 에서 성공 이펙트가 하나씩 켜진다(7.4).
- 결과: 별 판정(80/40/0 문턱, 공용)에 따라 카레 모델 `ed_obj00~03` 과 김 이펙트가 바뀐다(6.7).

### 3.2 준비 단계 [판독]

1. `Scene::Scene @0x710000ed88`

   - `BeforeOneBeat` 는 부르지 않는다 → 줄 0 = 단계 6 시작(TopStart, 마디 B+1 1박) [판독, 02_rhythm 10절과 일치].

### 3.3 멘토 캐릭터 고르기 `Scene::SetMentorCharacterID @0x710000efd0` [판독]

- 4명의 `PlayerWork::GetCharacterID()` 를 모은다.
- 후보를 **순서대로** 보고 4명 중에 없는 첫 캐릭터를 멘토로 한다: WALUIGI(5) → LUIGI(1) → YOSHI(6) → CATHERINE(11) → WARIO(4).

### 3.5 파이버 순서 [추정]

매니저 Impl 5개가 모두 `bex::Fiber(0,false)`(우선순위 0)다. 만드는 순서: Sequence::Impl(RmSyncedSetupGame) → Info → Stage → Camera → Player. 모두 `OnStartUpdate`(SyncedSetupGame) 안에서 만들어지므로, mg1801_core.md 4절 규칙(우선순위 0, 안정 정렬, 그 전에 만든 파이버는 같은 프레임부터)을 적용하면 한 프레임 순서는

`Sequence::Impl::Update`(줌) → `InfoManager::Impl::Update`(시간 += dt) → Stage → Camera → **Player(입력·판정)** → … → 장면 흐름(OnGameMain → 줄 배분 → Entry/NextEntry 훅)

이다. 원본 실행으로 확인하지 않았다 **[추정: mg1801 규칙 적용]**. 판정 프레임 계산(6.3)은 "Player 가 흐름보다 먼저"에 기대고 있다.

## 4. 구조체·필드·상수·열거형

### 4.1 열거형 [판독 + 데이터]

`ACTION_TYPE`(CHART_INFO+0x4C.., PLAYER+0x48/0x4C):

| 값 | 채보 문자열(`CheckAction` 표 `@0x7100042930`) | 플레이어 모션 키 → 파일 |
|---|---|---|
| 0~4 | `POSE_00`~`POSE_04` | `pose0NI` → `rhy_spice_pose0Nb` (30f 루프) |
| 5 | (없음) | `missI` → `rhy_spice_miss00b` (50f 루프) |
| 6 | (없음) | `idle` → `rhy_spice_idle00` (30f 루프) — 멘토 "준비" |
| 7 | `SWING` | (모션 없음, 실채보 미사용) |
| 8 | 그 밖·빈칸 | 동작 없음 |

모션 키 표 `PLAYER::AddAnim::anim` 는 생성 때 채워진다(`AddAnim @0x710000cf90`): `idle→idle00, miss→miss00a, missI→miss00b, pose00I→pose00b … pose04I→pose04b`, 실제 파일은 `"rhy_spice_" + 값`. 모션 길이·루프는 `extracted/converted/character/motion_index.json` [데이터]. `miss00a`·`pose0Na`·`shake00~04` 는 아카이브에 있지만 mg1806 코드가 재생하지 않는다 [판독].

`CHECK_TYPE`(판정): **0 = FAST, 1 = JUST, 2 = SLOW, −1 = 없음**. mg1801(0 JUST, 1 FAST, 2 SLOW)과 번호가 다르다 [판독].

### 5.1 채보 해석 `Mg1806InfoManager::Impl::SetupChartInfo @0x71000075b0` [판독: 디스어셈블리]

채보 열: **1P = 단계 코드, 2P = 포즈 코드, 3P = 참가자 문자열, 4P = 사용자 정의 카운트(`*`), OBJ1~4 = 쓰지 않음**. 실채보에서 4P·OBJ 열은 모두 빈칸이다 [데이터].

```ts

for (i = 0; i < rows; i++) {

  ci = fresh();

    main.push(...temp);                                                       // M 항목 원본
```

- `setAction(ci, pose, players)` @0x7100008ac0: `CheckAction(pose)` 가 8 이면 4칸 모두 8. 아니면 `players` 에 `"1"`·`"2"`·`"3"`·`"4"` 가 **들어 있는** 레인만 그 포즈, 나머지 8 [판독]. (디컴파일은 레인 2·3 의 조건이 뒤집혀 보이지만 디스어셈블리 기준 모두 "포함" 검사다.)
- **2P 포즈는 카운트 경계 줄(M 줄에서 b 줄 간격)에서만 읽힌다.** 경계가 아닌 줄의 포즈는 버려진다 [판독 `@0x7100007a50`]. 실채보 포즈는 모두 경계 줄에 있다 [재구현 계산].
- 카운트 경계 줄마다 항목이 하나씩 생긴다(포즈가 없어도, action 전부 8).
- P 단계 항목은 M 항목을 **같은 상대 줄**로 복사한 것이다. 그래서 P 단계 길이는 1P 열의 `P_PHASE` 위치가 정한다(실채보는 늘 M 시작 + a).
- W_PHASE 는 그때까지 모은 M 항목을 버린다. 실채보에서 W 는 늘 P 뒤에 온다 [데이터].

**최대 점수 `CalcMaxCount @0x7100008e70`**: 항목을 앞에서부터 보며 `isTop` 항목의 phase 를 "현재 단계"로 기억한다. 현재 단계가 P 인 항목의 레인마다 `action != 8` 이면 maxScore += 2, 그 레인 최대 += 2, 포즈 수 += 1 [판독]. (`SWING`=7 도 센다. 실채보 없음.)

`SetPersonalPlayNum @0x7100008f80`: `GetPlayerList` 순서 p 의 PlayerID 로 `RmUiStatusMan::SetPersonalPlayNum(id, 포즈 수[p])` [판독].

### 6.1 입력 — 가속도 상승 에지 [판독 `PlayerManager::Impl::Update` @0x710000af68~0x710000afd8]

```ts
// 사람, 연습 아님, PlayerID != 4(멘토), active
if (DownTimer(cooldown)) {                          // cooldown -= dt, 0 이하로 떨어지면(또는 이미 0이면) 참, 0 으로 고정
  const a = InputModule.getAcc(playerId);          // (x,y,z,w) G
  const m = Math.sqrt(a.x*a.x + a.y*a.y + a.z*a.z + a.w*a.w);
  const prev = prevAcc; prevAcc = m;
  if (m >= params.acc && prev < params.acc) {      // fcmp/fccmp: 임계 이상이고 직전 프레임은 미만
    cooldown = 0.125;                              // 0x3E000000

```

- mg1801(`|a| > 2.9` 수준 비교, 쿨다운 = 8분)과 다르다: **임계 2.5, "이번 프레임 ≥ 임계 && 직전 프레임 < 임계"(상승 에지), 쿨다운 0.125 s 고정** [판독].
- `prevAcc` 는 쿨다운이 끝난 프레임에만 갱신된다(DownTimer 가 거짓인 동안 읽지 않음) [판독].
- 크기 식·`GetAcc` 단위·4번째 성분은 mg1801 6.5 와 같다(05_ui_input 6.1). 버튼 입력 경로는 없다(`isButtonPlay` 미사용) [판독].
- `ready` 가 0 이면 휘둘러도 쿨다운만 걸리고 아무 모션도 나오지 않는다 [판독 `@0x710000afd8 cbz`].

### 6.2 판정 트래커 갱신 (매 프레임, 입력보다 먼저) [판독 `Update @0x710000aac0~0x710000add4`]

```ts
function tick(t: Tracker): CHECK {                 // 열린 트래커마다
  t.counter++;
  if (t.counter == t.fastStart) t.comPress = (t.comCheck == 0);
  if (t.counter == t.t0)        t.comPress = (t.comCheck == 1);
  if (t.counter == t.slowStart) t.comPress = (t.comCheck == 2);
  if (t.counter >= t.end) { t.open = false; t.comPress = (t.comCheck == -1); return NONE; }
  if (t.counter < t.fastStart) return NONE;
  if (t.counter < t.justStart) return FAST;        // 0
  return t.counter < t.slowStart ? JUST : SLOW;    // 1 : 2
}
// 두 트래커 결과 r = JUST 우선 → FAST → SLOW → NONE
```

- 트래커는 매 프레임 먼저 돌고, 같은 프레임의 입력이 그 결과 r 을 쓴다 [판독].
- `comPress` 는 그 프레임에만 참이다(다음 tick 에서 덮어쓴다).

### 6.3 판정 창 [판독 `PLAYER::Ready @0x710000e2e0`][재구현 계산]

`Ready(action)` 은 판정할 줄 R 의 **한 줄 전**(줄 R−1 배분 = NextEntry) 프레임 F 에 불린다. 트래커를 교대로 열고 `counter = 0` 으로 둔다. 3.5 의 순서(Player 가 흐름보다 먼저)에서 프레임 F+k 의 tick 은 `counter = k` 다. BPM 120 에서 줄 R 배분은 F+15 프레임이므로:

| 판정 | counter | 줄 R 배분 프레임 기준 |
|---|---|---|
| FAST | 7~10 | −8 ~ −5 |
| JUST | 11~20 | **−4 ~ +5** (10프레임) |
| SLOW | 21~24 | +6 ~ +9 |
| 창 닫힘 | 25 | +10 (CPU "놓침" 누름) |

- 식: `t0 = GetBeatToFrame(1)`, `fast = t0−(hitWide+justFront)`, `just = fast+hitWide`, `slow = just+justWide`, `end = slow+hitWide`. Params 기본 4·4·10 [판독].
- **프레임 수 기준 창**이다. BPM 이 바뀌어도 t0 만 바뀌고 창 폭은 같다(BPM 180: t0 = 10, FAST 2~5, JUST 6~15, SLOW 16~19) [재구현 계산]. mg1801(f32 경과 시간 절삭 비교)과 다르다.
- 카운트 간격이 2줄(30프레임)이라 두 판정 창은 겹치지 않는다. 그래도 원본은 트래커 2개를 교대로 쓴다 [판독][재구현 계산].
- `Ready` 는 P 단계의 **모든 카운트 줄**(포즈 없는 줄 포함, action 8)과 P 단계 시작 줄에도 불린다. action 8 인 창에서 휘두르면 미스 모션만 나오고 점수는 없다(6.4).
- `Ready` 는 참가하지 않는 레인(`active=0`)에도 불리지만, 입력·CPU 모두 `active` 를 먼저 검사하므로 효과가 없다 [판독].

### 6.4 휘두름 판정 [판독 `Update @0x710000afdc~0x710000bc1c`, `TimingTelop @0x710000de3c`, `PlayerSucessEffect @0x710000e0d4`]

```ts
function judgeSwing(p, r /* 6.2 결과 */) {
  if (p.action == 8 || r == NONE) {                 // 포즈 없는 창이거나 창 밖
    if (!p.practice) { p.motionAction = 5; playMiss('missI'); }
    return;                                          // ready 는 그대로 — 창 안에서 다시 휘두르면 판정된다
  }
  p.motionAction = p.action;
  if (p.action >= 6) idle(); else if (p.action == 5) playMiss();
  else {
    playerSucessEffect(r);                          // ShowCommonEffect(r==JUST ? 0 : 1, pos+(0,1,0)), JUST 면 PlayExcellentSe(-1,true)
    motion.play(`pose0${p.action}I`, blend = params.shiftTime);   // "rhy_spice_pose0Nb", 속도 BPM/120
    spiceTimer = 0; spiceMotion = 이름; spiceCheck = r; spiceArmed = p.active;
  }
  const telop = { FAST:0, JUST:2, SLOW:1 }[r];
  ShowTimingTelop(p.playerId, telop, p.position + (0,-0.35,0), 0);
  Sound.Play2D(r == JUST ? 'SQ_SE_MG1806_POSE_JUST' : 'SQ_SE_MG1806_POSE_SUCCESS', pan = PAN[p.lane]);
  const pts = r == JUST ? 2 : 1;
  RmStarEffectMan.Start(pos, GetBeatToSec(0,1), p.playerId, pts);  // → RmGameWork 점수(공용 8.1)
  info.addScore(pts);                                              // 카레 색용 점수
  FxTrigger(r == JUST ? 'VB_MG1806_JUST' : 'VB_MG1806_SUCCESS');   // 진동
  p.ready = 0;
}
```

- `PAN` = `PLAYER::PlaySE::PAN @0x710003bb78` = `[-0.75, -0.25, 0.25, 0.75]`(레인 순서) [데이터].
- 텔롭 위치 오프셋 `@0x710003bb40` = (0, −0.35, 0) [데이터].
- JUST·FAST·SLOW 모두 **같은 포즈 모션**을 재생한다. FAST·SLOW 도 향신료 이펙트가 나간다. 판정 차이는 공용 이펙트 ID·SE·진동·점수뿐이다 [판독].
- **한 창에서 한 번만 판정된다**(판정 뒤 `ready = 0`). 창 밖 휘두름은 `ready` 를 남겨 둔다. 그래서 일찍 휘둘러 미스 모션이 나와도 0.125 s 뒤 창 안에서 다시 휘두르면 판정을 받는다 [판독, 원본 그대로].
- 창이 지나도 `ready` 는 1 로 남는다(트래커만 닫힘). 다음 Ready 전까지의 휘두름은 모두 미스 모션이다 [판독].
- 향신료 이펙트(`Update` 끝 `@0x710000bd20` 이후): `spiceMotion` 이 있으면 `spiceTimer += dt`, `≥ shiftTime(0.05 s)` 이 되면 `spiceArmed` 일 때 이펙트를 켜고 이름을 지운다 [판독].
  - JUST(`spiceCheck == 1`): SPICE_EFFECT+0x00 계열 `spice_stay00*`(훅 `attach_ef`) + +0x80 계열 `spice_stay_wave00*`(훅 `attach_ef01_Np`)
  - FAST·SLOW: +0x40 계열 `spice_stay01*` + +0xC0 계열 `spice_stay_wave01`
  - 같은 계열 4슬롯을 돌려 쓴다(슬롯 번호 0→1→2→3→0, PLAYER+0x230/+0x234).

### 6.5 CPU [판독 `PLAYER::Ready` 디스어셈블리, 점프표 `@0x710003bb70`]


## 8. 다른 기능과의 상호작용

- **박자**: 단계·포즈·판정 창 모두 줄 배분(G14 8분 상태 변화 프레임)에서 시작한다. 판정 창은 그 뒤 프레임 카운터라, 사운드→프레임 관측 지연이 생기면 창 전체가 함께 밀린다(mg1801 11.2 와 같은 미확정).
- **NextEntry 한 줄 앞서기**: Ready 와 줌·카메라 종류·Active 는 판정 줄보다 한 줄(8분) 먼저 일어난다. Lock 훅은 비어 있다.
- **입력 차단**: M·W 단계, 참가하지 않은 레인, 연습 중(`practice`), 마지막 P 단계 뒤(`Last`), ChartEnd 뒤(`EndPlayer`) [판독].
- **같은 프레임**: 트래커 tick → 입력/CPU 판정 → (흐름) 줄 배분·Ready 순서 [추정 3.5]. 그래서 Ready 와 같은 프레임에는 그 트래커로 판정되지 않는다(counter 0).
- **동기 난수**: 기본 설정에서는 쓰지 않는다. comMode 4~6 에서만 Ready 마다 소비 [판독].
- **결과**: 수프·징글·PERFECT 는 공용 상태 점수로 정한다. InfoManager 점수는 카레 색 전용이다.
