## 1. 기능 개요와 사용자에게 보이는 동작

4인 협력 리듬 미니게임이다. 플레이어 4명이 의자 위에 한 줄로 앉아 거품기를 들고 있다. 위에서 구름 위 NPC(쥬게무)가 크림을 떨어뜨리고, 헤이호들이 그릇을 들고 플레이어 앞을 오간다. 크림이 그릇에 닿는 박자에 맞춰 Joy-Con 을 휘저어(흔들어) 크림을 담는다.

- 음표 종류는 둘이다.
  - `S`: 한 번(크림 하나).
  - `Ln`: 8분음표 간격의 연속 n 번(n ≥ 2). 첫 음표만 JUST/FAST/SLOW 를 가리고, 나머지는 창 안에서 휘저으면 "맞음"이다.
- 그릇은 크기 S·M·L·X(레인 1~4칸)가 있고 헤이호가 1~4명 붙어 나른다. 그릇이 덮는 레인의 플레이어가 맞힌 음표만 그 그릇에 점수로 쌓인다.
- 그릇이 퇴장(`R`)할 때 쌓인 점수가 플레이어별로 팀 점수에 들어간다. 점수가 하나도 없으면 헤이호가 그냥 들고 나가고, 있으면 배경 케이크 쪽으로 던진다.
- 판정 텔롭(JUST/FAST/SLOW), JUST 소리(공용 아르페지오 사슬), 진동이 따른다.
- 결과: 공용 별 판정. 배경 케이크 크기(10단계)가 달성률을 따라간다.

### 3.4 줄 → 음표·그릇 [판독 `ObjectManImpl::Entry @0x71000044a0`]

열 의미: **1P~4P = 레인별 음표, OBJ1~4 = 그릇 명령**.

```ts
for (col = 0; col < 8; col++) {
  const s = data.cols[col]; if (!s || s[0] == ' ') continue;
  if (col < 4) {                                         // 음표
    const n = s[0] == 'S' ? 0 : max(parse('L%d'), …);    // L1·L2 → 2, L3 이상 그대로, S → 0
    timingJudgeMan.entry(data.row, n, col);              // n==0 이면 1개
  } else if (s[0] == 'R') {
    bowls[col - 4].leave();                              // **열 번호 = 그릇 번호**
  } else {
    for (size of ['_S','_M','_L','_X']) {                // size_char @0x7100048050
      if (s 에 size 가 들어 있고 sscanf(s, 'B%d' + size, &id) == 1) {
        const b = bowls[id - 1], slot = col - 4;
        if (b.active && !(b.state in {3,4,5})) b.move(slot);              // 이미 있으면 옮기기
        else { npcs = getUseNpcPtrs(sizeIndex + 1); b.entry(slot, sizeIndex, npcs, false); }   // 헤이호 sizeIndex+1 명
        break;
      }
    }
  }
}
```

- 디스어셈블리 `@0x71000047f4~0x710000485c` 로 "활성이면 Move, 아니면 Entry" 분기를 확인했다 [판독].
- `Bm_Z` 는 **그릇 m 을 OBJ 열 위치(슬롯)로** 보낸다. `R` 은 **그 열 번호의 그릇**을 퇴장시킨다. 실채보는 둘이 어긋나지 않게 짜여 있다(예: chart00 70줄 `B1_S`@OBJ2, 79줄 `R`@OBJ1 → 그릇 1 퇴장) [데이터].
- 그릇이 덮는 레인 = `[slot, slot + sizeIndex]`(S 1칸 … X 4칸) [판독 `JudgeInput`].

`PreEntry(Data)` @0x7100004924 (Entry 훅, 2줄 먼저): 레인마다 음표가 있으면 안내 NPC(`NotesMan+0x210+8·lane` = `NpcGuide`)에 `EntryDelayAction(GetBeatToSec(1,1) × (S ? 1 : max(n,2)+1))` — 연출 전용 [판독].

## 4. 구조체·필드·상수·열거형

### 4.1 판정 자료 [판독 `TimingJudgeMan::Entry @0x710000b310`, `JudgeSwing @0x710000da30`]

`TimingJudgeMan` = `vector<JUDGE_INFO>`(ObjectManImpl+0x88).

JUDGE_INFO (0x28 B):

| +off | 이름(웹 권장) | 값 |
|---|---|---|
| +0x00 | `row` | Lock 줄 |
| +0x04 | `lane` | 0..3 |
| +0x08 | (0) | |
| +0x10 | `vector<TIMING_INFO> notes` | n 개 |

TIMING_INFO (0x10 B):

| +off | 이름 | 값 | writer |
|---|---|---|---|
| +0x00 | `noteId` | `NotesMan::Entry` 가 돌려준 크림 음표 id | Entry |
| +0x04 | f32 `elapsed` | 0, 매 프레임 += dt | ObjectManImpl::Update |
| +0x08 | f32 `target` | `GetBeatToSec(1,8) + i·GetBeatToSec(1,1)` = 1마디 + i·8분 | Entry |
| +0x0C | u8 `done` | 0, 맞으면 1 | Entry, SendHitJudge |
| +0x0D | u8 `isFirst` | i == 0 | Entry |
| +0x0E | u8 `holdEnd` | 0 | Entry(이 밖에 쓰는 코드를 찾지 못함, 6.5) |

`JudgeData`(JudgeSwing 결과, 0x1C B):

| +off | 내용 |
|---|---|
| +0x00 | `type` SWING_TIMING: **1 JUST, 3 FAST(이름), 2 SLOW(늦음), 0 연속 음표 맞음, −1 없음** |
| +0x04 | `diff` = `(int)(target·60) − (int)(elapsed·60)` (+ = 일찍) |
| +0x08 | `noteId` |
| +0x0C | `isFirst` |
| +0x0D | `holdEnd`(TIMING_INFO+0x0E) |
| +0x10 | f32 `remain` = `target + GetBeatToSec(1,1) − elapsed` |
| +0x14 | `bowlId` (JudgeInput 이 채움, 없으면 −1) |
| +0x18 | `seq` = JUDGE_INFO.row + 음표 번호 (JUST 소리 묶음 키) |

## 5. 상태 전이와 전체 수명

### 5.1 시각 관계 [재구현 계산]

- BeforeOneBeat(1, 0) 이므로 mg1801 과 같다: **Entry 줄 r = B + (6+r) 8분, Lock 줄 r = B + (8+r) 8분**(B = 게임 BGM 시작 마디, 02_rhythm 7.3).
- 음표 i 의 목표 = Lock 줄 r 배분 + 8 + i 8분 = **B + (16 + r + i) 8분**. 예: chart00 0번 줄 `L4` → B+2 마디 1박부터 8분 4개.
- 판정 프레임(BPM 120, dt = f32(1/60) 누적, Lock 프레임에 elapsed = 0, 판정은 같은 프레임의 증가 뒤 — mg1801 6.3 과 같은 순서 [추정: 파이버 순서 mg1801 규칙]):

| 음표 | 목표 프레임 | 결과 (Lock 뒤 프레임) |
|---|---|---|
| 첫 음표 | 120 | FAST 106~115, **JUST 116~126**, SLOW 127~136 |
| 2번째 | 135 | 맞음(type 0) 121~151 |
| 3번째 | 150 | 맞음 136~166 |

  창 반폭 `(int)(GetBeatToSec(1,1)·60)` = 15, JUST `|diff| ≤ 5`(f32 누적 절삭 때문에 JUST 11프레임) [재구현 계산 `analysis/rcC_calc_bpm120.json`].
- 리듬 쿠킹 롱 후반(BPM 180): 목표 80프레임(1마디 = 1.333 s), 창 반폭 10, 첫 음표 FAST 71~75 / JUST 76~86 / SLOW 87~91, 연속 음표 간격 10프레임 [재구현 계산 `analysis/rcC_calc_bpm180.json`]. 휘젓기 모션 잠금은 `frame += 1.5·1.2` 로 9프레임이다.
- 연속 음표는 창(31프레임)이 서로 겹친다. JudgeSwing 은 앞에서부터 **아직 안 맞은 첫 음표 중 창 안의 것**을 고른다 → 휘저을 때마다 하나씩 앞 음표부터 소모된다 [판독].
- 지난 음표는 마지막 음표 목표보다 2개 8분 더 지나면 JUDGE_INFO 째로 지운다(`elapsed − target > GetBeatToSec(1,2)` 마지막 음표 기준) [판독 `ObjectManImpl::Update @0x71000054a0`].
- chart00(152줄): 마지막 음표 그룹 Lock 128 → 마지막 목표 = Lock 줄 142 해당 시각(B+18.75 마디). 마지막 그릇 퇴장 `R` = Lock 144(B+19 마디). 종료 BGM 요청 = Lock 148(B+19.5) → 종료 BGM·ChartEnd = **B+20 마디(40 s)** [재구현 계산].
- `SQ_BGM_MG1807_A` 트랙0 길이는 8064틱 = 21마디다. 종료 BGM 은 20마디째에 들어와 A 의 마지막 마디는 나가지 않는다(시퀀스의 ENDPLAY_CHECK 동작, 04_sound 5.3) [데이터][재구현 계산]. 감상용 녹음에서 종료 곡이 40.000 s 에 시작하는 것과 맞는다(7.3) [실행: 자체 렌더 vs 원본 녹음].

### 6.1 휘젓기 값 PadDriver::Update [판독 디스어셈블리 `@0x7100014a78`]


- **에지가 아니라 매 프레임 크기**로 값을 정한다. 휘젓기 한 번은 6.2 의 모션 잠금이 나눈다 [판독].

## 8. 다른 기능과의 상호작용

- **입력 창 vs 그릇**: 판정은 TimingJudgeMan(레인·시간)만 본다. 점수는 그릇이 그 레인을 덮을 때만 쌓인다. 그릇은 OBJ 열 명령으로 따로 움직인다(헤이호 이동 시간 = 8분 × 거리/4).
- **같은 프레임 순서**: ObjectMan(elapsed 증가·그릇·NPC) → PlayerMan(입력·판정) → 장면 흐름(Lock 훅 → Entry) [추정: mg1801 규칙]. 그래서 Lock 프레임에 들어간 음표는 그 프레임에 판정되지 않는다.
- **연속 음표 겹침**: 한 번 휘저으면 창 안 첫 미판정 음표 하나만 소모된다. 13프레임 모션 잠금 때문에 8분(15프레임)마다 한 번씩 휘저으면 모두 맞는다 [재구현 계산].
- **점수 이전 시점**: 그릇 퇴장(R) 때. 그 전에 게임이 끝나면 쌓인 점수는 들어오지 않는다(실채보는 마지막 R 이 ChartEnd 전) [판독][데이터].
- **난수**: mg1807 게임 코드는 난수를 쓰지 않는다(`mg1807_game_only.c` 에 `SyncRand`·`RandModule` 호출 0건) [판독].

## 9. 웹 포팅 구조와 구현 순서

mg1801 회색 박스(`web/script/games/mg1801/`)와 같은 Product 구조를 쓴다. 공용 박자·단계·줄 배분(`logic/rhythm.ts`)·채보(`chart.ts`)는 그대로 가져온다.

| 웹 파일 | 원본 | 책임 |
|---|---|---|
| `logic/scene.ts` | `mg1807::Scene` | 채보 선택, CalcTotalPoint(6.6), 훅 → 방송(3.3) |
| `logic/objectMan.ts` | `ObjectManImpl` | Entry/PreEntry(3.4), JudgeInput/SendHitJudge(6.3), Update(5.1·5.2), 시작 그릇 |
| `logic/timingJudge.ts` | `TimingJudgeMan` | JUDGE_INFO/TIMING_INFO(4.1), JudgeSwing |
| `logic/bowl.ts` | `NewBowlOne` | 4.2 상태, Entry/Move/Leave/OneShake(6.4) |
| `logic/npc.ts` | `NewNpc`, `NotesMan::NpcGuide` | 운반·안내 연출 상태(화면 값) |
| `logic/notes.ts` | `NotesMan`, `Notes` | 크림 음표 표시(목표 8개 8분 전 표시, DROP/MISS 사건) |
| `logic/player.ts` | `Player` + `PadDriver` | 6.1·6.2, 모션 잠금 |
| `logic/map.ts` | `MapImpl` | 카메라·케이크·결과 |
| `logic/data.ts` | static 표 | size_char, 위치 표, div_rate, 모델 이름, Params 기본값 |

한 step 순서: dt → Stage(MapImpl) → ObjectMan(시작 그릇 타이머 → TIMING_INFO.elapsed += dt·만료 삭제 → NotesMan → 그릇 4 → NPC 8 → JUST 소리 묶음 타이머) → PlayerMan(Player 0~3) → 장면 흐름(단계, 줄 배분: Entry 훅 → PreEntry, Lock 훅 → Entry).

| 원본 | 웹 | 동등성 |
|---|---|---|
| 가속도 크기 3단계(≤1.5 / <2.3 / ≥2.3, 창 밖 ≥4.0) | 키를 누르고 있는 동안 3.0 G(창 밖 휘젓기 키는 4.5 G) | 모션 잠금 13프레임이 휘젓기 간격을 정하므로 키 반복은 무시 |
| 시퀀서 G14 | 02_rhythm 11.3 | Lock 줄 r = B + (8+r)·15 프레임 |

구현 순서: (1) CalcTotalPoint → 272/232/64 (2) TimingJudgeMan → 5.1 판정 프레임 표 (3) 그릇 명령·덮임 → CPU 전원 272 (4) 화면.
