## 1. 기능 개요와 사용자에게 보이는 동작

4인 협력 리듬 미니게임이다. 플레이어 4명이 각자 화구 앞에서 프라이팬을 든다. Joy-Con 을 세로로 쥐고 휘둘러 팬케이크를 뒤집는다.

- 플레이어마다 뒤에 **서버 NPC(헤이호)**가 반죽을 들고 있다. 채보 줄보다 2박(8분 4개) 먼저 반죽을 받아 1박 뒤 프라이팬으로 던진다. 반죽은 정확히 채보 줄 시각에 팬에 떨어진다(5.4).
- 크기는 셋이다: **S(작음)·M(중간)·L(큼)**. 크기마다 굽는 시간이 다르다 — S 8, M 12, L 28 (8분음표 단위) [데이터]. 반쯤 구워졌을 때 1번째로 뒤집고, 다 구워졌을 때 2번째로 쳐서 손님 접시로 보낸다.
- 휘두르면 **언제든** 뒤집힌다. 판정은 목표 프레임과의 차이로 JUST(±5프레임)·FAST(이르게)·SLOW(늦게)다. 너무 오래 두면 탄다(NG, 연기와 함께 사라짐).
- L 팬케이크는 두 사람이 나눠 칠 수 있다(채보 `OBJn = "12"`): 1번째 면은 1번 플레이어, 뒤집으면 2번 플레이어 팬으로 넘어가 2번째 면을 그 사람이 친다.
- **손님 NPC(헤이호)**가 접시를 들고 들어오고(`B4`/`B2`) 나간다(`E`). 2번째로 친 팬케이크는 손님 접시로 날아가 쌓인다.
- 점수: 한 번 칠 때 JUST 2점, FAST·SLOW 1점, 탄 경우 0점. 팬케이크 1장 최대 4점.
- 결과 연출: 손님 접시에 쌓인 팬케이크 탑, 둘 다 JUST 면 장식 연기(`mg1808_smoke_s/m/l`), 결과 징글은 별 판정 공용 규칙(6.6).

## 3. 진입점과 전체 호출 흐름

### 3.1 클래스 구성 [판독]

```
mg1808::Scene : ca::rm::RmMgSceneBase      장면(+0x478 EffectMan, +0x480 StageMan, +0x488 ObjsMan, +0x490 NpcMan, +0x498 PlayerMan)
  EffectMan      이펙트 생성 도우미(파이버 없음)
  StageMan       무대·화구(CookingStove)·카메라·결과 무대(+Impl 파이버)
  ObjsMan        팬케이크 풀 48개(Pancake + BatterModel + AssistUi 2개)(+Impl 파이버)
  NpcMan         ServerNpc 4(반죽 배달) + ReceiverNpc 4(손님 접시)(+Impl 파이버)
  PlayerMan      Player 4(+FryingPan)(+Impl 파이버)
  Mg1808Model    모델·모션·노드·훅 래퍼(공용 유틸)
```

- 생성 순서: `Scene::RmSyncedSetupGame @0x7100021330`이 EffectMan → StageMan → ObjsMan → NpcMan → PlayerMan 순서로 만든다 [판독].
- 각 매니저 생성자가 `bex::Fiber::Fiber(…, 0, false)`로 Impl 파이버를 만든다(StageMan @0x7100022c7c, ObjsMan @0x7100015d8c, NpcMan @0x710000f46c, PlayerMan @0x710001c95c). 같은 우선순위 0, 생성 순서대로 등록된다 → **한 프레임 실행 순서 = StageMan → ObjsMan → NpcMan → PlayerMan → 장면 흐름** [판독: 생성 순서][추정: 등록 순서 = 실행 순서, mg1801 core 결론과 같은 규칙].
- 객체마다 **`std::function` 슬롯**이 있다(Pancake+0x10, Player+0x60, FryingPan+0x10, ServerNpc/ReceiverNpc+0x20). 매니저 Update 파이버가 매 프레임 이 슬롯을 부른다(`vtable+0x30` = operator()). 상태가 바뀌면 다른 람다를 넣는다(`FUN_71000042c8` = 대입). 예: `ThrowBatter`가 `on_throw` 람다를, `SetFryAction`이 `OnFry`/`OnPlateReturn` 람다를 넣는다 [판독].

### 3.4 한 프레임 안의 일 (단계 6 이후)

```
StageMan 파이버  : 무대 갱신
ObjsMan 파이버   : Pancake 48개 Update (슬롯 람다: on_throw / OnFry / OnPlateReturn, AssistUi, CountDown, CalcWhistle, NG 처리)
NpcMan 파이버    : ServerNpc 4 + ReceiverNpc 4 슬롯 람다 (OnDeliver / OnReceiveReady / OnFrameOut)
PlayerMan 파이버 : Player 4 슬롯(OnMove: 입력 → 판정 → 득점), FryingPan 슬롯(OnMove), 프라이팬 연기 타이머
장면 흐름        : OnGameMain 단계 처리 → 꼬리(Lock 줄 → EntryLock, Entry 줄 → Entry(빈) → NextEntry(줄+4))
```

- 판정(OnMove)은 같은 프레임 ObjsMan 이 늘린 `elapsed`를 읽는다 [판독: 실행 순서 3.1 기준].
- 배달·던짐·착지는 NpcMan/ObjsMan 슬롯 안의 시간 누적이다. 정확한 프레임 오프셋(±1~2프레임)은 11.2.

### 5.2 배달 → 던짐 → 착지 [판독 `NpcMan::Impl::EntryNext @0x7100010020`, `ServerNpc::SendMessageDeliver @0x7100013880`, `OnDeliver @0x7100013df0`, `Pancake::ThrowBatter @0x710001a87c`, `on_throw @0x710001aa28`]

1. **NextEntry(줄 R = 지금 줄 + 4)**: 열 1P~4P 각각(lane = 열 번호)
   - 코드가 비었거나 첫 글자가 `' '`면 건너뛴다. `L`/`M`/`S` 가 아니면(예 `BREAK`) 배달하지 않는다.
   - 인계 대상: `OBJ(lane+1)` 문자열. 비었거나 첫 글자가 `' '`·`'B'`·`'E'`(비트 마스크 `0x2400000001`)면 없음(−1). 아니면 길이 ≥ 2 일 때 `first = OBJ[0]−'1'`, `second = OBJ[1]−'1'`.
   - 서버 4명 중 하나라도 `busy == 0`이면 `ServerNpc[lane].SendMessageDeliver(lane, type, 1, first, second)`. 4명 모두 바쁘면 그 줄의 이 칸은 버린다 [판독, 원본 그대로].
   - `second ≥ 0`이면 `ServerNpc[second].served = 1`.
2. **SendMessageDeliver**: `ObjsMan::Entry(rotY=ServerNpc+0x18, type, lane, 쟁반 엔티티, …, first, second)` → `Pancake::Entry`
   - `targetPlayer = first ≠ −1 ? first : lane`, `handoffPlayer = second`, `state = 0`, 쟁반 훅 `tray`에 붙인다, 필드 초기화(4.4).
   - 서버 모션 0 → 1(`EnqueuePlay`), `busy = 1`, 슬롯 = `OnDeliver`.
   - `ServerNpc+0x18` 쟁반 위 회전 = 예약 표 맨 앞 크기를 보일 때 **비동기 `RandRangeF(0, 2π)`** [판독 `SetReserveThrowObj`·`OnDeliver` case 4]. 동기 난수는 쓰지 않는다.
3. **OnDeliver** (매 프레임, `t1 = GetBeatToSec(1,1)`):
   - 단계 0: 서버 모션 프레임 ≥ 1 이 될 때까지 기다린다 → 반죽을 손(`attach_R_hand`)에 붙인다, 타이머 = dt.
   - 단계 1: 타이머 += dt, **≥ 2·t1(8분 2개)**이면 이 서버의 id 목록 전부 `ObjsMan::ThrowBatter`, 서버 모션 4, 다음.
   - 단계 2: 타이머 ≥ t1 → 모션 3. 단계 3: 모션 프레임 ≥ 23 이면 쟁반 다시 보이기, `served=1`, `busy=0`. 단계 4: 2·t1 뒤 다음 쟁반 크기 표시.
4. **ThrowBatter**: `SQ_SE_MG1808_CAKE_THROW`(3D), 시작 = 현재 위치, 끝 = 대상 플레이어 프라이팬 노드 위치, 훅 해제, `state = 1`, 슬롯 = `on_throw`.
5. **on_throw** (`T = GetBeatToSec(1,2)` = 8분 2개):
   - `phaseTimer += dt`, `r = phaseTimer/T`, 위치 = lerp(시작, 끝, r) + y·`sin(r·π)·1.5`.
   - `r ≥ 0.5`이고 높이가 팬 높이 이하가 되면 프라이팬 훅 `fryingpan`에 붙이고 비행을 끝낸다(`phaseTimer = T`). 아니면 `phaseTimer ≥ T − 0.01`까지 반복.
   - 착지: 반죽 모션 3개 재생(속도 2.0, 크기 1 이상이면 1.0), L 이면 `SQ_SE_MG1808_BIG_CAKE_LAND` + `…_BIG_CAKE_BAKE`, 아니면 `SQ_SE_MG1808_CAKE_LAND`. `PlayerMan::SendMessageObjLanding(targetPlayer, id)` → Player+0x9C·FryingPan+0x58 = id. `onPan = 1`, `whistleOn = 1`, `counting = 1`, `state = 2`, 예고음 카운트다운(6.9).

### 5.3 손님 NPC와 BREAK [판독 `Scene::OnRmRecieveBeatEntryLock @0x71000222b0`, `NpcMan::Impl::EntryReceiverNpc @0x7100010418`]

EntryLock(줄 R, 단계 6 이상):
1. `OBJ4` 첫 글자:
   - `E`: 활성 손님 중 첫 번째에 `SetFrameOut`(퇴장, 서버 `served` 4개 0).

2. `1P` 코드가 정확히 `"BREAK"`(5글자)이면: `GetObjsActiveList`(state≠−1 && !burnt)의 **모두**가 `IsReturnedPlate`(state 7)이면 `RmMgSceneBase::SetGameEndForce()`. 목록이 비어 있어도 강제 종료다 [판독].
   - 강제 종료 플래그가 서면 단계 6 끝 조건이 참이 되어 종료 BGM 을 요청한다(공용 단계 6→7).

### 5.4 장면 단계와 시각 [판독 02_rhythm 7절 + 재구현 계산]

공용 단계 0~10 은 [mg1801.md 5.3](mg1801.md)과 같다. mg1808 고유 점:

- BeforeOneBeat 가 없으므로 **줄 r 의 Entry·Lock = B+1 마디 첫 박 + r × 8분**(B = 게임 BGM 시작 마디). BPM 120 에서 줄 r = BGM 시작 + 120 + 15r 프레임 [재구현 계산, 02_rhythm 7.3].
- NextEntry(줄 r+4)는 줄 r 시각에 온다. 그래서 줄 0~3 의 팬케이크는 배달될 수 없다. 실채보 첫 팬케이크는 줄 8(chart00/01)·줄 4(chart00s)라 문제가 없다 [데이터].

- 원본 특이점 1: **S·M 은 FAST·SLOW 에도 `PlayExcellentSe(-1,true)`**(JUST 아르페지오 사슬, [04_sound 6.5](../engine/04_sound.md))를 부른다. L 은 대신 `SQ_SE_RC_JUST`를 직접 내고 지역 변수 0 에 L 카운트(1~4)를 쓴다. `LSizeJustSeNum`은 `ObjsMan::Entry`마다 0 이 된다 [판독, 원본 그대로].
- 원본 특이점 2: `hitCount[lane]`은 그 플레이어 레인 기준이다. 인계 L 은 1타 1번 플레이어, 2타 2번 플레이어라 각자 1 이 되어 `hitCount == 2` 조건(결과 어긋남)은 인계 L 에서 성립하지 않는다 [판독 + 추론].
- OnFry(8분 2): `r = phaseTimer/T`, 위치 lerp + y·`sin(r·π)·(handoff ≥ 0 ? 2.3 : 2.0)`, 회전 `r·π`(x축) + rotY. r ≥ 0.5 이고 팬 높이 이하이면 착지: 인계면 `SendMessageObjLanding(target, −1)` 뒤 `target = handoff`, `SendMessageObjLanding(handoff, id)`; NG 아니면 착지 SE; 훅 `fryingpan`(y = height), 회전 π. 이어서 굽기 모션 속도 `105/((bake − elapsed)·60)`, 2면 안내, `counting = 1`, 예고음 카운트다운, `state = 5`.
- OnPlateReturn(8분 2): `GetRate(phaseTimer, 0, T, 0, 1)`로 r, 위치 lerp + y·`sin(r·π)·2.5`, 회전 `r·π + π`. r ≥ 1 이면 착지: NG 아니면 `SetResultV(stack.x, stack.z, rotY, plateId, type, justAt[], 굽기 모션 프레임 2개)`, `SQ_SE_MG1808_(BIG_)CAKE_LAND_COMP`, `SetReceiverNpcPlateObj`, 두 번 다 JUST 면 완성 이펙트(`smoke_s/m/l`)를 켜고 위치를 따라가게 한다, 훅 `wagon`(L 은 y+0.1), `done = 1`; `state = 7`, `SendMessageObjLanding(target, −1)`.

### 6.7 CPU [판독 OnMove·`SetComAttackTiming @0x710001ec5c` 디스어셈블리]

- COM 은 자기 레인 팬케이크의 `d ≥ comOffset` && `|d| ≤ 30` && `hitCount < 2` 인 **첫 프레임**에 휘두른다. 쿨다운·공중 잠금은 사람과 같다.
- `comOffset`(Player+0xA0)은 `SetComAttackTiming`이 `Player+0xA4 != 0`일 때만 바꾼다. **+0xA4 에 0 이 아닌 값을 쓰는 코드가 없다** → comOffset 은 항상 0, COM 은 항상 d = 0(f32 누적으로 d=1 일 수도)에서 쳐서 **항상 JUST** [판독].
  - 죽은 경로(참고): ComTiming 1 → `−RandRange(6,10)` = −6..−9(FAST), 2 → `+RandRange(6,10)`(SLOW), 3 → `RandRange(0,20)−10` = −10..9, 0 → 0. `RandRange(a,b)` = [a,b) [01_core].
- COM 진동(`VB_*`)은 내지 않는다(사람만) [판독].

## 8. 다른 기능과의 상호작용

- **박자 ↔ 시간 누적**: 줄 배분은 사운드 G14 가 바뀌는 프레임, 그 뒤 배달·비행·굽기는 dt 누적이다. 프레임 관측 지연은 공용 미확정([mg1801.md 11.2](mg1801.md)).
- **입력 차단**: 단계 2 전 입력 없음 → 단계 2~5 연습 람다(판정 없음) → 단계 5 OnMove → 단계 7 슬롯 비움. 단계 7 뒤에도 NextEntry 로 배달은 계속된다(Lock ≥ 줄수−4 이후 4줄). 실채보 마지막 4줄에는 팬케이크가 없다 [데이터].
- **강제 종료(BREAK)**: 5.3.
- **동기 난수**: mg1808 이 쓰는 동기 난수는 slip 경로(SyncRandRangeF ×2)뿐이고 그 경로는 +0x15C 에 달렸다. 그 밖(쟁반 회전, NPC 모션 프레임, 결과 어긋남, COM)은 비동기 난수다 [판독].
- **같은 프레임 순서**: Pancake Update(경과 증가) → Player OnMove(판정) → 장면 꼬리(배달). 같은 프레임에 착지와 휘두름이 겹치면 착지 프레임의 state 는 2 라서(굽는 중 아님) 판정되지 않는다 [판독: ObjInfo+0x32].
