## 1. 기능 개요와 사용자에게 보이는 동작

4인 협력 리듬 미니게임이다. 플레이어 4명이 테이블 앞에 한 줄로 서서 빵(번)을 잡고 있다. Joy-Con 을 세로로 쥐고 아래로 밀어 빵을 누른다.

- 재료 4종(토마토 계열 `T`, 고기 계열 `M`, 치즈 계열 `C`, 양상추 계열 `A` [추정: 모델 텍스처 이름 `obj_food00/01`, `obj_lettuce`])이 **왼쪽 또는 오른쪽에서 통통 튀며** 각 플레이어 앞으로 온다. 튀는 소리 `SQ_SE_MG1809_FOOD_BOUNCE_1~4`가 재료마다 다르다.
- 재료가 플레이어 앞에 도착하는 순간(JUST 시각)에 맞춰 밀면 재료가 빵 위에 쌓인다. 판정은 JUST·FAST·SLOW 셋이다(6.3).
- 위에서 빵(뚜껑)이 떨어지고(`P`) 4명의 재료를 모두 받은 뒤 다음 세트로 넘어간다. 세트가 끝날 때(`W`) 받지 못한 재료는 연기(`mg1809_vns_smoke00`)와 `SQ_SE_MG1809_FOOD_MISS`로 사라진다.
- 재료가 도착하기 전 **예고 멜로디**(`SQ_SE_MG1809_SIGN_MELODY_1~4`)가 반음씩 올라가며 타이밍을 알린다(6.6).
- 점수: 재료 1개에 JUST 2점, FAST·SLOW 1점, 놓침 0점.

## 3. 진입점과 전체 호출 흐름

### 3.1 클래스 구성 [판독]

mg1809 는 다른 리듬 게임과 구조가 다르다. **티켓(메시지) 교환 + 커맨드 시스템 + CSV 파라미터 관리자** 위에 게임 로직이 있다.

```
mg1809::Scene : RmMgSceneBase            +0x478 SceneLiaison(장면 → 시퀀스 요청)
  SceneLiaison                            RequestSequence(id) / IsRequested / IsCompleted — 장면 훅을 "시퀀스 번호"로 바꿈
  Sequence (+Impl : Fiber 0x10000, Transceiver)   채보·BGM 설정, CalcTotalPoint, 단계 티켓 중계, BeatCode 보관(슬롯 0/1)
    CommandAndControlSystem (Fiber 0x3f000)       Effect/Sound/Locate/Phase 커맨드(지연·기간 실행)
    Stage (+Impl : Fiber 0x20001, Transceiver)    재료 Parts 32개(종류 4 × 8), 빵 Pack 큐, 판정 Action, 결과
    PlayerManager (+Impl : Fiber 0x20000, Transceiver)  Player 4(MGActorPlayer), 입력, 예고 멜로디
  ParamManager                            mg1809_param.csv + 코드 기본값(4.3)
  TicketExchanger (Fiber 0x40000)         비즉시 티켓 큐를 프레임 끝에 배포
```

- 파이버는 **우선순위 오름차순 + 등록 순**으로 돈다([01_core](../engine/01_core.md)). 장면 흐름 파이버는 우선순위 0 이다([mg1801_core.md](../../../analysis/notes/mg1801_core.md)). 그래서 한 프레임 순서는 **장면 흐름(0) → Sequence(0x10000) → PlayerManager(0x20000) → Stage(0x20001) → 커맨드(0x30000·0x3f000) → TicketExchanger(0x40000)**이다 [판독: 생성자 인자 PlayerManager::Impl @0x710000dffc·Sequence::Impl @0x7100011d6c·Stage::Impl @0x7100014c0c·CommandAndControlSystem::Impl @0x71000038e0·TicketExchanger @0x710001f420][추정: 장면 흐름 우선순위 0 은 mg1801 결론 적용].
- `ParamManager::Impl::Impl @0x71000087d8`도 우선순위 0 파이버를 만든다. 하는 일은 판독하지 않았다(파라미터 편집·로그용 [추정]).
- 티켓: `Transceiver::DistributeTicket(kind, value, immediate)` → `TicketExchanger::SendTicket`. `immediate`면 **즉시** 모든 수신자의 `ReceiveTicket(kind, value)`를 부르고, 아니면 큐에 넣었다가 TicketExchanger 파이버(프레임 끝)가 배포한다 [판독 @0x710001f7f0].

| 티켓 kind | 보내는 곳 | 받는 곳·뜻 |
|---|---|---|
| 2 (value = 시퀀스 번호) | SceneLiaison | Sequence: 다음 시퀀스 예약 |
| 3 (value = 단계 번호) | Sequence | Stage·PlayerManager: 단계 전환(1 연습, 3 본편, 4 채보 끝, 7 결과, 8 캡처) |
| 4 | Sequence | Sequence: PhaseCommand 생성 → 단계 3 전파 |
| 5 (value = BeatCode 슬롯) | Scene::OnRmRecieveBeatEntry(**즉시**) | Stage(재료·빵·세트 끝), PlayerManager(예고 멜로디) |
| 9 | RmSyncedSetupGame(즉시) | Sequence: 초기화 시퀀스(Stage/PlayerManager Initialize) |

### 3.2 준비 단계

1. `Scene::Scene @0x7100010ec4`: `RmMgSceneBase` 생성자(공용), `SetMinigameScene(this)`, SceneLiaison 생성, `LoadSceneNonPlayerCharacter(0x2d)` = **KANIBO**(Number 36, `chara/npc036`), `(5)` = **HEYHO**(`chara/npc002`) [판독][데이터 `characterlist.json`]. 둘 다 배경 NPC(`hook_npc%02d_bg`)로 쓰인다 [판독: 문자열][추정: 역할].
2. `Sequence::Impl::Impl @0x7100011d6c`: **`ParamManager::Load("mg/mg1809/data/mg1809_param.csv")` 뒤 코드 기본값으로 AddItem**(4.3), CommandAndControlSystem·Stage·PlayerManager 생성.
3. `Scene::RmSyncedSetupGame @0x7100010fd0`:
   - `Sequence::Setup` → `Sequence::Impl::Setup @0x710001268c`:
     - `SetGameBgmName("SQ_BGM_MG1809_A")`, `SetGameBgmFinName`(`SQ_BGM_MG1809_A_MG_ENDING` [판독: 02_rhythm 10절]), `SetMainBeatType(1)`, `SetMainBgmName`.

     - `SetStatusType(2)`, `CalcTotalPoint()` → `SetStarTotalScore`(6.1), `CommandAndControlSystem::Setup`, `Stage::Setup`, `PlayerManager::Setup`(Player 4명, 연습 화살표 모델 `model/mg1809_arrow00`, PERFECT 텔롭 회전 −14°(0xC1600000)).

   - `DistributeTicket(2, 9, 1)` → 초기화 시퀀스.
   - BeforeOneBeat 호출 없음 → 줄 배분은 단계 6부터.

- `OnRmGameStartAfter`의 반환값을 기반 클래스가 어떻게 쓰는지(반환 거짓이면 다음 프레임 다시 부르는지)는 기반 판독 범위 밖이다 [미확정].

### 3.4 한 프레임 안의 일 (단계 6 이후)

```
장면 흐름(0)      : 단계 처리 → 꼬리: Lock(기반, 빈) → Entry(줄 r) → 티켓 5 즉시 → Stage.EntryParts/EntryPack/W, PlayerManager 예고 멜로디
Sequence(0x10000) : (Exec 빈 함수)
PlayerManager     : 타이머 −dt, [0,1,2,3] 을 SyncRandMod 로 섞은 순서로 Player::Exec(입력 → Stage::Action → Parts::Push 판정)
Stage(0x20001)    : (+0x449 켜짐) Parts 32개 Update(남은 시간 −dt, 이동·도착·버림), Pack 큐 Update
커맨드·티켓       : 이펙트·소리 커맨드 진행, 비즉시 티켓 배포
```

- **같은 프레임에 판정이 갱신보다 먼저**다. 재료가 생기는 프레임(줄 r)에 Player 가 보는 남은 시간은 아직 감소 전 값이다. 그래서 생성 프레임을 0 으로 두면 k 번째 프레임의 판정값 t = c·8분 − k·dt 이다 [판독: 순서][재구현 계산].

### 6.7 세트 끝 W / 빵 P [판독 `Stage::Impl::ReceiveTicket` kind 5]

- `OBJ1` 첫 글자 `P` → `EntryPack(3, 0)`(빵 풀에서 비어 있는 것 → 큐 뒤, `Pack::Entry`). 숫자 `4`는 읽지 않는다 [판독: 디컴파일 상수].
- `W` → 보이는 재료 중 state ∉ {3,4} 전부 state 4(`hopTimer = 4T`, 외곽선 숨김) → 다음 Stage 갱신에 연기·`FOOD_MISS` → 숨김. 큐 맨 앞 빵 `Pack::Discard @0x710001a150`: 그 빵이 상태 1·2(아무도 안 누름)일 때만 상태 5·타이머 4T → 연기 `smoke01` 뒤 Clear [판독].
- `Pack::Clear @0x710001a1f8`가 붙은 재료 4개를 떼고 state 0 으로 돌린다 → 종류별 8개 Parts 를 deque 로 돌려 쓴다(`EntryParts`는 맨 앞을 꺼내 Entry 하고 뒤에 다시 넣는다. 꺼낸 것이 state 0 이 아니면 Entry 가 아무것도 하지 않는다) [판독].
- 빵이 비면(Stage Exec) 그 빵의 (kind, 판정) 4칸을 ProductInfo 로 결과 목록에 넣는다. 4칸 모두 음수면 넣지 않는다 [판독].

### 6.8 결과 [판독 범위 축소]

- `Stage::Impl::Result @0x710001a2f0`(3556 B)이 ProductInfo 목록으로 결과 샌드위치를 만든다(`result_locator`, `result_bead00`, `RESULT_SCALE`). 배치식은 **[미확정: 판독 안 함]**.
- 별 판정·징글·PERFECT 는 공용([02_rhythm 8](../engine/02_rhythm.md)). PERFECT 기준 = 개인 횟수 × 2(chart00 22점).

## 8. 다른 기능과의 상호작용

- **동기 난수**: 플레이어 실행 순서 셔플이 `PlayerManager` 활성 동안 **매 프레임 3회** 소비한다. 다른 동기 난수 사용은 없다 [판독: 전수 검색]. 웹 골든은 같은 프레임 수만큼 소비해야 시드가 맞는다.
- **판정 ↔ 갱신 순서**: PlayerManager(0x20000)가 Stage(0x20001)보다 먼저라 판정은 이전 프레임까지 줄어든 `justLeft`를 본다(3.4).
- **티켓 지연**: 단계 전환은 비즉시 티켓이라 같은 프레임 끝에 반영된다. 줄 티켓 5 는 즉시라 그 프레임 Player 판정 전에 재료가 생긴다.
- **입력 차단**: 단계 1 전·단계 4 뒤 `enabled=0`. 단계 1~3(연습)은 판정 없이 PUSH 모션만.
- **모드**: 외곽선 안내(노멀·롱만 처음 16개), 채보, BGM(`_C`·`_B`·REMIX) 외에 로직 차이는 없다 [판독].
