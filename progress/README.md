# MPJ Progress Atlas

원본 함수·분석 문서·웹 코드의 대응과 확인 근거를 탐색하는 독립 로컬 대시보드입니다. **TypeScript + esbuild + Apache ECharts + Python 표준 라이브러리**로 만들었습니다. React와 Vite를 사용하지 않습니다.

## 데이터 소스

**기본은 `web/ghidra/db`를 직접 읽는다**(`scanner/ghidra_db.py`, 설정 `config/ghidra.json`). md 스캔 없이 서버가 db를 읽어 메모리에서 집계하고, db 파일이 바뀌면(MCP 서버 저장 → 자동 내보내기) 다시 읽는다.

| 항목 | 근거 |
|---|---|
| 분석 | `functions/*.tsv`의 `ST_ANALYZED`(완료)·`ST_PARTIAL`(부분)·`ST_RECHECK`(재확인) |
| 분모 | 전체 함수 − 외부 라이브러리(`EX_LIB`·라이브러리 네임스페이스) − `EX_DEBUG` − thunk − 작은 함수 |
| 영역 | main 엔진(`SYS_*`별) · 미니게임(모듈별) · 화면·모드 · 보드 |
| 웹 구현 | 코드의 `@orig <모듈>:<주소> full\|partial\|approx` |
| 문서 | plate 주석 첫 줄의 `md: <경로> §<절>` |

기존 md 스캔 결과로 보려면 `npm run dev -- --source md` (먼저 `npm run scan`). 규칙 전체는 `web/docs/ghidra_가이드.md` §8.

## 실행

PowerShell에서:

```powershell
cd C:\dev\mpj\web\progress
npm install --cache .cache/npm --no-audit --no-fund
npm run scan   # 최초 데이터 생성 또는 명시적 재스캔
npm run dev
```

기본 주소: <http://127.0.0.1:8765/>

**`npm run dev`는 스캔을 선행하지 않습니다.** 저장된 통계로 서버와 첫 트리맵을 먼저 열고, 큰 함수 목록은 뒤에서 읽습니다. 실행 중 원본 자료가 바뀌면 백그라운드에서 갱신하며, 완료 전까지 이전 스냅샷을 계속 볼 수 있습니다. 최초 데이터가 없으면 `npm run scan` 안내와 함께 종료합니다. 데이터 새로고침 버튼은 이미 생성된 서버 스냅샷을 다시 읽으며 스캔을 강제로 실행하지 않습니다.

```powershell
npm run view                          # 자동 감시 없이 저장된 스냅샷만 조회
npm run dev -- --port 8767             # 별도 포트
npm run build                         # TypeScript 검사 + esbuild 번들
npm run serve                         # Python 서버 + 자동 감시; 미리 build 필요
npm test                              # 대시보드 스캐너와 실제 수집 데이터 검증
```

스캐너 파일을 수정했다면 Python 서버를 재시작해야 합니다. 프론트엔드 소스는 esbuild가 다시 번들하며 브라우저를 새로고침하면 적용됩니다. `view` 모드에서 별도로 스캔한 결과를 읽으려면 서버를 다시 시작합니다. 포트가 사용 중이면 중복 서버를 시작하지 않습니다.

## 탐색

- 분석 / 웹 구현 / 검증 탭, 기능 카테고리 / 원본 모듈 보기를 제공합니다.
- 카테고리 → 하위 시스템 또는 확인된 미니게임 → 함수 순서로 탐색합니다. 큰 그룹에는 모듈과 64KiB 주소 범위 단계가 추가됩니다. 함수가 누락되거나 표본으로 대체되지 않습니다.
- **함수 단계에서는 함수 하나가 동일 면적의 셀 하나입니다.** 전체 화면에서는 그룹 집계를 표시하며 33만 개 셀을 동시에 그리지 않습니다.
- 함수명·주소 검색 결과를 클릭하면 해당 그룹과 상세 패널로 이동합니다. `/` 키로 검색창에 접근합니다.
- 상태, 미확정 항목, 카테고리, 보조 태그로 필터링합니다. 보조 태그 검색은 관련 함수를 찾는 용도이며 전체 집계에서는 대표 카테고리로 한 번만 셉니다.
- 상세 패널에서 디컴파일 위치, MD 제목·줄·인용, 분류 근거, 연결 신뢰도, 웹 코드, 테스트 import, 직접 `FUN_` 호출을 확인합니다.
- 경로를 클릭하면 읽기 전용 미리보기가 열립니다. 줄 번호를 강조하고 절대 파일 경로를 복사할 수 있습니다. 원본 편집 API는 없습니다.
- 미확정 / 웹 코드·기능 / 분석 문서 목록은 별도 검색과 페이지 이동을 지원합니다.

## 수량과 판정의 의미

**대응 미확인은 미구현 확정이 아닙니다. 완료 0개도 실제 구현이 없다는 뜻이 아닙니다.** 자동 수집된 증거로 완료를 입증하지 못했다는 뜻입니다.

| 항목 | 분모 | 완료 기준 |
|---|---|---|
| 분석 | 함수 TSV를 `모듈 + 정규화 주소`로 중복 제거한 원본 함수 전체 | 해당 함수를 명시한 완료 문장 또는 근거 파일이 있는 수동 확인 |
| 웹 구현 근거 | 자동 발견한 export 코드 단위 + 수동 등록한 기능 | 근거를 갖춘 수동 완료 확인; 파일 존재로 자동 완료 처리하지 않음 |
| 검증 | 동일한 식별 웹 항목 전체 | 해당 기능 ID·소스 해시·통과 결과를 담은 검증 보고서 |

웹 코드 단위는 구현 대상 게임 기능과 1:1이 아닙니다. **전체 포팅 요구 기능 목록이 확정되지 않았으므로 현재 웹 완료 확인율을 게임 전체 구현률로 해석할 수 없습니다.** 함수 트리맵의 웹 색상은 원본 함수에 연결된 웹 항목의 상태이며, 통계의 웹 분모는 함수 수가 아닙니다.

자동 웹 상태:

| 상태 | 확인된 내용 | 확인하지 않은 내용 |
|---|---|---|
| 대응 미확인 | 원본 함수와 웹 코드의 명시적 대응 없음 | 기능이 실제로 없는지 여부 |
| 관련 코드 후보 | export 코드 단위 발견, 문서의 코드 경로 연결 등 | 원본 기능의 구현 범위 |
| 부분 구현 근거 | 원본 함수 명시적 참조 + AST에서 실행 본문 확인 + 명시적 스텁 표시 없음 | 원본의 모든 분기·상태·수식에 대한 동등성 |
| 완료 근거 확인 | 근거가 있는 수동 보정 | 자동으로 원본 실행 동등성을 보장하지 않음 |

TypeScript 컴파일러 API로 export 함수와 클래스 메서드의 본문, 빈 본문, throw 전용 본문, 상수 반환을 수집합니다. 상수 반환은 정상 동작일 수도 있으므로 그것만으로 스텁이라고 단정하지 않습니다. AST는 구조 분석이며 동작의 의미를 증명하는 도구가 아닙니다. 상세 패널과 웹 목록에 이 근거와 추가 확인 항목을 표시합니다.

분석 MD의 일반적인 “완료” 상태를 모든 참조 함수에 전파하지 않습니다. 정확한 모듈·주소 또는 고유 심볼을 우선합니다. 섹션에 판독 설명이 있으면 부분 판독 근거로 기록합니다. 모듈이 불명이고 여러 함수가 같은 주소를 사용하는 경우 연결하지 않습니다. 미확정/추정 인용은 자동 추출 후보이며, 문맥 해석과 동일 이슈 중복 정리는 수동 확인이 필요합니다. 명시적인 해소 문장과 제목 자체는 미확정 목록에서 제외합니다.

테스트 파일 import는 **테스트 연결**입니다. **통과 증거가 아닙니다.** 기존 웹 프로젝트 테스트를 임의 실행하지 않았습니다. 그 테스트가 원본 프로젝트 밖에 결과를 쓰거나 기존 산출물을 바꿀 수 있기 때문입니다. 대시보드 자체의 테스트 결과와 게임 기능 검증을 분리합니다.

## 분류와 수동 보정

`config/categories.json`에서 카테고리, 심볼 패턴, 하위 시스템, 감시 간격을 바꿀 수 있습니다. 미니게임 이름은 기존 `analysis/minigame_catalog.tsv`의 이름을 사용합니다. 모듈 이름만으로 모든 함수를 미니게임에 넣지 않으며 해당 게임 네임스페이스가 확인된 함수를 분류합니다. 일반 라이브러리 심볼과 이름 없는 함수는 별도로 남깁니다. 패턴 점수는 경험적인 분류 신뢰도이며 정확도를 검증한 확률이 아닙니다.

`config/overrides.json`만 편집해 함수 대표 분류·태그·분석 상태, N:M 웹 기능 연결, 검증 보고서, 모듈 불명 C 파일의 모듈을 보정합니다. 원본 MD/소스에는 주석을 추가하지 않습니다.

```json
{
  "functions": {
    "main.nso:0x710013aa70": {
      "category": "logic",
      "analysis": "partial",
      "note": "해당 절의 원본 초기화식 확인",
      "evidence": [{"path": "web/docs/engine/01_core.md", "line": 1, "reason": "난수 판독 설명"}]
    }
  },
  "features": [
    {
      "id": "custom:rng-initialization",
      "name": "난수 시드 초기화",
      "path": "web/script/game/core/rng.ts",
      "category": "logic",
      "functions": ["main.nso:0x710013aa70"],
      "implementation": "partial",
      "evidence": [{"path": "web/script/game/core/rng.ts", "line": 25, "reason": "초기화 본문과 원본 식의 대응"}]
    }
  ],
  "verification": [],
  "source_modules": {}
}
```

위 예시는 설명이며 실제 설정에 완료 판정을 추가하지 않았습니다. 수동 기능을 추가하면 자동 코드 단위와 같은 동작이 겹칠 수 있으므로 분모도 함께 검토해야 합니다. `implementation: complete` 또는 `analysis: complete`에 유효한 근거가 없으면 판정 대기로 낮춥니다.

검증 등록은 다음 형식의 JSON 보고서를 `web/progress/reports/`에 저장한 뒤 `verification`에 연결합니다. 보고서는 실제로 실행한 테스트/비교 결과를 기록해야 하며 이 예시를 성공 증거로 사용하면 안 됩니다.

```json
{
  "format": "mpj-progress-verification-v1",
  "features": ["web/script/game/core/rng.ts"],
  "source_hash": "data/features.json의 해당 source_hash",
  "kind": "automated_test",
  "result": "passed",
  "command": "실제 실행한 검사",
  "recorded_at": "실제 실행 시각"
}
```

`verified` 상태에는 `kind: original_execution_comparison`이 필요합니다. 보고서의 기능 ID, 소스 해시, 통과 결과, 검사 종류가 맞아야 집계됩니다. 소스 해시는 Python 텍스트 읽기의 개행 정규화를 거친 SHA-256이며 `data/features.json`에서 확인합니다. 수동 항목에는 `source_hash`를 명시해 해당 구현 버전에 고정할 수 있습니다.

## 수집·캐시·격리

`scanner/scan_functions.py`, `scan_markdown.py`, `scan_web.py`, `classify.py`를 `build_progress.py`가 묶어 실행합니다. `watch.py`는 HTTP API와 변경 감시를 제공합니다. TSV, `analysis/decomp/INDEX.tsv`, 디컴파일 헤더, `ghidra_work` C 출력, 프로젝트 분석 MD, 기존 웹 소스를 읽습니다. 제3자 매뉴얼, 의존성, 라이브러리, 임시/빌드 산출물과 대시보드 자체는 제외합니다.

- SQLite 파일별 파싱 캐시와 AST 구조 캐시: `.cache/`
- 함수·문서·웹 항목·카테고리·진행률·미확정 데이터: `data/*.json`
- 수량 대조 및 최초/최근 스캔 보고: `reports/scan.json`
- 함수 분모는 TSV 인덱스입니다. 모듈 불명 또는 인덱스에 없는 C 헤더는 `audit.unmapped_sources`에 기록하며 완료/분모에 몰래 추가하지 않습니다.
- 변경되지 않은 파일은 다시 파싱하지 않습니다. 전체 연결 관계와 집계 재구성은 현재 전체 함수를 순회하므로 캐시를 사용해도 즉시 끝나지는 않습니다.
- 감시는 mtime/크기를 사용합니다. 같은 mtime/크기를 보존한 외부 수정은 감지하지 못할 수 있습니다.
- 동시 스캔은 커널 파일 잠금으로 하나만 실행합니다. 원본 자료의 변경을 스캐너가 완료하기 전에 추가로 감지하면 다음 주기에 다시 반영합니다.
- 앱은 `127.0.0.1`에만 바인딩합니다. 정적 파일은 `index.html`과 `dist/`만 제공하며, 미리보기는 스캔에서 확인된 문서/소스 경로만 허용합니다.
- 패키지·lockfile·npm 캐시·Python 캐시·번들·로그·테스트 산출물은 모두 `web/progress/` 안에 있습니다. 원본 프로젝트 설정과 소스를 수정하지 않습니다.

성능·브라우저 확인 결과와 실제 수량은 `reports/VALIDATION.md`를 참고하세요.
